**Where:** internal/daemon/pidfile.go:85-128, internal/daemon/pidfile.go:130-142, cmd/sync.go:206-238, cmd/sync.go:343-351
**Confidence:** med

`WritePID` stores `pid starttime`, and the doc says the timestamp is "compared against the process's actual start time". In practice `FindProcess` only calls `isReusedPID`, which checks whether `ps -o comm=` contains "watchtower". Watchtower spawns many short-lived `watchtower` processes: `watchtower mcp`, `ai query`, the ~50 Desktop CLI call sites. After a daemon crash or SIGKILL leaves a stale `daemon.pid`, a reused PID held by one of them is reported as the running daemon. Consequences:
- `sync --daemon --detach` refuses to start ("daemon already running").
- `sync --now` signals an unrelated process with SIGUSR1, whose default action terminates it.
- `sync stop --force` can SIGTERM/SIGKILL it.

Separately, `runSyncStop` calls `RemovePID` without checking the file still names the PID it stopped. A daemon respawned quickly by the Desktop can lose its fresh pid file, and the tray then shows it as not running. Fix: compare the process start time (`ps -o lstart=`/sysctl) with the stored timestamp, or test the `sync.lock` flock. Remove the pid file only if its content still matches.

**Resolution (round 1, superseded — kept for history):** an initial fix compared the stored start time against `ps -o lstart=` textually. Review caught that `lstart` is locale-formatted (fails to parse under ru_RU/en_GB/etc.), that a parse failure fell back to "assume ours" with the old comm check removed entirely — silently disabling identity verification for signalling on any non-C locale — and that several pid-file-removal branches in `cmd/sync.go` still bypassed the identity re-check. See round 2 below for the actual shipped fix.

**Resolution (round 2, shipped):** identity verification now reads the process's start time locale-independently instead of parsing a formatted string: on darwin (the only OS watchtower ships a daemon for) `internal/daemon/procident_darwin.go` reads it via the `kern.proc.pid` sysctl (`golang.org/x/sys/unix.SysctlKinfoProc` — a single syscall returning an epoch-relative `timeval` plus the kernel's own recorded command name, no subprocess, no locale, no local-wall-clock DST ambiguity); `procident_other.go` is a portable ps-based fallback (forcing `LC_ALL=C`) that exists only so non-darwin builds (this repo's own Linux CI) compile and test, never a path any real daemon runs. `WritePID` now records the daemon's *own* OS-recorded start time (read back via the same reader), not the wall-clock moment it's called, so the later comparison needs only a 5-second tolerance instead of betting on an unbounded startup duration. Identity is a two-factor check (`identifyProcess`): start time within tolerance AND (when available) the command name contains "watchtower" — restoring the pre-fix comm check as a second factor rather than removing it. A third state, `processUnknown` (the identity read itself failed/was unavailable — distinct from a positive "gone" or "reused" verdict), is never guessed at: `FindProcess` (lenient, for read-only callers: status, kb, the "already running" check) still resolves it, but the new `FindConfirmedProcess` — used by every callsite that's about to SIGNAL the daemon (`runSyncStop`, `verifyDaemonAlive`/`forceStopSync`, `runSyncNow`) — returns `ErrIdentityUnconfirmed` and refuses, with a clear message naming the pid, rather than falling open. `readProcessIdentity` is a stubbable package var, so `internal/daemon/pidfile_test.go` pins every state (`TestIdentifyProcess_*`, `TestFindProcess_*`, `TestFindConfirmedProcess_*`, including the unparseable/unavailable-read case) deterministically, independent of locale or of what the test binary itself is named — confirmed to pass under `LC_ALL=C`/`ru_RU.UTF-8`/`en_GB.UTF-8` alike.

Every pid-file-removal branch in `cmd/sync.go` (both in `runSyncStop`'s plain path and all four signal-completion branches in `forceStopSync`, including the ESRCH ones) now goes through a single `reapPIDFile` helper that calls `daemon.FindProcess` directly (not the stubbable `verifyDaemonAlive` seam, so a test stubbing that seam to control a signalling decision can never also silently disable cleanup) — so a pid file is only ever removed when `FindProcess` itself, re-reading the CURRENT file content, confirms the process it now names is gone or reused; a fresh daemon that claimed the same path in a race window is never clobbered. A property guard (`TestSyncGo_NoDirectRemovePIDCalls`) asserts `cmd/sync.go` contains zero direct `daemon.RemovePID(` calls, so a regression to the old shape fails immediately. Pinned end-to-end by `cmd/sync_stop_test.go`'s `TestRunSyncStop_PlainStopRemovesPIDFileOnCleanExit` (regression) and `TestRunSyncStop_PlainStopSparesFreshDaemonThatWonTheRace` (a second live helper process that takes over the pid file mid-wait is never touched, positively confirmed via a "signalled" marker the helper prints on SIGTERM receipt — not inferred from liveness alone, which can't distinguish "never signalled" from "signalled, still in its exit delay").

Tests (round 2): `go test ./internal/daemon/...` and `go test ./cmd/... -run 'TestRunSyncStop|TestForceStopSync|TestSyncStop|TestSyncGo_NoDirectRemovePIDCalls'`, both under `LC_ALL=C`, `LC_ALL=ru_RU.UTF-8`, and `LC_ALL=en_GB.UTF-8` — all exit 0. `make lint-diff` — 0 issues.

**Resolution (round 3, shipped — fixes round 2's own regression):** round 2's `identifyProcess` compared a stored start time against the live kernel start time with a *symmetric* 5s tolerance, unconditionally. That broke upgrades: a pid file written by any build before round 2 (or main, right now) stores a wall-clock timestamp taken partway through `Daemon.Run` — after `db.Open`, migrations, syncer wiring, Jira `/myself` calls — which can legitimately trail the real fork by well more than 5s on a slow/boot-time/network-constrained startup. A symmetric check judged such a live, legitimate old-build daemon "reused" and deleted its pid file: `sync stop`/`--now`/even read-only `status`/`kb` would silently drop it, `sync --daemon --detach` would then start a SECOND daemon that immediately dies on the `sync.lock` flock, and the original daemon — running the pre-update binary — would keep running invisibly forever (never reachable by the tray, Quit, or any CLI command) until a reboot or manual kill.

Fixed by tagging the format instead of guessing: `WritePID` now writes a third field, `pidFileFormatTag` ("kstart", exported as `daemon.PidFileFormatTag` for tests), ONLY when its own identity read at write time succeeded — meaning field 2 is known to be the kernel's own accurate start time, safe for the tight symmetric check. An untagged two-field file — every build before this tag existed (including the just-shipped round 2), and `WritePID`'s own rare identity-read-failure fallback — gets a looser, ONE-SIDED check instead: the same process's kernel start can only be AT OR BEFORE the stored wall-clock value (plus `legacyStartTolerance`, 2s, for the value's own second-level flooring), since that value was read sometime AFTER the real fork; a kernel start meaningfully AFTER the stored value can only belong to a later, unrelated process that reused the pid. The comm ("watchtower") factor applies identically to both paths. `readPIDWithStart` now returns the tag alongside pid/startTime; `identifyProcess` takes an explicit `tagged bool`.

Also fixed per the same review round: (N2) `readProcessIdentity` is unexported, so `cmd`'s tests couldn't previously exercise `FindConfirmedProcess`'s refusal through the real production wiring (`runSyncStop`, `forceStopSync`, `runSyncNow`) — only via the cmd-local `verifyDaemonAlive` stub, which bypasses the actual identity machinery. Added `daemon.SetIdentityReaderForTest` (exported, test-only, swaps the same seam via an exported `ProcessIdentity` shape) plus four new `cmd` tests: refusal in `runSyncStop`, `runSyncNow`, and `forceStopSync` (this last one lets the initial resolve succeed via a stateful stub, then fails only on forceStopSync's own re-check — proven via the established call-counting technique that escalation stops there, never reaching a third read before SIGKILL), and one confirming the tagged/new-format path's happy path end-to-end. (N3) `resolveProcess`'s `processUnknown` branch now re-checks `kill(pid, 0)` before settling: if the process exited in the narrow window between the first liveness check and the identity read, that's "gone" (remove the file), not "unknown" (refuse and leave it) — pinned by a real subprocess the identity stub itself kills mid-read. (N4) the `//nolint:nilerr` comments now name EPERM (a live process now owned by another user — i.e. a reused pid) alongside ESRCH, not just "no such process".

Tests (round 3): `internal/daemon/pidfile_test.go` adds `TestIdentifyProcess_Legacy_*` (slow-startup-confirmed, reused-after-write, comm-mismatch), `TestIdentifyProcess_Tagged_*` (within/beyond tolerance, both directions), `TestResolveProcess_LegacyUntaggedSlowStartupIsConfirmed`, `TestResolveProcess_ReaderErrorButProcessGoneOnRecheckIsGone`, `TestReadPIDWithStart_Tagged`/`_UnknownThirdFieldIsNotTagged`, `TestWritePID_TagsAccurateStartTime` (via `TestWritePID_AtomicWrite`'s updated assertion). `cmd/sync_stop_identity_test.go` (new file) adds the four tests above.
