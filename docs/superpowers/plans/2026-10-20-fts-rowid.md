# Search Indexes Keyed by Row Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `messages_fts` and `transcripts_fts` are addressed by their source row's rowid, so every index write is an O(log n) lookup instead of a scan of the whole index; the one-time messages fill runs in the launch step before the compaction, with a daemon fallback.

**Architecture:** Migration 00146 renames the old messages index to `messages_fts_legacy`, creates the new one with the same columns and rowid-keyed triggers, and marks `fts_rebuild_pending` in `db_maintenance`; transcripts are re-keyed and backfilled inside the migration. `internal/db` owns the resumable chunked fill (`RebuildMessagesSearch`) and its due/disk rule; `db compact --if-due` runs fill → VACUUM in one child and prints a phase line per phase; the Desktop splash shows "Updating search index — m:ss" then the existing compaction line; `phaseMessagesSearchRebuild` finishes a pending fill in the daemon with a per-cycle budget.

**Tech Stack:** Go 1.26, SQLite FTS5 via `modernc.org/sqlite` (dbstat compiled in), goose SQL migrations, SwiftUI/WatchtowerCore (XCTest).

**Spec:** `docs/superpowers/specs/2026-10-20-fts-rowid-design.md` (binding), `docs/superpowers/specs/2026-10-20-fts-rowid-business.md` (owner-approved). Background: `docs/features/db-compact.md`.

## Global Constraints

- Scope: `messages_fts` and `transcripts_fts` only. `memory_fts` and `internal/db/memory.go` are not touched (G4, ask #364).
- Search results unchanged: same columns (`text`; `channel_id`, `ts`, `user_id` UNINDEXED; transcripts `text`; `transcript_id`, `title` UNINDEXED), `tokenize='porter unicode61'`, contentful (no `content=`). Readers (`internal/db/search.go`, `SearchQueries.swift`) are NOT rewritten (D5: neither path).
- Migration: `internal/db/migrations/00146_fts_rowid.sql`, SQL only, fast (no fill of messages inside it; the Desktop kills `db migrate` at 30 s). Not added to `compactAfterMigrations`.
- `db_maintenance` keys: `fts_rebuild_pending` (`"1"`), `fts_rebuild_cursor_messages` (integer as text, last `messages.rowid` covered). Absent = not pending / cursor 0.
- Fill: chunks of 5,000 `messages` rows by ascending rowid, one short write transaction each (cursor written in the same tx), `NOT EXISTS` skip of rows a trigger already indexed, interruptible between chunks, resumes from the cursor. Completion = one tx: `DROP TABLE messages_fts_legacy`, delete both keys.
- Fill disk rule: free ≥ `ftsRebuildNeedsDiskBytes(legacy) = legacy * 3 / 2`, legacy = summed page size of the `messages_fts_legacy_*` shadow tables (dbstat). Independent of the compaction's 2× rule and of its 3-failure cap (`gave_up`).
- Wire (`db compact --json`), additive only; exits 0–5 and every existing key unchanged:
  - `--check` gains `fts_rebuild_pending` (bool, always present). When pending: `due: true`, `reason: "fts_rebuild"`, `needs_disk_bytes` = the fill's need, `disk_ok` against it.
  - Run result gains `fts_rebuilt` (bool, omitempty).
  - Phase lines, `--json` only, on stdout before the result line: `{"phase":"fts_rebuild"}` and `{"phase":"compact"}`. The result stays the last stdout line.
- Splash copy (exact): `Updating search index — <m:ss>`; subtitle unchanged (`This happens rarely, usually after an update.`). Disk notice when the check's reason is `fts_rebuild`: `Watchtower could not update its search index: it needs <N> free, <M> available.`
- Daemon fallback budget: `searchRebuildBudget = 30 * time.Second` per cycle; no `pipeline_runs` row.
- Public repo: no live-install numbers, ids or local paths in code, tests, docs or commits. Repo text in English.
- Inner loop only per task (`go test ./internal/<pkg>`, `make test-swift FILTER=…`, `make lint-diff`); the full gate runs once by the controller.

## Review Focus

1. **`INSERT OR REPLACE INTO messages`** gives the row a new rowid and, with `recursive_triggers` off, never fires `messages_ad` — the old index row would stay as a duplicate hit. Expect: production code never REPLACEs a messages row (all upserts are `ON CONFLICT … DO UPDATE`, which keeps the rowid). Pinned by `TestSearchIdx01_NoReplaceIntoMessages` (Task 6); `TestMessagesFTS_UpsertKeepsRowid` (Task 1) pins the upsert path.
2. **A write landing between two fill chunks** (sync insert, edit, tombstone, delete of a row below or above the cursor). Expect: exactly one index row per indexable message after the fill, none for deleted/empty rows. Pinned by `TestRebuildMessagesSearch_ConcurrentWritesBetweenChunks` (Task 2).
3. **Fresh install vs upgrade with only non-indexable rows** (all empty text or tombstoned). Expect: no legacy table and no pending key after `Open`, golden schema without `*_legacy`. Pinned by `TestMigration146_FreshInstallHasNoLegacy` and `TestMigration146_OnlyNonIndexableRowsDropsLegacy` (Task 1).
4. **`--check` cost on a large legacy index** (dbstat walks the shadow tables' pages) against the Desktop's 30 s check timeout. Expect: the size read touches only the legacy b-trees, read-only. Pinned by `TestCheckMessagesSearchRebuild_ReadsOnlyLegacyPages` (Task 2, asserts the query names only `messages_fts_legacy_%` objects and writes nothing).
5. **Phase line after the child exited / split across pipe chunks.** Expect: the splash never flips back to a running phase after `.finished`, and a line split across two reads is still recognised. Pinned by `testPhaseLineAfterExitIsIgnored` and `testPhaseScannerJoinsSplitLines` (Task 5).

**Migration content (decided):**
- Up, messages: drop `messages_ai`, `messages_au`, `messages_ad` **before** the rename (SQLite's RENAME rewrites trigger bodies; dropping first avoids triggers pointing at the legacy table) → `ALTER TABLE messages_fts RENAME TO messages_fts_legacy` → recreate `messages_fts` exactly as schema.sql declares it today → new triggers:
  ```sql
  -- messages_ai: AFTER INSERT ON messages WHEN NEW.text != '' AND NEW.is_deleted = 0
  DELETE FROM messages_fts WHERE rowid = NEW.rowid;
  INSERT INTO messages_fts(rowid, text, channel_id, ts, user_id) VALUES (NEW.rowid, NEW.text, NEW.channel_id, NEW.ts, NEW.user_id);
  -- messages_ad: AFTER DELETE ON messages
  DELETE FROM messages_fts WHERE rowid = OLD.rowid;
  -- messages_au: AFTER UPDATE OF text, is_deleted ON messages WHEN OLD.text != NEW.text OR OLD.is_deleted != NEW.is_deleted
  DELETE FROM messages_fts WHERE rowid = OLD.rowid;
  INSERT INTO messages_fts(rowid, text, channel_id, ts, user_id)
  SELECT NEW.rowid, NEW.text, NEW.channel_id, NEW.ts, NEW.user_id WHERE NEW.text != '' AND NEW.is_deleted = 0;
  ```
  → `INSERT OR REPLACE INTO db_maintenance(key, value) VALUES ('fts_rebuild_pending', '1')` (unconditional; SQL cannot drop a table conditionally — see the cleanup below).
- Up, transcripts: drop the three `meeting_transcripts_*` triggers, `DROP TABLE transcripts_fts`, recreate it with today's columns, triggers keyed by `rowid = NEW.id` / `OLD.id` (same WHEN clauses as 00052, delete-first in the insert trigger), backfill `INSERT INTO transcripts_fts(rowid, text, transcript_id, title) SELECT id, transcript_text, id, title FROM meeting_transcripts WHERE transcript_text != ''`.
- Down: drop the new triggers and tables (`messages_fts`, `messages_fts_legacy` IF EXISTS, `transcripts_fts`), recreate the 00001/00052 shapes and triggers verbatim (column-keyed), repopulate both from their source tables (`WHERE text != '' AND is_deleted = 0` / `transcript_text != ''`), `DELETE FROM db_maintenance WHERE key IN ('fts_rebuild_pending', 'fts_rebuild_cursor_messages')`.
- Post-goose cleanup (Go, in `migrate()` after `goose.Up` returns nil; runs only in an `Open` that migrated, under the migrate flock): if `messages_fts_legacy` exists and no `messages` row has `text != '' AND is_deleted = 0`, one tx drops the legacy table and deletes both keys. Ruling: this replaces the spec's conditional in-migration drop, which goose SQL cannot express, without adding a Go migration (CLAUDE.md keeps those for repairs).

- `CompactCheck` gains `FTSRebuildPending bool \`json:"fts_rebuild_pending"\``; `CompactResult` gains `FTSRebuilt bool \`json:"fts_rebuilt,omitempty"\``.
- `CheckCompaction` order becomes: no file → `schema_pending` → **fts pending (due, reason `fts_rebuild`, `NeedsDiskBytes`/`DiskOK` from `MessagesSearchCheck`)** → `gave_up` → `migration:<v>` → `freelist`. `FTSRebuildPending` is filled whenever the schema is current, so a `gave_up` install still reports it.

**Decisions:**
- Chunk algorithm: `hi = MAX(rowid)` over the next `ChunkRows` messages rows with `rowid > cursor` (indexable or not); `hi` NULL → completion tx. Otherwise, one tx: the spec's `INSERT … SELECT m.rowid, … WHERE m.rowid > :cursor AND m.rowid <= :hi AND m.text != '' AND m.is_deleted = 0 AND NOT EXISTS (SELECT 1 FROM messages_fts f WHERE f.rowid = m.rowid)`, then write `cursor = hi`. Bounding by `hi` (not `LIMIT` on indexable rows) makes the cursor advance past non-indexable stretches.
- Not pending (key absent) → `Done: true`, no writes. Pending but no legacy table (should not happen) → completion tx still clears the keys.
- ctx cancelled mid-chunk → that chunk rolls back, return `ctx.Err()` wrapped; between chunks → same error, nothing lost.
- Legacy size: `SELECT COALESCE(SUM(pgsize), 0) FROM dbstat('main', 1) WHERE name LIKE 'messages_fts_legacy%'` (aggregate mode; read-only). Free space: the database file's directory from `PRAGMA database_list` through `freeDiskBytes`; an in-memory DB reads `DiskOK: true`.
- Completion does not touch `last_compacted_version`; a compaction is never recorded while pending (the CLI runs the fill first, Task 3).

  package struct CompactionPhaseScanner { package mutating func feed(_ chunk: Data) -> [CompactionRunPhase] }

  // CompactionCheck gains ftsRebuildPending: Bool ("fts_rebuild_pending", absent → false)

**Decisions:**
- `ProcessCompactionChild` drains stdout with `ProcessPipes.drain(_:onChunk:)` through a `CompactionPhaseScanner`; the full stdout is still returned for `decodeLastJSONLine` (the result is the last line).
- Initial running phase: `.updatingSearchIndex(dbBytes:)` when `check.ftsRebuildPending`, else `.compacting(dbBytes:)`. A `.compact` phase line moves `.updatingSearchIndex` → `.compacting` and sets `phaseStartedAt = elapsedSeconds`; a `.ftsRebuild` line is a no-op (already there). Phase callbacks hop to the MainActor and are ignored unless the step is in `.updatingSearchIndex` (so nothing changes after `.finished`).
- Displayed time = `phaseElapsedSeconds` (each line starts at 0:00). Skip/kill thresholds keep counting `elapsedSeconds` from the child's start, so **Skip for now** appears 15 s into the step and stays across the phase change. `isRunning`, `canSkip` and `tick()` treat `.updatingSearchIndex` like `.compacting`.
- Disk short with `reason == "fts_rebuild"` (from the check, or exit 2 `disk` after a pending check) shows `searchIndexDiskNotice`; otherwise the existing compaction notice. `fts_rebuilt` is logged (`DB search index rebuilt`) on exit 0, before the compaction log.
- Splash: `.updatingSearchIndex` shows `searchIndexLine(elapsedSeconds: compaction.phaseElapsedSeconds)`, the same subtitle and Skip button as `.compacting`; `.compacting` now passes `phaseElapsedSeconds`.
