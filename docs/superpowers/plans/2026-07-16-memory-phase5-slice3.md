# Secretary Memory Phase 5 — SLICE 3 (5B render-inversion, step 1: channel digests over memory episodes, dark compare-mode): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is sized for one focused agent session; obey the stated dependencies. Read `docs/superpowers/specs/2026-07-16-memory-phase5-universal-substrate-design.md` (**§5B step 1 ONLY** — channel digests consume the window's episodes; steps 2–4 of 5B are OUT), `docs/inventory/memory.md` (MEM-01..12, MEM-15) and `docs/inventory/catchup.md` (the legacy digest pipeline is covered here via `MarkDigestRead`/CATCHUP-01 — it must stay byte-untouched) **first**.

**Scope (this plan covers ONLY):** the FIRST render-inversion of 5B — **channel digests rendered from memory episodes, dark-launched in compare mode against the legacy digest pipeline**. Both pipelines run; the legacy one stays authoritative and byte-untouched; a per-channel diff report + shadow rows land in the branch for the owner's hand-review. This introduces the **MEM-13 kernel** (render fidelity: a memory-rendered digest's message refs cite only validated episode provenance — the hallucinated `key_messages` class dies by construction).

**Everything else is OUT of this plan:** 5B step 2 (people_cards ← person entities), step 3 (running_summary ← channel entity `## Current`), step 4 (decisions → episode-outcome facet); 5C internal-entity mirrors; the actual *switch* of the digest consumer off legacy (that follows only once the compare wins the owner's hand-review). Compare mode never mutates a `digests`/`digest_topics` row and never lets a memory render reach any UI.

**Architecture (a pure additive tail step; the existing daemon order and the legacy digest pipeline do not change):**
- **Episode-window query substrate.** Provenance refs today live only in each episode's `## Provenance` markdown section (`- <channel_id> <ts>` lines) — there is no indexed way to ask "which episodes cover Slack channel C in window [t0,t1]?". Slice 3 adds a **derived** index table `memory_provenance(node_id, scheme, channel_id, ts_raw, ts_unix)`, populated wholesale-per-node inside `UpsertMemoryNode` (the `memory_aliases`/`memory_fts` replace-on-upsert precedent) and cleared by `DeleteMemoryNode`/`DropMemoryIndex`. It is **rebuildable from files** (parsed from the body already passed to `UpsertMemoryNode`), so — unlike `memory_engagement`/`memory_entity_hints` — it belongs **inside** MEM-02's reindex-equivalence set (extends the contract, does not weaken it; owner-review flagged). The query layer is one helper: `ListEpisodesForChannelWindow(channelID, fromUnix, toUnix)`.
- **The memory render.** `internal/memory/digest_render.go` — `renderChannelDigest(ctx, gen, channelID, from, to, episodes, gapMsgs)` builds a cheap-tier prompt from the overlapping episodes' Story/Outcome + provenance, plus the raw messages in the window that no episode covers ("coverage gap" — the spec's "raw only for coverage gaps"), and returns a `digest_topics`-compatible shape (summary + topics[] with title/summary/decisions/action_items/situations/key_messages). New prompt `memory.render_channel_digest`, **cheap tier** (matches legacy `digest.channel_batch`/`channel`, both routed to `ModelHaiku`). **MEM-13 kernel:** every `key_messages` / decision `message_ts` the render emits is validated at write through the provenance registry's message resolver AND must be episode-cited (a member of the input episodes' provenance set, or a resolving raw gap-message ts); an invented ref is dropped-and-counted, never written to the shadow row.
- **Shadow storage.** A dedicated memory-owned table `memory_digest_shadow(channel_id, period_from, period_to, rendered_json, legacy_digest_id, coverage, ...)` — never the legacy `digests`/`digest_topics`. This makes the legacy-untouched proof structural: the compare runner reads legacy digests read-only and writes only the shadow table + a report file.
- **Compare runner + diff report.** `internal/digestcompare` runs after the memory extractor inside `phaseMemory` (so the current window's episodes already exist this cycle), gated by `memory.renders.digest_compare` (default false). For each recently-written legacy channel digest it: queries the window's episodes, renders the memory digest, writes a shadow row, and computes a mechanical field-by-field diff (topic count, per-topic key_messages **ref-validity** — 100% by construction for memory vs the measured legacy rate, coverage = window messages covered by episodes, length/compression). A CLI `watchtower memory digest-compare` writes the human-readable per-channel report to the branch; a hand-review protocol section is appended to the living validation task.

**Tech stack:** unchanged. Go 1.25, `modernc.org/sqlite`, goose migrations, `digest.Generator` (mocked in tests). No Swift in this slice.

- **All vault/index writes flow through existing helpers.** The provenance index is populated only inside `UpsertMemoryNode`/`DeleteMemoryNode` (never a second write path); the shadow table is written only by the compare runner.

## Resolved ambiguities (for reviewer attention)

1. **Episode-window query = a derived `memory_provenance` index table, NOT a per-cycle body scan.** Provenance refs live only in each episode's `## Provenance` markdown today; there is no indexed lookup by channel+window. A per-digest full-vault body re-parse would re-read every episode on every channel window every cycle and does not scale as the vault grows (~55 episodes/day, ~2.5K at steady state). The index is populated wholesale-per-node inside the existing `UpsertMemoryNode` transaction (the alias/FTS precedent), is **rebuildable from files** (so it goes INSIDE MEM-02, strengthening it), and is the shared substrate the later 5B steps (people_cards, running_summary) will also query. One parse site (`memory.parseProvenanceRefs`), one write site (`db.UpsertMemoryNode`), one transaction.
2. **Render tier = cheap (haiku), matching legacy.** Legacy `digest.channel_batch` and single-channel `channel` digests both route to `ModelHaiku` (`internal/digest/models.go`). The memory render consumes already-distilled episodes — a lighter task than raw-message analysis — so the cheap tier is at least as safe; using it keeps the compare cost-honest against legacy and keeps a future switch a like-for-like swap.
3. **Shadow storage = a dedicated memory-owned `memory_digest_shadow` table + a branch report file.** Rejected: a marker row in `digests` (would pollute the table CATCHUP-01's `MarkDigestRead` cascade and every DigestFilter/UI read touch, and risk a memory write into an operational table — MEM-05/14 violation). Rejected: a file-only artifact (loses the structured per-field diff). The side table makes the legacy-untouched proof structural: the runner reads legacy read-only and writes only the shadow table + the report.
4. **MEM-13 kernel = episode-cited + registry-validated refs, scoped to the render's own output.** A memory render's `key_messages`/decision `message_ts` is kept only when it is a member of the input episodes' provenance set (episode-cited — and thus already MEM-01-valid) OR a raw gap-message ts that resolves through the provenance registry's message resolver; anything else is dropped-and-counted (`render_refs_rejected`). This kills the hallucinated `key_messages` class by construction (100% valid vs the audit's ~0.6% legacy validity). MEM-13 here governs the *shadow render only* — the legacy pipeline's hallucinations are measured, not fixed; fixing them is the future *switch* off legacy, out of this slice.
5. **Placement = tail of `phaseMemory`, after the episode extractor.** The spec says "runs after legacy digests in the daemon cycle"; `phaseMemory` already follows `phaseChannelDigests`, and running the compare after extraction means the current cycle's episodes exist for the window (a fairer coverage number than running it before extraction). Residual lag: the extraction watermark may trail the digest window's newest messages; those trail as *coverage gap* (raw fallback), never a fabricated miss — recorded and surfaced as the `coverage` metric. The flag therefore requires `memory.enabled` (no memory phase → no compare) — documented, not separately gated.
6. **Coverage gap = window messages no episode provenance covers, fed raw.** The spec's "raw only for coverage gaps": the render prompt gets the overlapping episodes' Story/Outcome + provenance first, and the raw messages in `(from,to]` whose ts is covered by no episode as a fallback block, with an instruction to use raw only to fill what the episodes miss. `coverage = covered_ts / total_window_msgs` is the reported fidelity input.
7. **`memory_digest_shadow` is not cleared by `DropMemoryIndex`; `memory_provenance` IS.** `memory_provenance` is vault-derived (rebuilt by Reconcile → cleared on reindex, inside MEM-02). `memory_digest_shadow` is compare telemetry keyed by (channel, period) that self-overwrites; it is not vault-derived, so a reindex leaves it — harmless and avoids losing a report's input mid-validation.
