# Workchat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the workbench session's read-only Chat pane into Workchat: a fast, markdown-rendered dialog that drives the session (send, queue, Stop, permission answers, ask cards) and is the session's second mode next to the Terminal.

**Architecture:** Go `internal/sessionfeed` gains an `event` entry kind for Claude Code notices. Swift: pure, testable pieces in `WatchtowerCore` (markdown cache, feed window, navigation path, outgoing-line matcher, layout mode). The phone handlers' gates move into one Mac-side `SessionControl` used by both the phone and Workchat. Views in `Views/Workbench/` are rebuilt on the AI Chat render pattern (`MarkdownBlocksView`, `Equatable` rows).

**Tech Stack:** Go 1.26, SwiftUI (macOS 14), GRDB, existing `SessionLineDelivery`/`TerminalCenter`/`SessionAgentStateCenter`.

**Spec:** `docs/superpowers/specs/2026-10-18-workchat-design.md` (approved, ask #400). Mockups: `docs/superpowers/specs/2026-10-18-workchat-mockups.html`.

## Global Constraints

- FEED-01: no transcript text in SQLite or any sidecar; transcripts read-only.
- FEED-02 amended only to add `event` entries (owner approval: ask #400). Tool calls, tool output, thinking never reach the feed.
- FEED-03: JSON keys only added (`event_type`), none renamed.
- FEED-05 / phone unchanged: the phone payload keeps today's kinds. `event` never reaches the phone.
- One typing path: every Workchat line goes through `SessionLineDelivery.deliverLine`.
- Phone behaviour unchanged: `Tests/MobileHub/PermissionAnswerHandlersTests.swift`, `SessionInputHandlersTests.swift`, `MobileLinkCenterTests+Permissions.swift` pass with no edits.
- The pane spawns at most one `session-feed` CLI process at a time and none while off screen (`isTabOnScreen`, `UIVisibilityCenter`).
- UI copy is English and matches the mockups: **Workchat**, **Terminal**, **Show Workchat**, **Open in Terminal**, **Open in Workchat**, "Queued · sends when the agent stops · Cancel", "Subagents are read-only. Write to the agent in the main Workchat.", "Session finished. The history stays readable.", "Loading earlier messages…".
- Saved layouts (`projects.layout.<id>`) keep decoding. Raw values `WorkspacePane.sessionChat`/`WorkspaceView.chat` stay.
- Test fixtures are synthetic (public repo hygiene, `CLAUDE.md`). No live transcript text.
- Swift house rules: `docs/review/review-rules.md` "Swift / Desktop conventions". Swift lint: `make lint-swift` (lint-diff is Go-only).
- Inner loop only per task: `go test ./internal/sessionfeed ./cmd -run 'SessionFeed'`, `make test-swift FILTER=…`, `make lint-diff`, `make lint-swift`. The full gate runs once at the end.

## Review Focus

1. The owner sends a line while the terminal prompt holds their own half-typed text. The line is held (`promptHasText`), never appended to the draft. *Task 6 test `testLineHeldWhilePromptHoldsText`.*
2. The session ends while a Workchat line is queued. The bubble says it was not sent, and the text goes back into the field. It never silently vanishes. *Task 6 test `testQueuedLineAfterSessionEndsReturnsToField`.*
3. An older agent message grows, or new entries arrive, while the owner reads older text. The window keeps its first visible entry, the view does not jump, and following resumes only at the bottom. *Task 3 test `testAppendWhileScrolledUpKeepsAnchor`.*
4. A notice whose wrapper lacks `<summary>` or `summary="…"`. It becomes an event with a fallback title (the first non-empty body line, else "Notice"), never an empty line or an owner bubble. *Task 1 test `TestParse_NoticeWithoutSummaryHasFallbackTitle`.*
5. A permission prompt answered in the terminal (or by the phone) while the card is shown. Allow returns `notPending`, the card goes away and no error is shown. *Task 7 test `testAnsweredElsewhereRemovesCard`.*

```swift
package struct WorkchatOutgoing: Identifiable, Equatable, Sendable {
    package enum State: Equatable, Sendable { case sending, queued, typed, copied, sent, notSent }
    package let id: UUID; package let text: String; package let sentAt: Date; package var state: State
    /// The feed's owner entry for this line: same text with whitespace collapsed
    /// (a "/name args" line equals the parser's slash entry), dated at or after sentAt.
    package static func matches(_ entry: SessionFeedEntry, line: WorkchatOutgoing) -> Bool
    package static let echoWindow: TimeInterval = 90
}
@MainActor @Observable final class WorkchatModel {
    init(sessionID: Int64, control: SessionControl, lineDelivery: SessionLineDelivery, now: @escaping () -> Date = Date.init)
    var draft: String
    private(set) var outgoing: [WorkchatOutgoing]
    func send() async            // trims; empty → no-op; clears draft
    func cancel(_ id: UUID)      // queued only: lineDelivery.dropHeld(sessionID:where: key == .workchat(id))
    func reconcile(with entries: [SessionFeedEntry])  // removes matched lines; past echoWindow → plain local bubble kept
    func stop() async -> SessionControl.InterruptResult
}
```

- `onHeldEvent` updates the line's state the same way.
- The composer view:
  - Return calls `send()`. Shift-Return adds a newline.
  - The round button is Stop (■) when `SessionControl.isWorking(status)`, else Send (↑).
  - Esc in an empty field calls `stop()`.
  - A `.awaitingApproval` result shows nothing extra: the permission card (Task 7) covers it.
  - Hidden for a finished or stopped session, and for a non-live session.
- Bubble captions per the spec table, including **Show in Terminal** for `typed`/`copied`. It switches the pane to Terminal through the Task 8 toggle; until Task 8 lands, it uses `vm.showInPane(..., .session(id))`.
