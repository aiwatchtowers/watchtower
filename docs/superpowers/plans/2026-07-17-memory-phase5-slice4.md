**Scope (this plan covers ONLY):**
1. **5C entity mirrors** — targets and tracks get **entity** mirrors in the vault (the `situation:<id>` alias pattern generalized to `target:<id>` / `track:<id>`, but as long-lived *entity* nodes, not episodes — a target/track is a state machine, not a story arc), maintained by a mechanical (no-AI) Run step behind `memory.sources.operational`. Mirrors carry `## Current` (operational state) + `## Open loops` (this slice is the FIRST writer of that hitherto-empty skeleton section) + `## Links` **conversion cross-links** to the originating `situation:<id>` episode (the episode side already records "Converted to target #N" — `situationOutcome` in `ingest.go` and `verdictBullet` in `action_ingest.go`; the 5C piece is the mirror side of the link, NOT a duplicate annotation).
2. **5C read surfaces** — (a) the **day plan** reads open loops from memory (a new dark-gated prompt block in `internal/dayplan`, `memory.surfaces.day_plan`); (b) **meeting prep** reads attendees' entity pages and beliefs (`internal/meeting`'s `PrepareForEvent` — the surface EXISTS, CLI `watchtower meeting-prep`; new dark-gated prompt block, `memory.surfaces.meeting_prep`). Both follow the Phase-4 briefing pattern (`gatherMemoryRevisions` in `internal/briefing/memory_revisions.go`: sentinel placeholder when the gate is off, `OpenExistingVault`, degrade-silently on `ErrVaultNotInitialized`, model-mediated framing).
3. **5C subject-mapping upgrade** — `targetSubjects`/`trackSubjects` (`chat_ingest.go`) additionally map a target/track Discuss chat to its OWN mirror entity (the slice-2 known-limitation "a bare target chat maps to nothing" is resolved when mirrors exist; a no-op when they don't — `resolveSubjectRefs` already skips unresolved aliases silently).
4. **5D semantic preference beliefs** — the ordinary belief pass (`ReviseBeliefs`) gains a gated **OWNER ACTIONS** input block (`memory.semantic.preferences`) rendering this run's staged `act:` interactions + per-subject engagement aggregates into the user message, so the model can form preference beliefs ("the owner does not care about X-alerts") through the SAME propose-new/confirm/weaken/shake/retire ops, the same hysteresis/shaken/dispute machinery, the same revision journal. **No new rank, no new machinery, no new prompt id** — slice 1 already ships the rank (`owner-action`, MEM-15), the resolver (`actResolver`), the staging (`runInteractionIngest` → `mergeStaged`), and the mint (`newEvidenceLines`); what is missing (verified) is only that `buildReviseBeliefsPrompt` never SHOWS the staged `act:` refs to the model — `stagedChat.statements` carries chat turns only (`mergeStaged` doc: "the act path stages refs + subjects only, never OWNER SAID prose"), so today the model cannot cite an act ref it never saw.
5. **Contract MEM-14** (mirror, don't absorb): memory never becomes the write path for operational tables — a `TestMemory14_*` guard proving `targets`/`tracks`/`day_plans`/`day_plan_items` (plus the MEM-05 inbox set) are byte-identical across a full slice-4-gates-on run.

**Everything else is OUT of this plan:** all 5B switchovers (digest/people_cards/running_summary/decisions renders — they wait on the owner's live compare-report verdict per the slice-3 hand-review gate); Jira source (sync still dead); embeddings; vault sync; any Desktop/Swift change (day-plan UI reads `day_plans` rows unchanged; meeting prep is CLI); target parent-hierarchy links on mirrors; `owner-action` age decay (stays a fixed 0.8, revisit with live preference data); any second write author for beliefs (MEM-11).

**Architecture (verified against the code):**
- **Mirrors are entities, alias-keyed, content-equality idempotent.** `internal/memory/mirror_ingest.go` — a mechanical Run step **3c** (after `IngestSituations` step 3 and calendar 3b, before `runExtract` step 4 — situation episodes must exist for cross-links, and mirror aliases must exist before the same run's chat ingest / belief pass resolves them). For each candidate target/track it builds a deterministic entity body (the `situationBody` determinism discipline): `## What` (target text/intent/level, track text/category), `## Current` (status, priority, ball-on, due, next step — replaced wholesale each refresh), `## Facts` (untouched — the rewrite tier owns it), `## Links` (episode cross-links, `appendToLinks` idempotent), `## Open loops` (open sub-items + ball-on line while non-terminal; **cleared** when terminal). Alias `target:<id>` / `track:<id>`; `Node.Refs.Targets` (an existing, currently write-unused frontmatter field — verified only `node.go` parse/render touch it) is stamped with the target id on target mirrors. Idempotency = `LookupMemoryAlias` + body-equality no-op (the `calevent:`/`gmailthread:` precedent — no empty git commit); **no watermark** — targets/tracks are small mutable tables, so the step re-scans all non-dismissed rows + dismissed/terminal rows inside a bounded `updated_at` window (the `interactionRescanWindowDays = 14` precedent) every run, and the equality check makes an unchanged re-scan free.

## Resolved ambiguities (for reviewer attention)

1. **Mirrors are ENTITIES, not episodes, under ONE flag `memory.sources.operational`.** A target/track is a long-lived state machine — the entity kind (What/Current/Facts/Links/Open loops) is its natural mirror; its *stories* already reach memory as episodes via situations/conversions. Targets and tracks share one flag because they share one mechanism and one blast radius (a single mechanical reader-of-relational-state step); per-table flags would double the config surface for no isolation gain.
2. **No watermark for mirrors — bounded re-scan + content-equality.** Targets/tracks are small, mutable, non-append-only tables; a floor would miss in-place edits. The scan is all non-dismissed rows + a 14-day `updated_at` window for terminal ones (the `interactionRescanWindowDays` precedent), and byte-equality makes an idle re-scan free (no commit). Rows terminal before the source existed are never mirrored (noise, the `ingestNewSituation` precedent).
3. **Conversion outcomes were ALREADY episode-recorded (slice 0/1); 5C adds only the mirror-side cross-link.** `situationOutcome` writes "Converted to target #N." and `verdictBullet` annotates "converted to target #N" — duplicating either would double-count. The new piece is the `target:<id>` entity's `## Links` line to the situation episode, which also makes converted mirrors `linkedEpisodes`-eligible for the rewrite/belief scope.
4. **Preference beliefs ride a gated USER-message block; `memory.revise_beliefs` stays v1.** Verified: the OWNER SAID block (Phase 4) set the precedent — instructions inline in the user message, system template untouched. This is what makes `memory.semantic.preferences=false` *byte-identical* (a v2 system template would leak different bytes with the gate off). No new prompt id → no `add-ai-prompt`/light-tier work; the pass stays strong-tier, budget-gated, `beliefs_max`-capped as today.
5. **The spec's "meeting prep" surface exists** (`internal/meeting.PrepareForEvent`, CLI `watchtower meeting-prep`) — no fallback scoping to calendar briefing was needed. It is CLI-invoked (not a daemon phase), which is fine: the gather runs at call time against the current vault.
6. **The day plan keeps its direct `targets` read; memory adds loops, not tasks.** `gatherTargets` stays authoritative for schedulable targets (MEM-14: memory is never the write/authority path for operational state). The memory block contributes cross-universe open loops (tracks, converted stories) with an explicit dedupe instruction, so the model never schedules the same target twice.
7. **Beliefs already range over mail/calendar/chat/act after slices 1–3** (verified: cross-source episodes back-link entities; `validateMarkers` admits their refs via the input set; `validateChatRefs` passes episode refs untouched). 5C's addition here is *subjects* — mirrors bring the owner's own work items into the rewrite/belief scope — and 5D's is *visibility* — the model finally sees the act refs it may cite.
