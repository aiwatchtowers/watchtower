# Chat — claude.ai tools: publish and connectors (2026-10-17)

Board #737; spec `docs/superpowers/specs/2026-10-16-chat-claude-ai-tools-design.md` (approved ask #325, decisions Q1–Q4 ask #326, scope and the CHAT-05 exception ask #236), plan `docs/superpowers/plans/2026-10-17-chat-claude-ai-tools.md` (approved ask #332). Wire shapes recorded with Claude Code 2.1.302: `internal/chat/testdata/claude_ai_probe.md` and the `claude_ai_*.jsonl` fixtures win over the spec's F-table.

- **Scope.** Only the warm main chat (`ai session --surface main`) on the Claude provider changes. `ai query` (meeting, idea, track, target chats), the daemon pipelines, automations and `mcp --workbench` keep `--strict-mcp-config` and their tool lists (decision Q2). `--setting-sources project,local` and the private neutral cwd stay on every spawn (TCC guard).
- **Availability** (`internal/chat/claudeai.go`): `chat.ClaudeAIAvailability(env, provider, surface)` is on only for provider `claude`, surface `main` and a child environment (`os.Environ()` plus `ClaudeOptions.Env`, last entry wins) without `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` or `CLAUDE_CODE_USE_FOUNDRY`. `cmd/ai_session_gate.go` `resolveClaudeAI` calls it once per `ai session` process; the backend's `ClaudeAIMode`, the prompt's `ClaudeAIPrompt` and the publish dir come from that one answer. The init event then has to confirm the login: `apiKeySource` `"none"` keeps the tools, any other value (or none) marks the catalog unavailable for the session's life (`apiKeyUnavailableReason`). `CLAUDE_CODE_OAUTH_TOKEN` and an `ANTHROPIC_BASE_URL` gateway do not switch it off by themselves.
- **Spawn in claude.ai mode** (`claude_backend.go`): `--permission-prompt-tool stdio` instead of `--strict-mcp-config`; `--tools ai.ClaudeAISessionBuiltinTools` (`ToolSearch,WebSearch,Artifact,Write`), `ai.ClaudeAISessionDisallowedTools` plus `mcp__claude_ai_<Token>` for each switched-off connector (`chat.DisabledToolTokens`) and every connector's `authenticate`/`complete_authentication`; `mcp__claude_ai_*` tokens are stripped from `--allowedTools` (`withoutReservedAllowTokens`) and Quick Connections refuse names starting with `claude_ai` (`connectorpolicy.ReservedServerToken`, `cmd/connections.go`), so a local server cannot pre-allow a real connector's write. Env: `CLAUDE_CODE_ARTIFACT=1`, `CLAUDE_CODE_ARTIFACT_AUTO_OPEN=0`, `ENABLE_CLAUDEAI_MCP_SERVERS=1|0` (always set, from `ai.claude_ai.connectors`). `ArtifactComments`, `ArtifactData`, `ArtifactCheck` stay hidden.
- **File sandbox — the TCC guard for the exposed file tools** (`internal/chat/sandbox.go`, owner decision ask #342 "guard before the CLI"): the CLI touches a model-chosen path *before* it sends `can_use_tool` — it lists a `Write` target's folder, and stats (in its cwd also hashes) an `Artifact` `publish` source to pin it — so the gate alone cannot keep a path in `~/Documents` untouched, and that touch from a Watchtower-spawned child would raise a privacy prompt in Watchtower's name. So the claude.ai-mode child always starts as `/usr/bin/sandbox-exec -D H0=<home> … -p <profile> -- <claude> <argv>` (`ChildSandbox.command`; the CLI path resolved first): `(allow default)` plus `(deny file-read* file-write* file-test-existence …)` for `/Volumes`, `/Network`, `/home`, `/net` (each also by its resolved spelling — macOS's `/home` is a symlink to `/System/Volumes/Data/home`, and a denied symlink does not deny its target; a home on one of them turns the tools off) and, under every home (`$HOME` and the account's own, symlinks resolved, passed as `-D` parameters, never in the profile text), `Desktop`, `Documents`, `Downloads`, `Pictures`, `Movies`, `Music`, `.Trash`, `Library/Mobile Documents`, `Library/CloudStorage`, `Library/Containers`, `Library/Group Containers` and the app-data folders of Contacts, Calendars, Reminders, Mail, Messages, Safari, Photos, HomeKit, TCC itself and the like (`protectedHomeDirs`). A sandbox denial is decided before TCC is consulted: the access fails with `EPERM`, no prompt (observed: a sandboxed read of an FDA-guarded file logs `Sandbox: … deny(1)` and no `tccd` request, while the same read unsandboxed logs a `tccd` `AUTHREQ` attributed to Watchtower). `resolveClaudeAI` builds the sandbox once per `ai session` (`chat.NewChildSandbox`, which also runs `/usr/bin/true` under the profile); without one — not macOS, no `sandbox-exec`, a home on a protected root, a profile that does not run — the tools are off with that reason (Settings is told), and a backend in claude.ai mode refuses to spawn a child without its sandbox. Recorded with 2.1.302 (`claude_ai_probe.md`, "Sandbox"): auth, connectors and every probe answer are unchanged under the profile; a `publish` from a protected folder is refused by the CLI itself ("this source cannot be safely verified") with no request and no byte read; a `Write` into one fails in the CLI's own pre-permission `stat` (`EPERM`) and never reaches the gate. The sandbox is inherited by everything the child starts, so the chat's MCP servers (Watchtower's own — its data lives under `~/.local/share/watchtower` — and Quick Connections) cannot read those folders either.
- **The gate** (`internal/chat/gate.go`, spec D3–D5): every `can_use_tool` control request goes through `connectorpolicy.Policy.Decide` (pure, `internal/chat/connectorpolicy`, first match wins): a built-in `Write` only inside the publish dir; `Artifact` `publish` of sources inside the publish dir (relative `files` sources joined with `root`), `list`/`open`/`quickstart`, `read` with `out_dir` rewritten into the publish dir (the final path checked too), `publish` with a `url` only for a URL this session published, `pin`/`unpin`/`delete` → Ask; a connector tool — only when the request's `mcp_server` is `{name:"claude.ai X", source:"claudeai"}` and its token matches the tool name — is denied when switched off, when the catalog does not list the server as an account connector (unknown **server** → deny, after one `mcp_status` refresh) or for the sign-in tools; the override table (`overrides.go`) and the Claude Docs rules come next (create/update/batch — a comment (`utterance`) included — free only inside a doc this session created, `OwnDoc`; a share, a delete (`delete`, `verb:"delete"`, a JSON-patch `op:"remove"`), a mention of anyone but the owner, any `answering` (a reply to a comment thread, even in the own doc), a comment `parent` given as a bare id, a string `payload` the policy cannot inspect, or any foreign doc → Ask); then `readOnly` and not `destructive` → Allow; anything else, an unknown **tool** of a listed connector included (after one refresh) → Ask. Allow echoes the request's own input byte for byte (an `Artifact` input carries the CLI's `__artifact*` sha256 pin), Deny sends the reason the model receives verbatim, a malformed request is denied. Every error fails closed.
- **Ask = one session-applied row** (`claude_ai_connector_call`, `External`, `AlwaysAsk`, `AppliedBySession`; `internal/tools/claude_ai_connector_call.go`, `registry_session.go`): the gate proposes it through `Registry.ProposeSessionCall` (`Propose` refuses the tool), commits it, then emits `tool_wait`, and polls the row every second for up to 15 minutes (`GateApprovalTimeout`, decision Q3). Approved → `ClaimSessionCall` (`approved → executing`, the AGENT-05 conditional claim) → allow with the stored input, the owner's edits included → `FinishSessionCall` records the result (`applied`, or `failed` for every `isError` result). Reject → deny. Timeout → `CancelSessionCall(…, "not approved within 15 minutes")`; Stop/Close → `"stopped"` (a pending row lands `rejected`, an approved one `failed`, both with that reason); an Approve racing either wins only if it lands first (exactly one outcome). A permanent status error (`ErrNotFound`, `ErrNotThisSession`) denies at once. `actions approve` stops at `approved`, `actions apply` (with or without `--force`) refuses the tool, the Desktop hides Retry. **Inbox badge (owner decision, ask #342):** a failed call is settled — off the badge, Home's Waiting on you and the strip's waiting group (`AgentActionQueries.settledSessionCall`) — except `session ended while the call ran; outcome unknown`, which may have reached the connector: it counts like a pending proposal until the owner clicks **Dismiss** on its card (`ConnectorCallProposal.awaitsDismissal`, `AgentActionFeed.dismiss`) → `actions dismiss <id>` (`Registry.DismissSessionCall`, refused under an agent, AGENT-07) stamps `agent_actions.dismissed_at` (migration `00140`); the status stays `failed`, a second dismiss is a no-op, any other row is `ErrBadTransition`. "Not sent", "stopped" and "session ended before approval" never count. A dismissed row stays in the strip's terminal tail by `dismissed_at`. Limit: a row left `executing` by a dead session reads "outcome unknown" too but is neither counted nor dismissable until `ExpireSessionCalls` fails it (the next chat session start).
- **Session token** (migration `00139`, `agent_actions.session_token`): `ai session` generates one random token per process (`registrySink`) and passes it to every Claim/Finish/Cancel/Expire; another process of the same conversation (respawn, `--resume`, replay) gets `ErrNotThisSession`. `ExpireSessionCall(id, token, reason)` fails an unclaimed row this session will never run (Stop after Approve, the CLI's `control_cancel_request`, the child gone). Before its first spawn a session runs `ExpireSessionCalls(conversationID, now−20m)` (token ignored): its own conversation's open rows and any other conversation's rows older than 20 minutes land `failed` — `session ended before approval`, or `session ended while the call ran; outcome unknown` for an `executing` one — and are never run again.
- **Publish dir** (`internal/chat/publishdir.go`): `<NeutralWorkDir>/publish/<conversation id>`, 0700, removed on `Close`. `Check` is lexical and point-in-time: any `..` refused, a relative path resolves against the child's cwd, a symlink, hard link, special file, another user's entry or a swapped level inside is refused (`ErrOutsidePublishDir`, `ErrUnsafePublishPath`); `/var` and `/private/var` spellings both pass. `Check` itself never stats anything outside the dir (the CLI does before it asks; the file sandbox keeps that out of the protected folders). It holds only while the child has no Bash, link-creating or cwd-changing tool — keep those out of the claude.ai allowlist.
- **Connector catalog and sidecar** (`internal/chat/connectors.go`, contract at the top of the file, fixture `testdata/claude_ai_connectors.json`): the backend sends `mcp_status` every second for up to 10 s after the spawn (one answer awaited up to 2 s), keeps the live snapshot for the policy and writes `<db dir>/claude-ai-connectors.json` (0600, temp file + rename): `updated_at`, `available`, `unavailable_reason`, `servers[{name, status connected|needs-auth|failed|pending|disabled, tools[{name, read_only?, destructive?}]}]`. A Claude main chat without the tools because of its environment (an API key, a third-party provider, an unconfirmed login) writes the unavailable form with its reason; a Codex or Ollama chat (the provider is per conversation) and a failed publish dir leave the file alone; an embedded surface never writes it. Config keys: `ai.claude_ai.connectors` (bool, default true; `config set` accepts only true/false) and `ai.claude_ai.disabled_connectors` (display names; `config set` takes them comma-separated, `""` = none). A switch applies when the next session starts; the Desktop retires idle sessions on a toggle (`ChatSessionPool.retireIdleSessions`), a busy turn finishes first.
- **Prompt** (`prompt_sections.go` `claudeAIBlock`, spec D7): On → publishing rules (pages and decks via `Artifact` from the publish dir, docs via Claude Docs, answer with the link, never "paste a prompt into claude.ai") and the connectors lines (reads free, writes are proposals that wait up to 15 minutes — pinned to `GateApprovalTimeout`); connectors off → one line; Codex/Ollama main chat → "needs the Claude provider; use the in-app artifact"; unavailable → the reason. Pages, decks and docs publish to claude.ai by default; drafts to send, tables and code stay in-app artifacts.
- **Protocol v2 additions → Desktop.** `tool_wait` `{turn_id, id, message:"Waiting for your approval", action_id}` (live only, all four fields always set; `testdata/events_v2_tool_wait.jsonl`): `ChatTurnDriver`/`LiveTurn` show an orange waiting step until the step ends ("see the approval card below"); the main chat refreshes the action feed once at wait start. A `tool_end` source `{kind:"claude_ai_published", title, url, ref}` (`testdata/events_v2_published_source.jsonl`; the link is the first `https://claude.ai/…` URL in the result not already in the input) renders `PublishedLinkCardView` — **Open in Browser** / **Copy Link** only, `https` and host exactly `claude.ai` (`PublishedLink`). The connector-call card (`ConnectorCallProposal`, `AgentActionCardView+Connector.swift`) shows connector, tool and the exact input, editable as a JSON object (`approve --patch {"input": …}`); its status lines key off the Go reason texts (Go side pinned by `TestGate_RowReasonTextsMatchTheCard`; change both together); Approve is offered only while the conversation's live session runs the row's turn, otherwise "Chat session ended"; `AgentActionFeed.bulkApprovable` skips session calls. Settings → Profile → claude.ai tools (`ClaudeAIConnectorsSection`, `ClaudeAIConnectorsModel` on `AppState`, `ClaudeAIConnectorsFile` decodes the Go fixture) lists the sidecar's servers with a master switch, one switch each and **Connect on claude.ai** (`https://claude.ai/customize/connectors`) for `needs-auth`.
- **Contracts:** CHAT-02 (gate decisions are steps), CHAT-03 (Close while waiting), CHAT-05 (the one private publishing exception; every other connector write through the gate), AGENT-03 (`claude_ai_connector_call` never executes inline), AGENT-05 (session-applied rows, session token) — `docs/inventory/chat.md`, `docs/inventory/agent-actions.md`. CHAT-04 unchanged: the prompt never reaches argv.
- **v1 limits.** A resumed conversation keeps its recorded system prompt (CHAT-04), so a chat started before this shipped — or one whose prompt was built while the tools were unavailable — runs without the claude.ai section while the tools still appear; the reverse case — an On prompt resumed by a session that is now unavailable — is covered by the On prompt's own rule: `Artifact` missing or refused → say so and give an in-app artifact. `Read` stays hidden (the CLI runs a read inside the cwd without asking, so the gate could not confine it) and `Edit` is not added (`Write` rewrites a whole file). Unknown server → deny, unknown tool of a listed connector → Ask. The pages and docs a session published or created are remembered per `ai session` process (`gate.own`): after an idle retire, a settings toggle or an app restart, updating an earlier page or doc goes to Approve. Several warm sessions rewrite the same sidecar, so a session started before a toggle may write an older disabled state over a newer one until the next start. `ExpireSessionCalls` also fails another conversation's row still `executing` after 20 minutes ("outcome unknown"), which a very slow live call could hit. An early exit can leave an empty 0700 `publish/<id>`, reused on the next start. A connector display name containing a comma cannot be switched off (the list is stored comma-separated; Settings refuses it). Docs node refs and comment parents are trusted through the session's own container; the publish-result and doc-creation ack formats were not recorded (link = first claude.ai URL not in the input). The file sandbox is a deny-list of the standard places macOS guards today (a TCC class Apple adds later needs a new entry), and it is path-based: a volume mounted somewhere other than `/Volumes`, `/Network`, `/home` or `/net`, a Photos library moved out of `~/Pictures`, or a hard link made elsewhere before the session to a protected file is not caught (the child itself cannot make one); it keeps Quick Connection servers in the main chat out of those folders too, and `sandbox-exec` is deprecated by Apple (still shipped; its absence turns the tools off, never on unguarded). No `ArtifactComments`/`ArtifactData`, no Desktop "Publish" button, no connectors in pipelines, automations or embedded chats, no Codex equivalent.
