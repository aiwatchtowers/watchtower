# Code navigation in the workbench code viewer (2026-10-02, phases A–B; AI questions are phase C)

- Spec: `docs/superpowers/specs/2026-10-02-code-navigation-design.md` (the R-numbers are design rulings cited in the spec and the code; the ones that shape behaviour are below). Go parses and searches, Swift owns state, matching and UI; no database tables — each workbench's index lives in memory only and is rebuilt from its folder.
- **CLI (Go).** `codewalk.Files` is the one file walk both commands share (`git ls-files` inside a repository via `gitbin`, else a walk skipping the Swift `CodeFileTree.hiddenNames`, pinned by the `code_hidden_names.json` fixture; > 2 MB index / > 5 MB search and binary files skipped). `watchtower code search --folder DIR --query Q [--word] [--case] [--regex] [--max] [--context] --json` (`internal/codesearch`) streams `{"path","line","col","text","text_col","before","after"}` lines, then `{"done":true,"files","matches","truncated"}`; SIGTERM stops it within 50 ms with no `done` line. `watchtower code index --folder DIR --json` (full, streamed per file) / `--files a b` / `--serve` (one request line of tab-separated paths per update) (`internal/codeindex`, tree-sitter under `cgo`; the full grammar set behind the `codegrammars` tag, Go/Swift/Python otherwise, none without cgo) streams `{"file","lang","symbols":[…]}`, then `{"done":true,"files","symbols","ms"}`. A named path that is gone is `{"file","deleted":true}`; one that is not a workbench file (ignored, binary, oversized, outside, a directory) is `"skipped":true` (R21); an unsupported language is `"lang":""`; a language indexed by a scan rather than a grammar (HTML, CSS, SCSS, Dockerfile, Markdown, YAML, TOML, JSON — `langSpec.holdsDefinitions`) carries `"defs":false` (R32). Symbol `outline:true` marks Markdown headings and config keys: jump bar only, never Open Quickly's Symbols. Columns are UTF-16, lines 1-based, everywhere.
- **Centers on `AppState`** (state outlives the pane and navigation): `CodeIndexCenter` (one index per workbench while shown — Files pane, FILES or Open Quickly, paired `markShown`/`markHidden` (R25) — kept 5 min after; one run at a time, a newer batch merges, rescan supersedes, `FolderWatcher` → 300 ms debounce → `--serve`; the `--serve` child lives ≤ 5–6 min after hide, R24), `OpenQuicklyCenter` (⇧⇧, ⇧⌘O, ⇧⌘F; its `keyWorkbench` gates the whole Navigate menu), `CodeNavigationCenter` (go to definition, per-workbench Back/Forward history, ⌃6), `CodeUsagesCenter` (⇧⌘U and the Files pane inspector). Every child is a `CodeCLIProcess`: `posix_spawn` in its own process group at utility QoS, group SIGTERM then SIGKILL, always reaped, stdin writes and close serialised on one queue. The three search centers share `CodeSearchRun` through the `CodeSearchStarter` seam: one live run per workbench (Open Quickly per session), a newer request cancels the older, generation counters drop stale callbacks. App quit stops every child of all four centers (`AppState.stopCodeNavigationChildren`, R34). Matching and ranking (`FuzzyMatch`, `CodeRanking`, `OpenQuicklyModel`, `DefinitionCandidates`, `NavigationHistory`, `JumpBarSegments`, `UsagesModel`) are pure Core types.
- **Page protocol** (`CodeEditorWeb/index.html` header, spec §8.5, checked by `make editor-bridge-check`): page → Swift `definition {req,id,word,line,col,x,y}` (⌘-click or `definitionAtCursor`; `x,y` anchor the menu, R29), `cursor {id,line,col}` (≤ 10/s, the last move always sent; `current` switches before the model, so the first message after a tab switch names the new file), `usages {id,word,line,col}`; Swift → page `definitionAtCursor()`/`usagesAtCursor()` → Bool, `definitionDone(req)` (only the latest clears the busy underline), `reveal({id,line,col})` (held until that file is shown), `focus()`. Monaco's own bindings for the app's chords are removed (R28) so they reach the menu from inside the editor.
- **Behaviour rulings.** Go to definition: one index candidate opens a kept tab, several ask through a menu ending in "Show All Usages…", none fall back to the `code search --word --case` heuristic only in a file whose language the index does not read for definitions — `lang ""`, `"defs":false`, or not indexed yet (R31/R32); in an indexed language a miss beeps and says "No definition of `w`" (or "still indexing"). A definition jump, a Usages row click (R33) and a jump-bar pick all put the location they leave on Back. ⇧⌘O belongs to Open Quickly on a workbench page (R26). ⌥↩ with Files as the only pane opens in place (R27). Open Quickly's ✦ Ask AI row, its "⌘↩ Ask AI" hint and ⌘↩/⌥⌘↩ are hidden behind `OpenQuicklyAskAIFeature.isEnabled` until phase C (R35). The ⌃6 filter opens the first match only on Return (its × just clears).
- **Keys** (spec §10): ⇧⇧/⇧⌘O, ⇧⌘F, ⌘-click/⌃⌘J, ⇧⌘U, ⌃6, ⌃⌘←/→ — the Navigate menu enables them only while a workbench window, or its Open Quickly panel, is key (R36).
- **v1 limits (accepted).** The hand-off of unconsumed chords from the WKWebView to the SwiftUI menu, and the ⌃6 filter field's typing/arrow hand-off inside the `NSMenu`, are verified manually only (the harness proves Monaco binds none of them; unit tests cover menu → center → page). ⌃6 is swallowed in the workbench terminal (vim's Ctrl-^, R36). ⌥⌘↩ no longer runs Monaco's Replace All (R30; the widget's button stays). Unsaved buffers are indexed from disk. Open Quickly's host is keyed by workbench id only; one jump bar and one Files pane per workbench (R27). A `--serve` crash requeues without retry (the state shows it; the next show runs a full pass). Back/Forward to a deleted or renamed file goes nowhere useful. Phase C adds the code questions (⌘I, Ask AI, hand to Claude Code).
