# Code navigation in the workbench code viewer (2026-10-02, phases A–B; AI questions and the hand to Claude Code are phase C)

- Spec: `docs/superpowers/specs/2026-10-02-code-navigation-design.md` (the R-numbers are design rulings cited in the spec and the code; the ones that shape behaviour are below). Go parses and searches, Swift owns state, matching and UI; no database tables — each workbench's index lives in memory only and is rebuilt from its folder.
- **CLI (Go).** `codewalk.Files` is the one file walk both commands share (`git ls-files` inside a repository via `gitbin`, else a walk skipping the Swift `CodeFileTree.hiddenNames`, pinned by the `code_hidden_names.json` fixture; > 2 MB index / > 5 MB search and binary files skipped). `watchtower code search --folder DIR --query Q [--word] [--case] [--regex] [--max] [--context] --json` (`internal/codesearch`) streams `{"path","line","col","text","text_col","before","after"}` lines, then `{"done":true,"files","matches","truncated"}`; SIGTERM stops it with no `done` line, targeting ~50 ms (the test allows 500 ms for loaded CI runners). `watchtower code index --folder DIR --json` (full, streamed per file) / `--files a b` / `--serve` (one request line of tab-separated paths per update) (`internal/codeindex`, tree-sitter under `cgo`; the full grammar set behind the `codegrammars` tag, Go/Swift/Python otherwise, none without cgo) streams `{"file","lang","symbols":[…]}`, then `{"done":true,"files","symbols","ms"}`. A named path that is gone is `{"file","deleted":true}`; one that is not a workbench file (ignored, binary, oversized, outside, a directory) is `"skipped":true` (R21); an unsupported language is `"lang":""`; a language indexed by a scan rather than a grammar (HTML, CSS, SCSS, Dockerfile, Markdown, YAML, TOML, JSON — `langSpec.holdsDefinitions`) carries `"defs":false` (R32). Owner regex rules (spec §6.5, `codeindex.LoadRules`): `code-languages.yaml` in the app's Application Support (or `code index --rules PATH`) adds `<lang>: {extensions, filenames, definitions: [{kind, pattern}]}` languages — RE2, group 1 = name, kind from the §6.1 set — only for files the language table does not know; any invalid part rejects the whole file, reported once on stderr and as `"rules_error"` on every `done` line (the jump bar says "Rules file: <error>"); a missing default file is no rules, a missing `--rules` file exit 2; built-in ids, extensions and file names cannot be claimed. The CLI reads the file once per process. Desktop: `CodeIndexDone.rulesError` → `WorkbenchCodeIndex.rulesError` (the last done line's, so a full run after a fix clears it) → `JumpBarRulesNote`, a muted note after the status on every file (which files a rejected file meant to cover is unknown): the leading file path dropped, whitespace collapsed, cut to 80 characters, the full error in the tooltip. `CodeIndexCenter` watches the file from the first show (`CodeRulesFileWatcher`: vnode sources on the Application Support folder and on the file, reporting only a change of the file's identity, size or mtime, so the database's writes beside it are ignored); an edit, debounced 500 ms, kills every run in flight and every `--serve` child (the next update starts a fresh one) and runs a full index for the workbenches on screen — a hidden one gets its full run when shown. Production passes no `--rules` (the CLI default is the same file); tests pin `rulesFile:` to a temp file, passed as `--rules`. Symbol `outline:true` marks Markdown headings and config keys: jump bar only, never Open Quickly's Symbols. Columns are UTF-16, lines 1-based, everywhere.
- **Centers on `AppState`** (state outlives the pane and navigation): `CodeIndexCenter` (one index per workbench while shown — Files pane, FILES or Open Quickly, paired `markShown`/`markHidden` (R25) — kept 5 min after; one run at a time, a newer batch merges, rescan supersedes, `FolderWatcher` → 300 ms debounce → `--serve`; the `--serve` child lives ≤ 5–6 min after hide, R24), `OpenQuicklyCenter` (⇧⇧, ⇧⌘O, ⇧⌘F; its `keyWorkbench` gates the whole Navigate menu), `CodeNavigationCenter` (go to definition, per-workbench Back/Forward history, ⌃6), `CodeUsagesCenter` (⇧⌘U and the Files pane inspector). Every child is a `CodeCLIProcess`: `posix_spawn` in its own process group at utility QoS, group SIGTERM then SIGKILL, always reaped, stdin writes and close serialised on one queue. The three search centers share `CodeSearchRun` through the `CodeSearchStarter` seam: one live run per workbench (Open Quickly per session), a newer request cancels the older, generation counters drop stale callbacks. App quit stops every child of all four centers (`AppState.stopCodeNavigationChildren`, R34). Matching and ranking (`FuzzyMatch`, `CodeRanking`, `OpenQuicklyModel`, `DefinitionCandidates`, `NavigationHistory`, `JumpBarSegments`, `UsagesModel`) are pure Core types.
- **Page protocol** (`CodeEditorWeb/index.html` header, spec §8.5, checked by `make editor-bridge-check`): page → Swift `definition {req,id,word,line,col,x,y}` (⌘-click or `definitionAtCursor`; `x,y` anchor the menu, R29), `cursor {id,line,col}` (≤ 10/s, the last move always sent; `current` switches before the model, so the first message after a tab switch names the new file), `usages {id,word,line,col}`; Swift → page `definitionAtCursor()`/`usagesAtCursor()` → Bool, `definitionDone(req)` (only the latest clears the busy underline), `reveal({id,line,col})` (held until that file is shown), `focus()`. Monaco's own bindings for the app's chords are removed (R28) so they reach the menu from inside the editor.
- **Behaviour rulings.** Go to definition: one index candidate opens a kept tab, several ask through a menu ending in "Show All Usages…", none fall back to the `code search --word --case` heuristic only in a file whose language the index does not read for definitions — `lang ""`, `"defs":false`, or not indexed yet (R31/R32); in an indexed language a miss beeps and says "No definition of `w`" (or "still indexing"). A definition jump, a Usages row click (R33) and a jump-bar pick all put the location they leave on Back. ⇧⌘O belongs to Open Quickly on a workbench page (R26). ⌥↩ with Files as the only pane opens in place (R27). Open Quickly's ✦ Ask AI row, its "⌘↩ Ask AI" hint and ⌘↩ ship with phase C (`OpenQuicklyAskAIFeature.isEnabled`); ⌥⌘↩ hands the query to Claude Code (§9.5, `handToClaudeEnabled`; R35 kept the switch). The ⌃6 filter opens the first match only on Return (its × just clears).
- **Keys** (spec §10): ⇧⇧/⇧⌘O, ⇧⌘F, ⌘-click/⌃⌘J, ⇧⌘U, ⌃6, ⌃⌘←/→ — the Navigate menu enables them only while a workbench window, or its Open Quickly panel, is key (R36).
- **Code questions (phase C, in progress).** `watchtower ai query --read-folder DIR` (`cmd/ai.go`) takes only a workbench folder (symlinks resolved, `db.WorkbenchByFolder`; anything else, or `--tools`, is exit 2). With it the provider reads the folder (owner decision 1, confirmed 2026-10-03, ruling R55; supersedes R42/R44): claude runs with cwd = the folder, `--tools` = `ReadFolderBuiltinTools` (ToolSearch + Read, Grep, Glob, LS), `--disallowedTools` = `ReadOnlyFolderDisallowedTools` (DisallowedTools minus those four) and `--setting-sources ""` (the folder's hooks never run); codex runs with `--cd` the folder, its shell on under `--sandbox read-only`, web search off, the watchtower server mounted by `-c`; ollama has no file tools. Without the flag both argvs are byte-identical (golden tests; `approvedChatBuiltins` pins the read-folder run's built-ins). `CodeQuestionSurface` (`Sources/Services/ChatSurfaces/`) is draft-only, on `chat_conversations` rows with `context_type = 'code_question'`, `context_id = '<workbench>:<path>:<line>'`, one conversation per question; the owner's provider/model pick lives on the conversation and is read per turn through `ChatSurfaceSpec.runOptions` (`ChatRunOptions`: provider, model, read folder; a non-Claude provider gets the system prompt again instead of a Claude session id, and every turn that resumes no provider session — Codex, Ollama, a Claude turn after a switch — starts with the conversation so far as Core `EmbeddedChatReplay`'s block, the main chat's Go replay wording and 24 000-character cap: system notices, failed replies and the question a Retry sends again left out, a stopped reply marked; board #361). `CodeQuestionContext` (Core) builds the first-turn context (folder, path, language, selection or cursor line, ±40 lines, ≤ 10 uniquely resolved index entries). Guards: `CodeQuestionSurfaceTests.testCodeQuestionGuard_NeverInTheMainChat` (list, title search, FTS), `TestCodeQuestionGuard_NoGoToolReadsChatHistory` (`internal/tools`) and `TestCodeQuestionGuard_ChatIngestNeverReadsCodeQuestions` (`internal/memory`).
- **Popover at the selection (phase C, Task 11).** `CodeQuestionCenter` (`AppState`, wired in `initWorkbenches`) owns per workbench the ✦ button's timing (Core `AskAIButtonSchedule`: 0.5 s after a non-empty selection settles; every `selection` or `scroll` message hides it and restarts the wait; suppressed while the popover is open) and the popover's question (`Session`: `CodeQuestionAnchor` — the selection, or the cursor line when nothing is selected — the first-turn `CodeQuestionContext`, the model pick, the suggested change). ⌘I is the page's own (consumed, so Navigate › Ask AI ⌘I only acts when the keyboard is elsewhere; Monaco binds nothing to it, R28); the ✦ and the menu ask the page (`askAI()`), so every path ends in the page's `askAI {id}` right after its `selection`. One popover per workbench; a second `askAI` while it is open does nothing. The conversation row is created on the first question (an opened and dismissed popover leaves none) and runs on `CodeQuestionSurface` in `EmbeddedChatCenter`; Esc, a click outside or a link click closes the `NSPopover` (`.semitransient`) and its diff, never the answer. `path:line` citations become `watchtower-code://open?path=…&line=…` links (Core `CodeLineLinks`; render-only: kept by the markdown strip only under the `markdownCodeLinks` environment flag the popover sets, never in `AllowedURLSchemes.permits`, so no other surface links or opens them) that open the file in Files when it is a file of the folder (Core `WorkbenchFolderPath`: each component `lstat`ed, a symlink followed only when its target's text stays inside the folder, so a link through a symlink to `~/Documents` never touches the target — no privacy prompt; board #361); a citation inside an existing markdown link is left alone (no link within a link). A completed reply's first `wt-edit` block (Core `WtEditBlock`; a selection's trailing line break is kept) is shown with `proposeEdit`; **Apply** is refused while the buffer has a `CodeFileBuffer.Problem` (PROJ-03) or for a selection the page cut at 20 KB, and the page refuses (`"changed"`) when the range no longer holds the question's text; otherwise it is one undoable `executeEdits` and the usual `text` → autosave path. After Apply the anchor moves onto the applied text, so a follow-up's suggestion applies too (the page compares line breaks as LF). **Where is it used?** (ruling R45) first runs `code search --word --case --max 30` for the selected identifier (else the one at the cursor; none → sent without) and attaches the locations to the context — the system prompt on a first turn, the turn's prompt once on a resumed session; the search is cancelled with the popover or the pane and reaped on quit (`stopCodeNavigationChildren`). A popover that cannot show (no window) drops its question. PROJ-03's amendment for Apply is owner-approved (2026-10-03, R47).
- **Open Quickly answers and the Questions tab (phase C, Task 12).** ⌘↩ or the ✦ Ask AI row calls `CodeQuestionCenter.askFromOpenQuickly`: a new conversation with no selection whose context is the Files pane's active file at the cursor line (±40 lines, language, index entries; line 1 when the cursor is in another file) and `context_id` `<wb>:<path>:<line>`; with no file open the prompt names the folder only and the id is `<wb>::0` (chosen so every row parses the same way and the list can say "No file open"). Nothing is sent → the empty row is deleted. The panel (`OpenQuicklySession.answerConversationID`) swaps its results for `OpenQuicklyAnswerCard` ("✦ AI answer", `EmbeddedChatView` `.compact`, "↩ Follow up · click a link to open the file"); while it shows, the panel's key handler passes every key but Esc to the follow-up field, which takes the focus. A `path:line` link opens the file and closes the panel (`OpenQuicklyCenter.openAnswerLink`). The inspector's **Questions** tab (`QuestionsView`; while it shows, `CodeQuestionCenter.observeQuestionList` follows the list by a GRDB observation; the app writes every question but the CLI's workbench delete, after which `workbenchRemoved` clears the list; a new list clears a read error, never an action's) lists Core `CodeQuestionList.fetch` (the `<wb>:` prefix matched exactly, so workbench 1 never lists 10's; newest first by `created_at`; the first `user` message; the line after the last colon), opens a conversation as a compact chat with the model picker, and deletes it (`CodeQuestionList.delete`: the row, its messages by cascade and their FTS rows; then `EmbeddedChatCenter.drop(key)` stops that one engine quietly — `dropContext` would stop every question asked at the same `path:line`; an open popover or inspector on it closes). **Pin to inspector** moves the popover's conversation there (inspector shown on Questions) with its engine. A question reopened with no context in memory (after a restart) rebuilds it from the file around its line (R41; the selection itself is not stored, so a selection question comes back as its first line's surroundings; the file is read only through `WorkbenchFolderPath`, never through a symlink leaving the folder). **Deleting the workbench** deletes its code questions in the same transaction (`db.DeleteWorkbench`, PROJ-02; migration 00104 removed the ones earlier deletes left), the confirmation counts them, and `CodeQuestionCenter.workbenchRemoved` closes the popover, drops the engines and clears the tab's state. **Engine ownership:** `CodeQuestionCenter.engine(for: CodeQuestionRef)` is the one way the popover, the card and the tab get an engine; it sets `onTurnFinished` once per engine instance (a body pass asking again changes nothing; an engine made again after a release gets it again), and the handler marks Where-used usages as carried, and proposes a `wt-edit` only to the popover holding that conversation. The context every turn reads is the center's per-conversation copy. Where-used usages stay attached until a turn carrying them completes (a Retry of a failed resumed turn sends them again) and are rolled back when the Where-used question cannot be sent (a follow-up from the composer was running), so no unrelated turn carries them.
- **Hand to Claude Code (phase C, Task 13; spec §9.5).** ⌥⌘↩ (or the button) in the popover (`CodeQuestionCenter.handToClaude(workbenchID:)`: the popover closes first), on a Questions-tab conversation, or in Open Quickly (`onHandToClaude(query, project)`: the panel closes first; the origin is `CodeQuestionCenter.openFileOrigin`, the Files pane's active file at the cursor line) puts a `CodeHandoffRequest` on `CodeHandoffCenter` (`AppState`, per workbench); `WorkbenchPageView` shows `HandToClaudeSheet`. The text is Core `HandoffText`, built from the **stored** messages (`ChatMessageQueries.fetchByConversation`): the line "From a Watchtower code question:", "Asked at `path:line`" (a selection's `start-end`) or "Asked with no file open", each owner question with its `complete` reply (system notices, a `partial` reply still streaming and an `error` reply are left out), and when an answer cites anything, "References:" — the origin, then `CodeLineLinks`' own citations in order (fenced code and URLs are not citations). The selected code and file bodies are never added. The popover's and the tab's buttons are disabled while the engine is busy (a hand-off waits for the reply; the center refuses with a beep too). The sheet lists the workbench's live `claude` sessions in panel order with their state, plus **New session**; the default is `TerminalCenter.activeSession` (Send comments' target) unless it waits on a permission prompt, else New session. **Send** is the confirmation: a running session gets `TerminalCenter.submitPrompt` — `sendPrompt(_:sessionID:keepingLineBreaks: true)` (one bracketed paste; `WorkbenchCommentPrompt.terminalPayload(keepingLineBreaks:)` keeps LF and tabs, still drops ESC and every other control) and one `\r` only into a session waiting at its prompt (ruling R52): `submitIf` — the session's PROJ-11 state is `.waitingForOwner` and the sheet's request still stands — holds before the pause and again after `submitDelay` (150 ms), the state re-polled first (`refresh` → `SessionAgentStateCenter.poll`), and only into that same running process. A working or unreported session gets the paste without Return and the terminal pane shows `TerminalCenter.pasteHints` ("Pasted into Claude — press Return to send"); a Cancel during the pause stops the Return and opens nothing (Cancel is disabled while Send runs); a clipboard delivery (bracketed paste off) is never submitted. **Never over an answer not sent (board #380, owner decision in ask #34):** `submitPrompt` sends no Return when the prompt already holds text not submitted — an ask's answer left typed, the owner's draft, an earlier hand-off (`promptDrafts`), or a line still in its own pause (`pendingReturns`: an answer's 500 ms or another hand-off's 150 ms) — and a line sent while this one is in its pause stops its Return too; the hand-off is then only pasted and the session counts as `TerminalCenter.sharedPrompts` (cleared with `promptDrafts`: the owner's submitting Return, the process's start or close), so the pane reads "Pasted into Claude next to text not sent yet — press Return to send them together", or, when an answer's typed bar is showing (the answer went in after the hand-off, or crossed it), "Answer typed next to text not sent yet — press Return to send them together". The same PROJ-12 predicate guards an answer's Return, so a hand-off and an answer never submit each other. A session in `needsApproval` (PROJ-11's stored state) is shown disabled and refused at Send — a Return would answer the permission prompt; an ended one keeps the sheet with an error. A new session is `startNewSession(project:title:prompt:placement:)` with a provisional title. Both open with `Placement.beside(.files)` (a split keeps the editor and swaps the other pane, exactly as `keeping`; a single pane splits instead of switching away from the editor — the spec's "beside the editor in a split"). **First prompts travel in the environment:** `TerminalLaunch` puts every first prompt (the fixed work-on/first-run ones too) in `WATCHTOWER_FIRST_PROMPT` and the command is `exec /bin/sh -c 'exec env -u WATCHTOWER_FIRST_PROMPT claude --session-id <uuid> "$WATCHTOWER_FIRST_PROMPT"'` — the login shell (zsh, bash, fish, nushell, csh…) runs one single-quoted literal and `/bin/sh` reads the variable — so no prompt text is parsed by a shell and nothing Claude Code starts inherits it; `TerminalLaunch.positionalPrompt` gives a prompt starting with "-" a leading space (`claude --help` documents no `--`). `HandoffText` is capped at 32 KB: the earliest turns go first ("… earlier turns omitted"), a last turn still too long is cut ("… cut at 32 KB").
- **Terminal `path:line` links (Task 13).** `TerminalCenter.start` gives a workbench session's process its folder (`TerminalSessionProcess.setPathLinkHandler`, a no-op default for fakes; a standalone terminal keeps SwiftTerm's own handler); `PalettedTerminalView` overrides `requestOpenLink` (SwiftTerm's ⌘-hover/⌘-click implicit detection): Core `TerminalPathLinks.resolve` → `TerminalCenter.onPathLink` → `WorkbenchesViewModel.openTerminalLink` → `openFile(at:beside: true)`; a URL (`isURL`: `scheme://`, `mailto:` …; `http://host:80` is never a path) goes to SwiftTerm's handler only when `AllowedURLSchemes.permits` it (`PalettedTerminalView.linkAction`, also in standalone terminals: no `smb://`, `x-apple.systempreferences:` or bare path opens there either); a `file://` link is resolved like a path; any other path that does not resolve opens nothing (SwiftTerm's default would `NSWorkspace.open` any existing file on disk). SwiftTerm detects no path without a `/` or with a space, so a ⌘-click it left alone is looked up by `mouseUp` in the clicked line (`TerminalPathLinks.candidate(inLine:at:)`: the quoted span — `"a b.txt:1"` or `'a b.txt':1` — else the whitespace token) at the cell computed from SwiftTerm's own cell size; the line is the rows a soft wrap split joined back (`TerminalPathLinks.logicalLine`), read one character per cell (a wide character's spill cell kept for the column and dropped from the candidate), and a line holding right-to-left text, which may be drawn reordered, is no hit. `resolve`: quotes, leading brackets and trailing punctuation (`,.;:)]` …) dropped; `:line` required (≥ 1), `:col` optional; `~` expanded; relative to the folder. Containment is checked lexically first (ruling R53): the normalized path must lie under the folder or its realpath (read once per session), else it is refused with no `realpath`, `stat` or `fileExists` — a ⌘-click on `~/Desktop/…` never touches the disk; only an in-folder candidate is resolved, by `WorkbenchFolderPath` (a symlink whose target's text leaves the folder is refused before the target is looked at), and must be a regular file inside the folder (`TerminalPathLinks.FileSystem` = `WorkbenchFolderPath.FileSystem` is the test seam). Standalone terminals have no path links but go through the same URL allowlist.
- **Code questions — v1 limits.** Claude and codex read the folder with their own read-only tools; ollama answers from the first-turn context alone (the code around the question and up to 10 index entries), its prompt says so, and its conversation shows "This model cannot read other files" once. Accepted by the owner (2026-10-03, R55): the read tools can read outside the folder (Claude's touch any path the model names before a deny rule refuses it; codex's shell sandbox reads the whole disk), so a question can raise a macOS privacy prompt attributed to Watchtower, and a folder codex trusts applies its `.codex/config.toml`. Spike #341 is dismissed. Watchtower's own reads (an answer's link, a reopened question's file, a terminal path link) never follow a symlink out of the folder (board #361). A Claude follow-up resumes its Claude session; a Codex or Ollama turn makes the engine forget that session (and keep no id of its own), so the next Claude turn starts fresh with every stored turn replayed. The question travels on `ai query`'s argv, as in every other embedded chat (CHAT-04 covers the main chat only).
- **v1 limits (accepted).** The hand-off of unconsumed chords from the WKWebView to the SwiftUI menu, and the ⌃6 filter field's typing/arrow hand-off inside the `NSMenu`, are verified manually only (the harness proves Monaco binds none of them; unit tests cover menu → center → page). ⌃6 is swallowed in the workbench terminal (vim's Ctrl-^, R36). ⌥⌘↩ no longer runs Monaco's Replace All (R30; the widget's button stays). Unsaved buffers are indexed from disk. Open Quickly's host is keyed by workbench id only; one jump bar and one Files pane per workbench (R27). A `--serve` crash requeues without retry (the state shows it; the next show runs a full pass). Back/Forward to a deleted or renamed file goes nowhere useful. Phase C adds the code questions (⌘I, Ask AI, the Questions tab, the hand to Claude Code). Hand-off limits: SwiftTerm still underlines on ⌘-hover every path its regex finds (also one outside the folder, which then opens nothing), and underlines none of the quoted-with-space paths that ⌘-click still opens; a ⌘-click in a line with right-to-left text opens nothing. Open Quickly's ⌥⌘↩ hands the typed query, not an answer card already on screen (the card's keys go to its follow-up field). The submit pause (150 ms) between paste and Return is not checked against a live Claude Code; a slower TUI could see the Return before the paste is taken in.
