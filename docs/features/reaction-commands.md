# Reaction Commands + Inbox Action Strip (Wave 1 2026-09-05, Wave 2 2026-09-06)

- **Wave 1** (`internal/reactioncmd/`, migration 00063, feature `reaction-commands` — OFF by default until 2026-09-26, **ON by default since**, see the 2026-09-26 entry below): the owner drives Watchtower by reacting to Slack messages. Daemon phase `phaseReactionCommands` (throttle 6h until 2026-09-26; now every cycle) polls `reactions.list` under each connected owner token, records new dictionary-emoji reactions in the `reaction_commands` ledger (idempotent by `(account_id, channel_id, message_ts, emoji)`, transient failures retry; since 2026-09-26 the row is claimed as provisional `pending` BEFORE compose/Propose and finalized after, so a failed ledger write can strand a row — surfaced as `failed` "outcome unknown" after 1 h — but never double-fire, see REACT-03), composes each into a tool's args via one light-tier AI call, and dispatches through the agent-actions registry — External tools (`create_jira_issue`) stay pending proposals. `reaction_command_map(emoji, kind, tool, handler_id, enabled)` seeded `white_check_mark→create_target`, `ticket→create_jira_issue`.
- **Wave 2** (`docs/superpowers/specs/2026-09-06-reaction-commands-wave2-inbox-action-strip-design.md`, plan `docs/superpowers/plans/2026-09-06-reaction-commands-wave2-inbox-action-strip.md`) widens the vocabulary and turns the Inbox tab into the strip the archetype implies:
  - Four new registry tools, seeded into the dictionary by migration 00065: `create_track` (`:eyes:`, trust `ask`), `create_idea` (`:bulb:`, trust `execute`), `remind_me` (`:alarm_clock:`, trust `execute`), `brief_context` (`:pushpin:`, trust `execute`, writes its summary into the `agent_actions` row's `result_json`, no other side effect).
  - New `reminders` entity (migration 00065: `id, account_id, message_ref, note, remind_at, status CHECK(pending|done|dismissed)`) backing `remind_me`. No daemon phase and no `due` status — "due" is derived at read time (`status='pending' AND remind_at <= now`, `db.ListDueReminders`/`ReminderQueries.fetchDue`); Done/Snooze are direct GRDB writes (Swift-owned, the `inbox_learned_rules` dual-path precedent).
  - The **inbox action strip**: the Inbox sidebar tab now renders `ActionStripView`/`ActionStripViewModel` instead of the situations Dashboard (`InboxFeedView`, unreachable from navigation since Wave 2 and deleted in the demolition's Desktop half; its Learned/Profile sibling tabs moved onto `ActionStripView`'s own segmented control, and the sidebar badge counts the strip — pending/failed proposals + due reminders — not situations) — a flat, cross-source union of non-terminal `agent_actions` rows (`AgentActionQueries.fetchStrip`, any surface, reusing `AgentActionCardView`'s Approve/Reject/Retry) and due `reminders` (Done/Snooze), read-time only (STRIP-02), with every decision routed through the existing `Registry.Apply`/`AgentActionFeed` path (STRIP-03) and no card ever manufactured from passive activity (STRIP-01).
  - The situations pipeline was removed on 2026-09-14 (see Attention detection). Wave 2's `inbox.situations.enabled` gate — which only muted `runCompose`/`runSituationCards` while §10 of its design deferred the demolition — is gone with the stages it gated.
  - **Reaction cheat sheet (2026-09-25):** an empty Actions strip renders `ReactionCheatSheetView` (emoji → action → Approve-or-immediate → destination, rows from the live `ReactionDictionaryViewModel.cheatSheetRows`, disabled mappings omitted; feature off → an "Enable Reaction Commands" button via `FeatureManagerService.enableNow` — the same `features enable` CLI path minus the rest of the Settings batch; on → "last check" from the latest `done` `reaction-commands` `pipeline_runs` row), a non-empty one keeps it behind a `?` popover — static help, never a card (STRIP-01); tool ids get human names in one place, `ReactionToolCatalog` (WatchtowerCore), shared with `AgentActionCardView` and the Settings editor.
  - **Card links (2026-09-26):** an applied strip card gets an "Open" affordance for what it produced, and a reaction-sourced card or due reminder a "Slack message ↗" link — pure mapping in WatchtowerCore (`AgentActionDestination.swift`: `AgentAction.destination`, applied rows only, from the tool's `result_json` id/url; `SlackMessageRef` splits `<channel_id>@<ts>` on the last `@` into a `SlackDeepLink.archives` URL), navigation passed into the AppState-free `AgentActionCardView` as an `onOpen` closure by `ActionStripView` (chat surfaces pass none: only the Jira web link shows there); `AppState.navigateToIdea` calls `IdeasViewModel.reveal` directly (no pending field — the VM is AppState-owned), which clears the segment/filter/search that would hide the idea.
  - **Settings → Slack** (`SlackConnectionDetail`'s "Reaction commands" section) gained a reaction dictionary editor (`ReactionDictionaryViewModel`/`ReactionDictionaryQueries`): list/add/remove emoji→tool mappings, toggle `enabled`, and see each tool's trust (read from `tool_trust`, edited elsewhere — not duplicated here).
- New contracts **STRIP-01..03** (gesture-gated, view-not-store, decisions-through-registry) and **REMIND-01..02** (inert-until-due, read-only Slack); **REACT-01..05** (Wave 1, previously undocumented) backfilled alongside them — see `docs/inventory/reaction-commands.md`.
