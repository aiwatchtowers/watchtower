# Confluence knowledge connector (2026-09-26)

- Makes Confluence Cloud searchable next to Slack/Jira/mail through the same index (`internal/kb`, `search_knowledge`) via a source-agnostic raw store, `ext_*` (migration `00074`): `ext_sources` (one row per selected space; `provider` CHECK'd to `'confluence'` today, `jira_account_id` or a future `connection_id`, per-stream `page_cursor`/`comment_cursor`/`attachment_cursor` + `page_token`/`comment_token`/`attachment_token`, `backfill_done`, `last_reconcile_at`, `status` ok/error/needs_consent/revoked), `ext_documents` (pages/blogposts/attachments, PK `(source_id, ext_id)`, `sections_json`, `extract_status`/`extract_attempts`, `children_changed_at` for a comment-only change), `ext_comments` (PK `(source_id, ext_id)`, `idx_ext_comments_page` on `(source_id, page_ext_id)`), `ext_users` (provider-wide display-name cache, PK `(provider, ext_user_id)`). Migration `00075` adds `idx_jira_issues_synced`/`idx_jira_comments_synced` for the link scanner below. Attachment binaries are never stored — only extracted text (EXT-03).
- `internal/extsync` is the generic engine: it knows nothing about Confluence, driving a `Fetcher` interface (`Containers`/`Changed`/`All`/`Fetch`/`Comments`/`Download`/`Users`) per enabled source. Per stream (pages+blogposts, comments, attachments) it stores one token `<since-RFC3339-or-empty>|<provider pagination token>` (`stream.go`'s `encodeToken`/`decodeToken`) — a resumed pass replays the pass's own `since` rather than recomputing it from the advanced cursor, so nothing between old and new `since` is skipped. A cycle makes **at most two passes** per stream (a fresh pass that completes ends it; a resumed pass that completes is followed by one fresh pass from the advanced cursor) however many pages the 1-minute cursor overlap (`cursorOverlap`) holds; the budget (90s, `Options.Budget`) is checked only between batches, so a started batch always commits, and a cut mid-run rotates which source starts next cycle (`Engine.startAt`) so one source's backfill can't starve its siblings. The **version gate**: a ref whose remote `version` equals the stored one is never re-fetched (`localVersions`/`localCommentVersions`, store.go); a degraded outcome (transient failure or `ocr_pending`) keeps the last good text and stashes the tried version under `meta_json.pending_version` (`pending.go`) so the stream's overlap re-listing doesn't re-download it forever — only `revisitAttachments` (chunks of 20, its own budget check) retries a pending/failed/`ocr_unavailable` row, capped at `extract_attempts < 3`. One attachment's extraction step as a whole (PDF helper + OCR batches) is bounded by `extractDeadline` (8 min, sized for the 60s PDF parse + a cold OCR-helper signature check (2 × 20s codesign) + 5 OCR batches of 60s + each helper's 5s kill grace, with margin — the guard derives that sum from the extractor's constants; the download is bounded by its own HTTP client timeout, and the cycle budget only stops new launches) — past it the attachment is a transient failure (attempts+1), never a batch error. Reconcile (`All`, ids+versions only) runs once per UTC day per source (a failed one waits `reconcileRetryAfter`, 4h, before the next full enumeration — an in-memory backoff, so a restart or a manual `confluence sync` retries at once): a locally-stored id absent remotely is deleted — that's the whole permission model (a page the owner loses access to just stops appearing in `All`). The reverse direction is fetched back: a listed ref the store lacks, or holds at another version, goes through the stream paths without touching their state (`recoverListed`, `reconcile_recover.go` — pages with their comment sets, then attachments under the pending-version gate, then the comment sets of stored parents with a missing/changed listed comment), so an item that returns *unmodified* — a view restriction lifted, a restore from the trash, a move into the space — is back after the next daily reconcile instead of waiting for an edit; chunks of 20 under the cycle budget (the first always runs, so a reconcile whose enumeration spent the budget still progresses), and a cut recovery leaves `last_reconcile_at` unstamped so the next cycle resumes it. Comments are reconciled in the same pass (`All(KindComment)`, drained with every other enumeration before any delete): a deleted comment never bumps its page's version nor reappears in `Changed`, so only this removes it from `ext_comments`; each parent that lost one is stamped `children_changed_at` (the KB re-renders it) and relinked. Statuses: `ErrAuthRevoked` stops the whole account's sources for the cycle (`revoked`); a scope-denied 403 → `needs_consent`; other errors → `error`; unlike Jira, the engine **can** write `ok` back on a clean pass, since it owns the whole pass result. Cross-source links are wired in through an injected `Options.Relink` hook (`RelinkFunc`), never a direct import (EXT-04); the revoked/needs-consent hint texts likewise come from `Options.Hints` (wired to `cmd/confluence.go`'s `confluenceHints`; nil = a provider-neutral fallback).
- `internal/confluence` turns HTTP into `extsync` values and storage XHTML into sectioned text; it depends on nothing but the GET-only `confluence.API` seam (`GetJSON`/`Download`, EXT-01). Enumeration is REST v1 CQL search (`/wiki/rest/api/content/search`) — the only delta listing Confluence Cloud offers — with a **24-hour** `since` overlap (`cqlOverlap`) because CQL reads its date in the requesting user's own time zone, which the fetcher never learns; the engine's own 1-minute cursor overlap is separate and unaffected — the version gate makes both kinds of overlap re-listing free. Content reads (page/blogpost/attachment/comment bodies) are v2 (the v1 single-content and child-comment endpoints are gone from Atlassian's published spec); attachment download stays on the documented v1 path (`/wiki/rest/api/content/{parentId}/child/attachment/{id}/download`); ancestors come from a CQL search with `expand=ancestors` (v2 exposes only ancestor ids, under a scope this grant doesn't request). `All(page)` uses the v2 space page listing instead of CQL because CQL omits archived pages — so `All` ⊇ `Changed`'s coverage and a reconcile never deletes what the delta just wrote — but `Changed` (and therefore the whole delta stream) can never see an edit to an **already-archived** page, but the daily reconcile fetches any page whose listed version differs from the stored one (and any listed page never stored, archived ones included), so an edit to an already-archived page reaches search within a day rather than never (R10, narrowed 2026-10-01). The storage→text converter splits at h1–h3 into sections with Confluence's own heading-anchor slug (`chunk_anchor` deep-links), renders tables/lists/macros, resolves `ac:link`-to-user via `ext_users` (unresolved → `@user`), turns a Jira macro into its issue key (feeds `doc_links`), and caps a page body at 1,000,000 runes.
- `internal/extract` is a pure `bytes + mime → text` library (no DB, no network) plus one helper exec: plain/md/csv/json/xml/html read directly; docx/xlsx/pptx via `archive/zip` + `encoding/xml`; PDF text layers via `github.com/ledongthuc/pdf`, but parsed inside a **killable helper subprocess** (the hidden `watchtower extract-pdf-text`, `internal/extract/pdfhelper.go`) because the pure-Go parser can spin forever on a malformed page tree — the parent kills it at a timeout, the child self-exits 10s after its own deadline should its parent be the one that dies (SIGKILL leaves no orphan); a helper timeout/crash/non-zero exit is a **transient** extraction error carrying its capped stderr (the engine records `failed`, attempts++, retried under the cap of 3), while oversized or malformed helper output is a final `failed`; recovered parser panics, corrupt OOXML and failed OCR batches are logged through `extract.Extractor.Logger` (the extsync logger) before becoming their status, and a PDF page whose text layer fails to read goes to OCR instead of being indexed blank; zip formats are capped against zip bombs, and every OOXML part walk also caps XML nesting at 256 elements (`failed`) and a single token at 4 × `MaxTextRunes` bytes of input (~800 KB, room for a full-length run in any script) (`too_large`), reading raw tokens so open elements' `xmlns:*` declarations are not retained — `encoding/xml` limits none of it, and OOXML is parsed in the daemon process itself; scans/images/PDF pages with no text layer go through OCR via the `watchtower-ocr` Vision helper (SwiftPM executable, Vision+CoreGraphics+ImageIO only — PDF pages are rendered through CoreGraphics, not PDFKit — no ML stack) in batches of 10 pages (a full-document single call always timed out on real scans) with its own 60s timeout and the same self-deadline shape as the PDF helper; the helper's code signature (Developer-ID, our own Team ID) is verified before every exec, the codesign calls running under the caller's ctx (a shutdown cancels them and caches no verdict) — a signature mismatch or an unreadable own-signature fails closed (`ocr_verify.go`) — and it reads only a file Watchtower itself spooled under `Config.WorkspaceDir()/tmp/extract/` (0700/0600), removed on every return path including errors and parser panics, with a startup sweep for anything a crash left behind. Everything else → `skipped_type`, still findable by file name and parent-page title.
- `internal/doclinks` (+ `internal/doclinks/linkscan`) detects cross-source references, mechanical, no AI: Confluence text → Jira keys via the dependency-free `internal/jirakey.KeyRegexp` (re-exported as `jira.KeyRegexp`, so the linker never pulls the AI stack) into `doc_links(from_kind='confluence', ..., to_kind='jira_issue', to_ref=KEY)`; Slack/Gmail/IMAP/Jira text → Confluence page URLs into `doc_links(..., to_kind='confluence_page', to_ref='<cloud_id>:<page_id>')`. `linkscan` is split out from `internal/doclinks` specifically because it imports `internal/kb` (to render a Slack ref) and `internal/extsync` must never transitively depend on it (EXT-04) — the engine instead calls the injected `Options.Relink` (wired in `cmd/confluence.go` to `doclinks.LinkConfluenceDoc`) inside its own batch transaction, and a one-shot backfill relinks documents stored before the hook existed. `linkscan.ScanSources` walks each kind (`slack`/`gmail`/`imap`/`jira_issue`/`jira_comment`) from its own `ext_link_state` cursor (Slack by `messages.rowid`, the rest by a `'<synced_at>|<rowid>'` cursor over closed seconds) inside `phaseExternalSync`'s 20s-per-cycle budget (`docLinkScanBudget`); the one-shot relink backfill's own progress lives under the reserved `ext_link_state.from_kind = 'ext_relink'` row (cursor `'<source_id>|<ext_id>'`, then `'done'`).
- Auth reuses the Jira account's OAuth grant: Confluence's granular read scopes (`ConfluenceScopes`, `internal/jira/scopes.go`) are requested **only when opted in** — `watchtower jira login|add --account N --with-confluence` requests `OAuthScopes` (`JiraScopes + ConfluenceScopes`); the plain `jira add` keeps requesting Jira-only scopes, and so does a plain `jira login` of an account that doesn't use Confluence, so an existing Jira-only install sees no consent-screen change. A plain `jira login` (and so the Desktop's Re-login) of an account that **does** use Confluence — stored grant already passes `HasConfluenceScopes`, or the account has `ext_sources` rows — defaults to `OAuthScopes` (`jiraReloginOptions`, `cmd/jira.go`), because the new grant replaces the old one and recovering a revoked Jira must not silently strip Confluence; an unreadable/corrupt token file (a *missing* one is just "not granted") is warned about and the default is decided from the selected spaces alone, so it never blocks the re-login that replaces it; only a failed selected-spaces lookup fails the login. Confluence calls go through the account's existing `*jira.Client` (`Client.Confluence()`, `internal/jira/confluence_api.go`) so the mutex-guarded refresh (`c.mu`/`refreshIfCurrent`) is shared with Jira — two independent refreshers on the same rotating Atlassian refresh token would revoke each other. A grant missing the scopes leaves every `ext_sources` row of that account `needs_consent` with a hint naming `--with-confluence` (an unreadable token file is instead logged and recorded as `error` with the read error — `extsync.Options.ScopesOK` returns `(bool, error)` — never `needs_consent`, since re-consent would not fix it); the Jira account's own status is untouched by a Confluence-only problem. **Owner prerequisite (outside the code):** the Confluence API (with these scopes) must be enabled on the Atlassian OAuth app in developer.atlassian.com for **every flavor Watchtower ships** (main, corporate, partner) — without it, consent silently omits the scopes and every space stays `needs_consent`.
- Feature `knowledge-connectors` ("Confluence in search"), config `knowledge.connectors.enabled`, default **true** (`CostNone`, `FeedsInto` knowledge-search) — nothing runs until a space is selected. Off = `phaseExternalSync` returns early (FEAT-01), synced `ext_*` and the index stay readable (FEAT-02); no fast-forward hook, re-enabling just resumes from the stored cursors. Daemon phase `phaseExternalSync` (after `phaseJiraSync`) also runs `linkscan.ScanSources` and writes nothing at all — not even a `pipeline_runs` row — while no selected space is runnable (`Engine.HasRunnable`: enabled, and its Jira account has a fetcher — so a removed/disabled account's leftover spaces don't log an empty run every cycle).
- CLI `watchtower confluence spaces [--account N] [--json]` / `select <KEY>...` / `unselect <KEY>...` (deletes the row, cascades `ext_*`; purely local, so an explicit `--account` may name a **removed** account — the only way to drop a removed account's spaces, since the Desktop hides removed accounts; `jira remove`/`logout` print that exact command when the account still owns spaces) / `status [--json]` / `sync` (foreground pass, refuses while the daemon runs unless `--force`, the `kb reindex` rule; like the daemon's `Engine.Run` a failing space does not stop the next — every failure is reported once, in the returned error, and the command exits non-zero if any failed; Ctrl-C returns the cancellation joined with the failures so far). Desktop: Settings → Connections → Jira gains a **Confluence** section per enabled site (`ConfluenceSpacesSection`/`ConfluenceSpacesViewModel`, mounted by `JiraConnectionDetail`; the site name joins the header only when several sites are enabled) — space list with toggles, per-space status, a "Grant Confluence access" button when `needs_consent` (re-runs the Jira login flow with `--with-confluence`); selecting a space also asks the daemon to sync now (best-effort, same as the tray's Sync Now).
- `search_knowledge`'s `sources` enum gains `confluence`; every Confluence hit's `link` is the page/attachment URL, its `chunk_anchor` the heading anchor. `get_task_context` gains a capped "Confluence" section (`internal/tools/taskcontext_confluence.go`): pages found via `doc_links` first (`Via: "link"`), then `kb.Search` hits restricted to `confluence` (`Via: "search"`), deduped by ref, each with a snippet around the key.
- Contracts `docs/inventory/external-sources.md`: **EXT-01** read-only forever (GET-only client + fetcher, two-part guard since the client's base-URL seam is unexported); **EXT-02** selection is honest (unselect or a hard account delete leaves no `ext_*` row and, after one KB cycle, no index row; `jira remove` is **non-destructive** by the Slack/Jira precedent — a removed account's already-synced spaces keep their rows and stay searchable, since only *enabled* accounts get a fetcher, nothing new is ever fetched for them); **EXT-03** attachment bytes never persisted (temp files removed on every path — success, error, parser panic — plus a crash-residue sweep at the start of every engine run); **EXT-04** the engine imports no Atlassian/link/AI package, only interfaces + the injected `Options.Relink` hook (`go list -deps` guard).
- v1 limits (accepted, beyond the ones above): `linkscan`'s per-kind cursor only ever moves forward, so an in-place edit that adds or removes a Confluence URL in an already-scanned row (or a message edited after its rowid passed) is never rescanned — only a row's first sighting is scanned; comment listing is N+2 sequential requests per page (rate-limit risk on a comment-heavy space, no CQL container-listing shortcut yet); the OCR helper's memory is uncapped for its ≤60s run; a per-item metadata `Fetch` error still fails its whole batch (pages and attachments alike) rather than skipping just that item; attachments and comments of an already-archived page fall out of CQL `All` and get reconcile-deleted (a consequence of the archived-page limit above); labels are read from only the first page; `jira remove` followed by `jira add` for the same site mints a new account, so re-selecting the same space syncs every page a second time under a second source id (duplicate search hits) until the old account's spaces are unselected with the command `jira remove` prints — no cross-account dedup.
