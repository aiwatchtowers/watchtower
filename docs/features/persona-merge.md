# Persona Merge — one assistant (2026-08-19)

- The two-persona concept (secretary vs assistant, owner decision 2026-08-18) is **merged into a single assistant** (owner decision 2026-08-19). One word everywhere user-visible and model-facing; what used to be per-persona rights are now **per-surface capability contracts** and did not move: the meeting Discuss chat stays draft-only (intent-draft, no action machinery, Copy only), target chat keeps propose→Approve + execute directives. See "The assistant & chat contracts" in `docs/review/review-rules.md`.
- Skills (ex "persona skills", PR #133) are persona-agnostic: the `persona` frontmatter key is retired (parsed by neither side, ignored as an unknown key in legacy files, shed by a Settings-editor save), `SkillsCatalog.chatContextTypes` replaces the context_type→persona table (same five surfaces; onboarding still excluded), every enabled skill is listed on every chat surface, and `load_skill` no longer reports a persona.
- Reworded prompt defaults got version bumps (triage/compose/situation-card — all three since removed on 2026-09-14 — plus memory tier, ideas mining, briefing v7, day-plan v4, meeting-prep v5) so non-customized DB rows auto-upgrade. **Stable identifiers keep the old word by design:** `workspace.secretary_profile`, the `secretary-inbox` feature id, `SecretaryProfile*` type names, historical specs/changelogs.
