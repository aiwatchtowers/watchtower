# Connect with an agent — Claude or Codex sets up every connector (2026-11-21, #2133)

Spec: [`docs/superpowers/specs/2026-11-21-agent-connect-design.md`](../superpowers/specs/2026-11-21-agent-connect-design.md). Plan: [`docs/superpowers/plans/2026-11-21-agent-connect.md`](../superpowers/plans/2026-11-21-agent-connect.md). Guide: [`docs/guide/features/connect-with-an-agent.md`](../guide/features/connect-with-an-agent.md) and the playbooks in `docs/guide/connect/`.

A **Connect with <harness>** button beside today's connect controls opens the *connect assistant*: a chat panel that runs one connector's playbook on the customer's own Claude or Codex. The agent drives the Desktop's existing connect flows through a small set of connect tools; with Claude in Chrome it also does the vendor-console clicks. It is another path beside today's screens, not a replacement (ask #1702): **Set up by hand** always opens the manual screen.

## Who writes what

The agent writes nothing by itself. Every write is a Desktop flow the buttons already run (`slack connect serve`, `<svc> add|login --app-return`, `slack app create|adopt`, `company draft save|check|publish`, `quickconnections`), so locks, single-flow rules, policy and purge checks are unchanged; the first start wins and a second gets `busy` (the panel's busy state with **Open it**). Secrets go from the panel's card straight to the verb's stdin or the wizard's in-memory draft, never through the model, a transcript or a log; every driver's secret result and failure line passes `ConnectSecret` (`scrub`, or `failure`, which replaces a line holding any piece of the value), the Slack and company drivers included.

Confirm cards (only the customer can press them): Slack PKCE adopt, a company Slack app update (the diff lines), a bring-your-own Google client (the card shows its Client ID), a Quick Connection's `enable` (the card shows the command line or URL it turns on), company **Publish** (the card lists the services it publishes), **Replace** of a stored company. A secret card names where the value goes when that place comes from the agent's fields (the mail server and login, the CalDAV URL, the Quick Connection header or variable). Every other step is covered by the panel's **Start** — for Slack that is the owner's press of SLACKFULL-01 (owner Q1, ask #1721).

MDM: a source blocked by `AllowedSources` (`PolicySourceMap`), a provider outside `AllowedAIProviders`, no allowed Quick Connection, or own Google project not allowed → no agent button; `connect_start` refuses the same source again on the Desktop. `SlackApps` never blocks an assistant connect; with no option the driver uses the org's first open row.

## Panel states

`empty` (intro + **Start**, **Guide me in words** in browser mode, **Set up by hand**; mode line "Using <harness> in Chrome" / "I'll tell you each step"), `browserMissing` (#1144: the intro says the browser isn't connected; the browser guide — install the extension from claude.ai/chrome, sign in with the harness's claude.ai account, restart Chrome — with **Check again**, **Continue without the browser**, **Set up by hand**; while a check runs only **Cancel**), `thinking`, `waiting` ("Waiting for you to …" + **Cancel**), `listening` (the agent's turn ended and it waits on the composer: no status line, **Cancel**), `failed` (agent, quota, harness missing, timed out; **Retry** + **Set up by hand**), `busy` (**Open it**), secret card (**Send**, **Don't send**, a close-the-page-first line per vendor), confirm card ("Only you can press this — <harness> can't."), `done` ("Slack is connected — 2 workspaces"). Once the browser is lost mid-run, `thinking`, `listening` and `waiting` also show the guide (with a "isn't connected any more" lead) and add **Check again** after **Cancel**; a card or a failure hides it. The mode line's help text names the S2 and secret-page limits. Shots: `connect-assistant-browser-missing`, `connect-assistant-browser-lost`.

Entry points include the company setup wizard's header (#1149): **Set up with <harness>** on every step (`CompanySetupActions.agent`, built by `AppState.companySetupAgent` from `connectAssistantButton(for: "company")`, so hidden when no harness is offered or the policy leaves none), opening the company assistant whose `CompanyConnectDriver` works on the wizard's own draft.

## Lifecycle

- **Close / quit:** `endRun` stops the controller, the socket and the engine. A running Desktop flow keeps today's behaviour: the Slack sign-in is handed to its own sheet (Connections → Slack, or the onboarding step's sheet); OAuth loopbacks time out. Reopening reads `connect_status` and the playbook resumes from it; `connect_wait`/`connect_cancel` adopt the driver's running flow.
- **Retry** starts a fresh controller, socket and engine. **Switch the assistant** ends the run and returns to the empty state on the other harness.
- **Onboarding:** drivers read `accountDaemonPolicy`, so a connect during onboarding defers the daemon restart like the sheets do.
- **Harness readiness:** `ai which` per connect-capable provider, refreshed on the Connections tab and the onboarding Connect step.

## v1 limits and follow-ups

- **Readiness = the CLI is found**, not signed in: no cached signed-in result exists and `ai test` costs a model request. A not-signed-in CLI fails the first turn into the error state with **Retry** / **Set up by hand**.
- **No agent Reconnect.** The attention banner keeps today's **Reconnect** only; no driver can re-sign an existing account (a plain connect adds a new one, and a Google custom client or scopes would be lost). Follow-up: a reconnect intent per driver, then the banner button returns.
- **Codex is words only.** S3 failed: `codex exec` gets no Chrome from the CLI (the bundled `chrome@openai-bundled` plugin is installed only by the Codex desktop app). Plan Task 7 (Codex browser) was dropped; re-check when the CLI ships the bundled marketplace.
- **The Claude browser probe has no time bound.** A stalled CLI leaves the panel preparing until **Cancel**. Follow-up: a probe watchdog on an injectable clock. The non-empty `list_connected_browsers` shape is still unverified (the live matrix observes it).
- **A `connect_wait` that runs out its step budget** (15 min / 20 calls) cancels the driver flow, so **Retry** finds a free slot. Closing the panel or quitting does not cancel the flow (§8). Own Google project has no cancel: after a timeout, Retry is `busy` until `google add` ends on its own.
- **Slack connect flow has no attempt counter.** A paste/link attempt that ends and is replaced within one watcher hop can be attributed to the wrong attempt.
- **No structured "harness missing" code.** `ConnectAssistantSession` matches the error text (`executable file not found`, `command not found`, …) to show "<harness> isn't installed on this Mac".
- **Narrow onboarding.** At the 800 pt minimum window the 380 pt panel leaves the step's rows cramped (the two buttons get tight).
- **Not enforceable in the browser:** a link click, form post or redirect to another host (only `navigate` is hooked; the prompt says leave and stop), and an agent that reads a secret page while the customer has it open. Both are named in the panel's help text.
- **Company draft read:** the company name, `services` (what the customer ticked, wizard order; empty until they confirm the Services step — continue past it, resume a draft beyond it, or the agent saves a list — since discovery pre-ticks found vendors; `vendors` holds exactly `services`, and before that confirm only the ticked vendors that already hold values), and per vendor its ids, site, `client_secret_set`, `checked`/`skipped`; Slack adds `ready` and `app` (`new` after **Create new**, `existing` after **We already have one** or a picked app; absent before a choice). The playbooks take these as answered and ask only for what is missing (#1146). `app` comes from the wizard's in-memory step state, not the draft file: after a relaunch, until the customer opens the Slack step again, the agent asks. Not in the read: whether a settings link was already saved (an `existing` app has its link read again), and the deny list. `connect_status.setup.stage` carries the wizard's page.
- **Reply language** is `digest.language` read by `ai query` from config; a customer who writes in another language gets replies in theirs. Vendor consoles shown in another language still get the playbook's English names in **bold**.
