# Watchman — the owner's twin, phase 1: learn and backtest (2026-11-16, board #1823)

Spec: `docs/superpowers/specs/2026-11-16-watchman-design.md` (approved, ask #1385). Plan: `docs/superpowers/plans/2026-11-16-watchman-phase-1.md`. Phase 1 is spec §12 item 1 with §8, §9, §11 and §11a: Watchman learns how the owner decides on a workbench and measures, on his own past decisions, how often a twin would have chosen the same. **It never acts**: no ask is answered, no permission decided, no review written, no session typed into (WATCHMAN-06). Phase 2 (acting at night, the journal, corrections) is planned only when the backtest says go.

## What it is

A leaf package `internal/watchman` reads the owner's own decisions in a workbench into a precedent index, builds per-category rule profiles and a learned sleep window, and runs a backtest: the newest decisions of each category are hidden, the twin decides them from what came before, and the answers are compared with what the owner really chose. Everything is per workbench and off until the owner presses **Start Learning** (Desktop) or runs `watchman learn --start`.

Fixed categories: `design`, `scope`, `ux_text`, `tests`, `review_code`, `review_doc`, `permission`, `finish`.

## Tables (migrations 00194, 00195)

- `watchman_workbenches` — one row per workbench Watchman is on for: `enabled_at`, `estimated_decisions` (taken at start, the progress denominator), `unlabelled` (decisions seen but not placed), `learned_through` (set when every source reports done on its backfill).
- `watchman_precedents` — one decision: `source` (`ask`/`review`/`spec`/`permission`/`turn`/`git`), `source_key` (UNIQUE with `workbench_id` and `source`: a commit hash or PR number repeats across repositories; an upsert never moves a row to another workbench), `category`, `situation`, `choice`, `owner_words`, `decided_at`, `weight`; `watchman_fts` (FTS5, porter) over situation/choice/words, kept by triggers.
- `watchman_cursors` — per workbench and source the opaque cursor `hi|lo` (each mark `decided_at,id[,sub]`): new rows past `hi` first, then the backfill older than `lo`, newest first.
- `watchman_profile` — per workbench a text per category plus the key `sleep_window`; `pinned`, `version`.
- `watchman_backtests` / `watchman_backtest_rows` — a run (`running`/`done`/`failed`, `verdict` `''`/`go`/`stop`, `cost_usd`, `progress`) and its per-category rows (`total`, `agree`, `wrong_high`, `cost_usd`, `baseline`, `status` `strong`/`weak`/`not_measured`).
- `watchman_skipped_keys` (00195) — decisions a source offered that got no category, keyed by `(workbench_id, source, source_key)` (cascading with the workbench), so a lookback does not offer them again.

Situation and owner words are redacted (`Redact`: known secret shapes, bearer tokens, token-looking words become `[secret]`) and clipped to 2048 runes (`SituationLimit`, `Clip`) before storage. "2 KB" means 2048 runes: a size bound, not a wire limit.

## Sources (closed list, WATCHMAN-03)

`DBSources()` + `TurnSource` + `GitSource`, all workbench-only (no Slack, mail, calendar or meetings):

| Source | Reads | Category |
|---|---|---|
| `ask` | answered owner asks; a review ask is a `review_doc` decision (verdict, comments as words); a question or check ask is left for the labeller; dismissed, open, withdrawn and automation-made asks are left out | labelled / `review_doc` |
| `review` | comments of a sent diff-review round, each round's outcome, an undone hunk (weight 2), a decided review lesson | `review_code` |
| `spec` | the owner's marks on spec review findings (ok, comment, not useful) | `review_doc` |
| `permission` | prompts the owner allowed or denied (pending, expired and answered-on-Mac are left out) | `permission` |
| `turn` | the owner's own lines in the workbench's agent sessions, with the agent text just before as the situation; sessions an automation started are left out; needs Agent analytics on the workbench | labelled |
| `git` | the owner's commits (authored by the folder's `user.email`, any author when none is set, and no agent trailer; the sleep window uses the same rule) that rewrite paths an agent commit changed in the 7 days before (`rewrote`), and the workbench's merged PRs (`merged`) | `tests` / `finish` |

A row a source cannot read (corrupt JSON, no `decided_at`) is skipped, logged by id and counted (`SkipCounter`); the cursor moves past it. The `git` and `turn` cursors set their `lo` mark to `end` once the backfill has drained, so a done source reads only what is new.

## Learning

`watchman.Learn` walks each source from its cursor in batches of 50. Precedents with no category go to the labeller (`NewLLMLabeler`, prompt `watchman.label`, light tier, up to 20 per call, a JSON array Go validates; a decision with no valid category is counted as `unlabelled`, its key marked skipped, nothing stored). One transaction writes a batch, its skipped keys, the unlabelled counter and the new cursor, so an interrupted pass resumes without duplicates. A budget is checked before each `Next` (a pass can overrun by one batch). `Estimate` (no model call) gives `decisions`, `need_labels` and `tokens` (~350 per labelled item, 12 owner turns assumed per session) for the owner to see before he starts.

## Profiles and the sleep window

Weekly per workbench (`phaseWatchmanProfile`): for each category with at least 5 precedents, one strong-tier call (`watchman.profile`) over the newest 60 returns at most 20 rule lines of at most 300 runes (`BuildProfiles`); a pinned entry is never replaced. The sleep window (`SleepWindow`, `UpdateSleepWindow`, key `sleep_window`, text `HH:MM-HH:MM`) is the median start and end of the longest gap between the owner's actions in each night (20:00 to 12:00 local) of the last 28 days, from his agent-log activity and own commits; fewer than 7 days with activity give no window. Wall-clock times, so DST neither shifts nor stretches a gap.

## Decide core (dry run)

`watchman.Decide(ctx, d, gen, store, Item)` retrieves up to 8 precedents decided strictly before `DecidedBefore` and not in `Exclude` (FTS), asks the strong tier (`watchman.decide`) and validates: the choice must be one of the options when there are options (`ErrChoiceNotOffered`), `precedent_ids` only ids that were retrieved, `confidence` low/medium/high, `importance` low/high. The item and the precedents go to the model as one JSON object between `<data>` and `</data>` (`json.Marshal` escapes `<` and `>`, so no text closes the fence). `Decide` never writes and never reads `watchman_profile`; the caller passes the profile and the owner's instructions (`LiveContext` for a live item).

## Backtest

`watchman.Backtest` (Task 8): per category the newest `HiddenPerCategory` = 30 precedents are hidden; the profile is rebuilt for the run from the 60 precedents before the category's oldest hidden decision and only `owner_instructions` older than that cutoff are passed (a stored or pinned profile is never used: it may postdate the decisions); each hidden item is decided with `DecidedBefore` = its own time and the hidden ids excluded. Only decisions whose situation does not give the answer away are hidden: a review round's outcome, an undone hunk and the git items (rewrites and merges) are **not measured** in phase 1 (they stay retrievable as precedents), so `review_code` is measured on the owner's review comments only. Scoring is **no worse than the owner** (asks #1422, #1423; migration 00196): the strong-tier judge (`watchman.judge` v3, `Judge.Grade(JudgeInput{Situation, Owner, Twin, Questions})`) grades each twin decision `same`, `acceptable` (a different but reasonable path) or `bad` (the owner would have had to undo it). A fixed-option item (asks with one single-choice question, review ask verdicts, permission allow/deny, review lessons) whose choice matches exactly is `same` with no judge call; a different option, a free answer and an ask answered with "Other" go to the judge (an empty choice leaves its `Choice:` line out; the twin's side carries its confidence). An ask with several questions is graded per question, each one scored decision (`total` grows by the number of questions); a grade the judge leaves out is `bad` but never counts toward `wrong_high`, an extra one is ignored; a reply with no grades at all is unreadable (retried once, then the run fails). An unusable twin reply (`ErrBadReply`) is `bad` with no judge call. Row columns: `agree` (= same), `acceptable`, `bad`, `wrong_high` (**bad while the twin's confidence was high**; the column kept its name), the base rate `baseline` (the share of the hidden decisions that always giving the owner's most common choice would get right; option-scored items only) and `rec_baseline` (the share of the scored decisions where the owner picked an option the agent marked recommended; per question; a decision with no recommended option is a miss) — both informational. A category row is `strong` when `bad/total <= 5 %` and `wrong_high = 0` (agreement does not gate), `weak` otherwise, and `not_measured` with fewer than 30 hidden precedents (no model call). Verdict `go` = at least 3 strong categories including `permission`, `design` or `scope`, else `stop`. `Backtest` takes `<workspace>/watchman.lock` itself (`ErrBusy` when held), closes a leftover `running` row as `interrupted` after taking the lock, writes progress after each item (`"<category>, <i> of <n> · <k> of 8 categories done"`) and on any error marks the run `failed` keeping the partial rows. Only a learned workbench (`learned_through` set) is backtested: half-learned history would measure the wrong thing.

## Daemon and CLI

- `phaseWatchmanLearn` — every cycle, for each workbench Watchman is on for; DB sources, the turn source where Agent analytics is on (turned off later, that source stays empty) and the folder's git history; one shared 5-minute budget per cycle, cursors carry the rest. Logs carry ids and counts, never text; a shutdown mid-pass stops cleanly.
- `phaseWatchmanBacktest` — weekly, never in-process (about 240 strong-tier calls): for at most one due workbench per cycle it launches a detached child `watchtower watchman backtest --workbench N` (`cmd.LaunchWatchmanBacktest`, own session, no agent markers, output in `watchman-backtest.log`) and does not wait. A workbench is due when it is learned, its success stamp `last_watchman_backtest_<id>.txt` (written by any finished run, manual included) is a week old or missing, and its launch stamp `last_watchman_backtest_launched_<id>.txt` is older than 24 h (a failed or still-running child is retried a day later). Nothing launches while the lock is held.
- `phaseWatchmanProfile` — weekly: stamp files `last_watchman_profile.txt` (success) and `last_watchman_profile_failed.txt` (retry a day later), read each cycle, no catch-up, a cancelled cycle writes neither.
- `watchtower watchman learn --workbench N [--start] [--json]` — without `--start` the estimate (`ok`, `workbench`, `decisions`, `need_labels`, `tokens`); with `--start` (owner verb, refused under an agent) turns Watchman and Agent analytics on for the workbench, runs one pass of up to 5 minutes (`ok`, `workbench`, `written`, `by_source`, `incomplete`, `unlabelled`, `analytics_turned_on`; on failure `ok`, `workbench`, `error`, `watchman_on`, `analytics_on`, `analytics_turned_on`) and leaves the rest to the daemon.
- `watchtower watchman profile --workbench N [--json]` — `ok`, `workbench`, `profiles` (`key`, `text`, `pinned`, `version`, `updated_at`), `sleep_window`; `profile set --key K --text-file F` pins an entry, `profile unpin --key K` lets the weekly rebuild replace it.
- `watchtower watchman backtest --workbench N [--force] [--json]` (Task 8; owner verb, refused under an agent; refused until the workbench is learned unless `--force`; busy gives `{"ok":false,"error":"busy"}`) — `ok`, `workbench`, `backtest_id`, `status`, `verdict`, `cost_usd`, `categories` (`category`, `total`, `agree`, `acceptable`, `bad`, `wrong_high`, `cost_usd`, `baseline`, `rec_baseline`, `status`). The text output prints each category as `same / acceptable / bad (bad while sure) · recommended-pick %`, then the verdict and the estimated cost.
- `watchtower watchman status [--workbench N] [--json]` (Task 9) — every workbench with its estimate (null when counting the folder's commits ran past 3 s) or learning progress (`written`, `estimated`, `done`), precedent counts, per-source state, sleep window, the last backtest and the last finished one (categories with `acceptable`, `bad`, `baseline`, `rec_baseline`), and `running` (the lock is held); a `running` row with no lock is shown `interrupted`. Pinned keys are in the plan's Task 9 and `TestWatchmanStatus_JSONKeysPinned`.

Prompts (all on both providers, `digest.WithSource(ctx, "<id>")`): `watchman.label` (light), `watchman.profile` (strong), `watchman.decide` (strong), `watchman.judge` (strong since v3, ask #1423).

## Phase 1b: measure decisions only (spec §§9.1, 9a, 11b; migration 00197)

Phase 1 hid every candidate and graded each; phase 1b makes the measurement fairer. Prompts: `watchman.label` v2 (light), `watchman.decide` v3 (strong), `watchman.judge` v5 (strong; a handoff's option label is not a claim).

- **Decisions only (D34).** A precedent is a backtest candidate only when it is a decision and Watchman would not park it. Owner turns that answer no agent question or proposal, and parked items, stay precedents (retrievable) and are never hidden. `watchman.label` v2 returns `decision` and `parked` per item; asks whose category Go sets still go through it for the flags (the category it returns for them is ignored). A row whose flags are unset (NULL) counts as a candidate.
- **Relabel pass (D39).** Earlier ask, turn and permission precedents are flagged once, after the sources in the learning cycle, in the 5-minute budget with cursors carrying the rest (`Stats.Relabelled`, status `relabel_pending`). It sets only `is_decision`/`parked`; a stored category never changes. The CLI `watchman backtest` refuses while `relabel_pending > 0` (`--force` overrides, like the learned check) and the daemon's weekly launch waits. Settings shows "Sorting earlier decisions: N left" and disables **Run Backtest Now**.
- **Permission rows by Go (D38, `hardlimit.go`).** `ParkedBy(PermissionAsk)` is the spec §5 hard-limit table (one test per row; phase 2 reuses it for acting): main-ref push/merge/rebase, tag, release, TestFlight, force-push, `reset --hard` on a remote ref, delete outside the worktrees, outward message, standing grant, a file edit outside the folder. Bash commands are judged only by the delete row for paths; file tools only by the outside-folder row. A `git push` with no refspec is not parked (the live pre-push hook covers it). The PR base of `gh pr merge` cannot be read from stored data, so every `gh pr merge` is parked (D42). The standing-grant row is a file write (Write, Edit, MultiEdit, NotebookEdit) to `.claude/settings*.json` or `.codex/config.toml`; a read is not one. A relative path is cleaned first and is outside when it climbs out (`subdir/../..`). A request whose stored summary was clipped (`summary_clipped`) is parked: its hidden tail may be what parks it. A row with an unknown worktree or folder is parked. Permission rows of a session being deleted are not learned (PROJ-17).
- **Handoff (D35, D40).** `watchman.decide` v3 returns `handoff` = `none` or `owner_only`: the twin hands back only what needs the owner's hands (a token, a sign-in, a command on his side). Every `owner_only` item goes to the judge, even when its choice matches, which answers `justified` or `unjustified`. Justified: the item is **handed**, its questions are left out of the scored total. Unjustified: one scored decision graded `bad` for the whole item, never bad while sure. The twin never claims an owner-only action as done and adds no unasked work on a status report (D37).
- **Handed count.** `handed` counts handed items (at most 30 per category), a column on the category row, `watchman backtest --json` and `watchman status --json` (Swift decodes it tolerantly, missing = 0). The owner's base rate still covers all his decisions, handed included.
- **Scored floor (D41).** A category needs at least `MinScored` = 20 scored decisions of its 30 hidden to be measured; fewer is `not_measured` with the handed count kept (Settings: `Not measured: <n> of 30 handed to you`), so a category is never measured on only a few decisions. Only justified handoffs leave the scored decisions, and the `handed` count shows how many. Strong, weak and the verdict rule are unchanged (D32).
- **Judge rubric (D36, v4).** A recommended or reasonable other path is `acceptable` unless irreversible and contradicting the situation; versions, cheap reversible CI actions and work order are never `bad` alone.
- **Run report.** Each run writes `<workspace>/watchman/backtest-<id>-<start unix>.jsonl`: one line per hidden item (a justified handoff still gets one), with the judge's grades and reasons as arrays, each reason clipped (`reportReasonMax` = 200 runes), redacted; no situation or answer fields. `--json` carries `report_path` and `report_error`; a report failure never fails the run.
- Phase-1 and phase-1b numbers are compared per category, not item by item: the hidden sets change.

## The twin worker (phase 2, Task 9)

`watchmanact.Twin`, driven by the daemon (`startWatchmanTwin`): a pass at start, on every Watchman wake and on each cycle's nudge — `ScanWatchmanWaitPoints`, the twin's held lines, the owed handover starts, then leases (`LeaseArmedWatchmanItem`: the lease re-checks the arming) of `ask`/`check`/`handover` items while fewer than 2 decide (10-minute lease, parked after 3 attempts, a provider refusal retried once after 15 min). Each pass binds the current routing. The twin's calls run **outside the cycle's AI worker pool** (`watchmanTwinGenerator`: at most 2 strong-tier decisions plus their light-tier label checks at once), so a busy cycle never times out a label check (which parks). Hard limits: `watchman.AskParkedBy` on the title, the summary and the questions before the model, on them plus the choice after (Markdown marks stripped); the label call may only add a park. Outcomes: `answered`, `handed`, `parked`, `owner_first`, `superseded` (the ask was withdrawn after the decision; before one the item is deleted). A "Continue in a new session" handover keeps the error `next session not started yet` until its start succeeds: a start claims it (`next session starting`, counted), a failure makes it owed again, up to 3 tries (then `starting the next session: <err>`), only while the session's arming row (kept by `PruneWatchmanArming` while its handover is queued, deciding or owes a start) or a target covering its destination (the item's target) is still armed — the lease may also use the source session's target, the start never — checked again in the claim's own statement (else `Next session not started: Watchman was taken back`; a deleted or missing session's row is pruned whatever its handover); a handover of a finished session is leased by that row; a claim found after a restart becomes `next session may have started — check the workbench` and is never retried. Hard-limit texts: the Go table reads the title, summary and questions before the model (not the options nor the changes), plus the choice after; the label call reads that text before and the whole situation with the choice after. A superseded item shows `The ask was withdrawn before the answer` (its own symbol) and takes no OK/Correct. A handover whose start failed for good (any other error) waits for the owner with its error as the reason, until Mark done.

Residual risks (accepted): a twin finish that commits before `markWatchmanHandover` runs answers the handover ask as an ordinary question; a session start that times out after the session host took it may start a second session. Its own `askanswer.Answerer` keeps held lines in `<workspace>/watchman_held_asks.json`.

## Twin reviews (phase 2, Task 12)

The twin worker also leases `review_doc` items (a spec or plan review ask) and `review_code` items (a session's diff, queued by `finish_session`; keyed `('session', S)` before any sent round, then `('round', last sent)`). `watchman.decide` **v4**: a `review_doc` item carries the spec review's findings (`key`, `text`, `specreview.MarkableFindings`) and the reply gains `marks` (`key`, `state` ok/comment/not_useful, `body`), read only for `review_doc`; unknown keys and states are dropped in Go.

- **review_doc** waits (queued, `not_before` = now + 1 min, its attempt given back, `DeferWatchmanItem`) while the review is `queued`/`running` or its author loop is open; then decides `approve`/`changes` and answers the verdict with the marks built by `specreview.AnswerMarks` in the answer's own transaction (outcome `approved` or `changes`). An answer that loses to a reopened author loop is released, not owner-first.
- **review_code** reads the session's review place (`LiveReviewPlace`: `tools.SnapshotReviewSession`, the snapshot the finish gate reads, so both agree on the tree and an empty diff; the diff from its base; the reviewer's cached overview), reuses an open round with no comments (a round the twin opened before a restart, or the owner's untouched one) or creates one, and decides over the summary, the overview and the diff stat. `changes` → one design comment (no path) with the rationale, sent with the round and the item's finish in one transaction, its `review send` line delivered (`Answerer.DeliverLine`). `approve` → `review approve`'s line, only for a PR (`gh pr view <branch> --json baseRefName`) whose base is known and not the default branch, else `Parked for the owner: merging to main is yours` (base = default branch) or `the PR base could not be read — the owner decides the merge target` (no PR, gh failed). After the decision (and the PR base) the place is read again before any send, Approve or park: a tree, place or branch that moved puts the item back for a minute (no attempt spent) to be reviewed on the new tree, and the send/approve transaction re-reads the round and does the same when it was repointed meanwhile.
- **Go parks before any Approve** (WATCHMAN-01, D46): `ProtectedChange(paths, diff)` — a path under `docs/inventory/` or a hunk (header, added, removed or context line) declaring `func Test<Module>NN_…`/`func test<Module>NN_…`; any edit of a changed test file (`*_test.go`, `*Tests.swift`, `Tests/**/*.swift`) that declares a guard test at the round's tree or base (one that cannot be read parks too); a truncated diff, a binary file (`-diff` included) or a file whose changes are not shown → `the diff is too large to check for protected changes — the owner reviews it`; `ProtectedDoc(<folder>/docs/inventory, snapshot)` on the whole document — a `docs/inventory` path or a `Test[A-Z][A-Za-z]*[0-9]{2}_` name anywhere, or any line naming a contract id (prefixes from the inventory's `## <ID> —` headings, `PROJ-12/21` = two ids) or a family wildcard (`REVIEW-0x`) (ids in any case) unless it names exactly one id and is a single clause (no `;` `.` `:` `,` `—` `–` `(` `but` `and` `except` `other than` but a closing mark) carrying a no-change marker (`unchanged`, `not changed`, `no change`, `does not change`, `untouched`, `stays as is`); an unreadable inventory, or one with files and no ids, parks (`inventory unreadable`). Either → `Parked for the owner: approving a change to a behavior contract or a guard test is yours`; `changes` is still sent.
- Ends: a review whose ref is no longer the session's last sent round (the owner sent one since) or whose round the owner sent or approved first → `owner_first` (his round is then the last, so the finish gate keys a new review); an open round holding the owner's comments → parked; the owner commenting while the twin decides → the item waits; no changes → the item is dropped; after 3 twin rounds asking for changes since its last Approve → parked (the finish gate passes a parked review). The twin never leaves a done, unparked review on the gate's current key, so the gate's "ended without an approval" refusal is not reached from the twin.
- Writers: `review_rounds`/`review_comments` — the owner (Desktop, `workbench review send|approve`) and the twin (`SendReviewRoundTx`/`ApproveReviewRoundTx` + the item's finish, one transaction); the round's open-state guard decides. `spec_review_marks` — the Desktop for an answer at the Mac, the twin only inside its winning answer transaction.

## The morning journal (phase 2, Task 16)

The Inbox root lists one more built-in entry, **Watchman** (`InboxFolderEntry.watchman`, id `watchman`), while a workbench was ever turned on or any `watchman_items` row exists (`WatchmanJournalQueries.inboxSummary`, read in `InboxFeedQueries.read`); its summary is `<n> waiting` (parked and handed items without feedback, every night) and its detail the newest night's counts. Its reading pane is `WatchmanJournalView` over the app-wide `WatchmanJournalViewModel` (`AppState.watchmanJournal`): the nights on the left (one column with menus below `WatchmanJournalContent.splitWidth`), a workbench scope menu, and the night. Empty state: `EmptyStateCopyTable` key `inboxWatchman` (C1).

- A night runs 12:00 to 12:00 local, built from calendar components so a DST day keeps noon (`WatchmanNight.start(of:)`, `end(of:)` = the next night's start); an item belongs to the night it was created in, a `watchman_gaps` span to every night it overlaps (`the Mac slept from <HH:MM> to <HH:MM>, nothing ran`). `WatchmanJournalQueries.nights(db, limit:)` reads the newest 30.
- Sections: **WAITING FOR YOU** (`parked`/`handed`, `feedback = ''`), **Decided** (every other finished item but checks and `owner_first` ones, which are lines `the owner answered first` under it and never counted; an `unsure` item as a full card with the Unsure badge, a sure one as a line; phase 2 journals all unsure, D43), **Checks nobody ran** (`kind = 'check'` without `check_done_at`). Outcome line: `the owner answered first` (`owner_first`), `session ended` (`delivery = 'no_session'`), else the decision's outcome.
- The busy line `Deciding: <question>` shows on tonight while an item is queued or deciding (`liveDeciding`); `Watchman is not running — the daemon is stopped` shows above the journal when `watchman status --json` says `daemon_running: false` (`WatchmanCenter.daemon`, a `WatchmanDaemonState` decoded tolerantly; reread when the journal opens; unknown = no line). The busy line shows whatever night is open. While the journal is on screen it rereads on a GRDB observation and every 30 s (the daemon writes from another process).
- Home: `Overnight Watchman decided <n> — <u> unsure, <w> waiting for you` above the Workbench zone (`WatchmanJournalQueries.homeNight`: the newer of tonight and last night that decided or parked anything); a click opens the journal (`HomeLink.watchmanJournal` → `InboxRoute.Entry.watchman`).

## Morning feedback (phase 2, Task 17)

- `WatchmanFeedbackQueries` is the only writer of `watchman_items.feedback`, `feedback_text`, `feedback_at`, `check_done_at`, and (migration 00202) `owner_done_at` and `correction_sent_at` (Go never writes them). `ownerDone` (CAS `owner_done_at IS NULL`, parked/handed only) is **Mark done** on a waiting card: the item leaves WAITING FOR YOU, the Inbox count and Home's count, and no section shows it; feedback stays untouched, so learning never reads it. `ok`/`correct` write only on a finished twin decision not judged yet (`feedback = '' AND state = 'done' AND kind != 'check' AND outcome IN ('answered','approved','changes')`): a second tap, and a parked, handed, owner-first or check item, write nothing, so learning (`source_journal.go`, WATCHMAN-03) never reads a non-decision as one. `correct` trims and refuses a blank text; `checkDone` stamps a check once (`check_done_at IS NULL`).
- Decided cards offer **OK**, **Correct…** (while `feedback = ''`) and **Open session**; a judged card says `You marked this OK — Watchman learns from it` or `You corrected: <first line>`. Waiting cards offer **Open session** and **Mark done**; a check line offers **Mark done**.
- **Correct…** (`WatchmanCorrectSheet`, D26) stores the text first, then sends `Watchman decided "<question>" as "<choice>" while I was away. My correction: <text>` (one line): through `SessionLineDelivery` with `LineKey.watchmanCorrection(itemID)` (PROJ-12 gates; held/queued lines report their later tries) when the session takes it, else — no session, or `.noSession` — a new session on the item's target (`startForTarget(mode: .new, placement: .background)`) or, without a target, in its workbench, with the line as its first instruction. Both starts are launch-checked (`startInBackground(projectID:title:prompt:)` for the workbench), so a launch that did not run throws. The journal never arms it; a target the owner armed still covers its new sessions. A line submitted or typed into the session (not one only copied to the clipboard), or a started session, writes `correction_sent_at` (CAS; 00202 backfills it on rows corrected before the column, from `feedback_at`, else `created_at`); a failed start or a held line whose session stopped shows `Not sent — <reason>` with **Retry**, and a corrected row without `correction_sent_at` on a fresh read shows `Not sent — the app quit before it went` with Retry. Retry runs only from Not sent, sets Sending before it awaits (a second tap does nothing) and never rewrites the feedback. Cancel and Escape are off while the sheet saves; a CAS lost to another judgement keeps the sheet and text with `This decision was already judged; your text is kept here.`
- **Open session** routes to the item's session (or the one its correction started) via `AppState.navigateToWorkbench`; a stopped session is shown, never started.

## v1 limits

- The sleep window treats the night's 20:00 and 12:00 edges as actions and needs only 7 active days of 28, so it is biased toward the edges for a sparse owner.
- Agent commits are recognised by a `Co-Authored-By` trailer only; an agent that omits it makes its commit look like the owner's, and a merge an agent made may be counted as the owner's.
- A row committed behind a source's `hi` mark by an out-of-order writer is missed (the git source rescans 30 days behind `hi` and is exempt); a spec mark edited after the answer is not re-read.
- Handover asks (`finish_session`'s `handover_ask_id`) carry no mark in the database: they are learned as ordinary questions and the labeller may or may not file them under `finish`, so `finish` can be thin.
- The journal card's meta line has no backtest figure for the category (the spec mock's "strong 84 %"): phase 2 does not show it.
- The journal card shows the decision's outcome only; the spec's "merged into `feature/x`, PR #" line is not tracked in phase 2.
- A waiting (parked or handed) item has no OK or Correct… (an OK there would teach an empty choice); **Mark done** clears it instead. Which session a correction started is not stored: after a relaunch Open session opens the item's own session.
- The `unlabelled` counter is additive and can inflate when the CLI and the daemon overlap; it is a display figure only.
