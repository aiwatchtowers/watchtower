# Target Brief Chat (2026-08-19)

- "New target" is a **composer**, not a form (`CreateTargetSheet` rewrite): one multiline field + permanent hint caption. **Enter = brief the assistant, ⌘Enter = just create (silent, no AI call), Shift+Enter = newline**; the Extract affordance stays as a secondary control. The old title/intent/checklist/level fields are gone — precision editing lives in the target detail view. Conversions (situation/idea/track → target, "Add sub-target") reuse the composer via the unchanged `TargetPrefill` wiring.
- **Row creation is always mechanical, local, synchronous** (TGT-BRIEF-02): provisional title = first non-empty line (`TargetComposerLogic`, testable Core type), written via `TargetQueries.create` — AI unavailability can never block or delay creating a target. Enter then hands off to `TargetBriefCenter` (`@MainActor @Observable` center on `AppState`, the `TargetExtractCenter` shape) which sends the composer text as the first owner message in the target's Discuss chat and holds the `TargetChatViewModel` until the run finishes; `TargetDetailView` adopts the center's VM for that target id (no two VMs racing one conversation). Closing mid-run aborts the stream; the persisted user message survives.
- **Directive vs discussion, `"mode"` field:** each `watchtower-action` block gains optional `mode: "propose" | "execute"` — absent/unknown ⇒ propose (backward compatible; TGT-BRIEF-03). Execute-mode actions auto-apply through the same `TargetActionExecutor` path Approve uses (single Swift writer) — but only when they carry no `target_id` (e.g. `create_child_target`), name the chat's own target, or are a `link_target`; an execute action aimed at another target in the subtree or a parent stays a pending card awaiting Approve (`ProposedAction.autoApplies(inChatFor:)`). Auto-applied actions render as done-chips, and produce **one persisted `system` summary message — no per-action follow-up AI turns**. Propose-mode behavior is byte-for-byte unchanged. Execute exists only in the Desktop target chat; the Go track-watcher grammar (`defaultTrackRun`) stays a propose-only subset. Go is untouched.
- Four new action kinds: `update_title`, `update_priority`, `update_due`, `update_intent`; new mutators `TargetQueries.updateText`/`updateIntent`/`updateDueDate` + matching `TargetsViewModel` mutators. (2026-08-24 adds two more Desktop-only kinds, `add_label`/`remove_label`, riding the same propose/execute rules — see the targets.md changelog.) The system prompt (`taskActionsContract`) teaches the mode rule and states the mandate rule verbatim — within a directive the assistant may modify the target and its subtree only as the directive implies (of those, only changes to the chat's own target, new children and links auto-apply — the rest wait for Approve, see above); out-of-mandate findings go to prose, never actions (TGT-BRIEF-01: directive-bound, never autonomous — no initiated turns, no mutations between owner messages, no re-runs).
- Contracts: `docs/inventory/targets.md` (TGT-BRIEF-01..03). Design: `docs/superpowers/specs/2026-08-19-target-brief-chat-design.md`.
