# Ideas & Decisions Registry (2026-08-07)

- `internal/ideas/` — two-stage pipeline, deliberately asymmetric in cost. **Stage 1 (cheap, rides existing reads):** Slack's `digest.channel` prompt and the meeting `meeting.recap` prompt each grow an optional `ideas` array next to the existing `decisions` array (`digest_topics.ideas` / recap JSON — old rows with no field parse fine); two **new** light-tier passes, `ideas.digest_email` (per Gmail account, new-thread chunks) and `ideas.digest_jira` (per Jira account/project, changed issues + comments), write `stream_digests` rows. **Stage 2:** `ideas.consolidate` (strong tier, `internal/ideas/consolidate.go`) reads only new stage-1 material past three `workspace` floors (`ideas_digest_floor`/`ideas_stream_digest_floor`/`ideas_transcript_floor`) plus a slice of the current registry and an owner-preference block, and emits `new_idea`/`new_decision`/`attach_mention` ops that Go validates and applies in one transaction. Migration 00050 seeds the three floors at the current top of each source table, so an existing install starts from material mined after the feature shipped rather than backfilling all of history; the per-account stage-1 floors self-initialize on first run instead (an account connected later has no migration to seed it). A mention's `source` is derived from the validated ref — the model's own `source` token is parsed and ignored.
- Daemon phase `phaseIdeas` (after `phaseChannelDigests`), throttled by `ideas.mine_interval_hours` (default 6, the `phasePeopleCards` precedent), gated `ideas.enabled` (default **true** — headline feature, not dark). Jira comments get a new bounded sync (`jira_comments` table, `internal/jira/sync.go`): comments are fetched only for issues whose `updated_at` moved in that sync pass, capped by `ideas.max_comment_issues_per_sync` — this reconciles with INBOX-02 (the dormant inbox Jira-comment handling wakes up now that comments actually sync; fixtures adapted, assertions unchanged). **Coupling resolved 2026-08-12:** that comment sync now rides `streams.enabled` (`cmd/sync.go`'s `jiraCommentSyncEnabled`, default **on**), so `jira_comments` sync — and the inbox's `jira_comment_mention` trigger plus its INBOX-02 auto-resolve — are live by default, decoupled from `ideas.enabled`. See the 2026-08-12 entry in `docs/inventory/inbox-pulse.md`.
- Tables (migration 00050): `ideas` (kind `idea`/`decision`/`note`, status machine per kind, `similar_to_id`/`merged_into_id`/`converted_target_id`), `idea_mentions` (provenance trail, the `situation_signals` analogue), `stream_digests` (shared Gmail/Jira stage-1 output), `jira_comments`. Per-account stage-1 floors: `google_accounts.ideas_email_floor`, `jira_accounts.ideas_jira_floor`. `targets.source_type` CHECK gains `'idea'`.
- Config: `ideas.enabled`, `ideas.mine_interval_hours`, `ideas.max_comment_issues_per_sync`, `ideas.max_prompt_chars` (input cap; a truncated run's floors advance only past the rows actually included, never past unconsumed material).
- CLI: `watchtower ideas mine [--from <date> [--to <date>]]` (no flags = one incremental consolidator pass, envelope with counts + `refs_rejected`; `--from` switches to range backfill over a historical window, `--to` optional, defaults to now), `watchtower ideas list [--kind --status]`. MCP read tools (`internal/mcp/ideas.go`): `list_ideas`, `get_idea`.
- **Backfill (2026-08-08, `internal/ideas/backfill.go`, `Pipeline.Backfill`):** saves the three workspace floors + per-account email/jira floors, lowers them to the window start, drains stage-1 then the stage-2 consolidator in a capped loop (cap 50) bounded by `to`, then restores every floor to `max(saved, reached)` — mining a mid-history window never causes the daemon to re-mine `[to, now]` nor loses the pre-backfill watermark. Concurrency guard: an `ideas_backfill.lock` file (pid+timestamp, `Config.WorkspaceDir()`, the `last_ideas.txt` precedent) makes `phaseIdeas` skip its cycle while the lock is fresh (<2h), ignored once stale. Gmail/Jira stage-1 skips account-windows already fully covered by an existing `stream_digests` row (coverage skip — cost, not correctness); re-mining any window any number of times never duplicates registry state (**IDEA-05**, ref-level dedup in `applyConsolidateOps`, migration 00051's `idx_idea_mentions_ref` — see `docs/inventory/ideas.md`).
- Desktop: new sidebar tab **Ideas** (badge = proposed + needs-review count), master-detail (`IdeasView`/`IdeaDetailPane`, the Catch-Up master-detail layout precedent) — "For review" section on top, filterable registry below, action bar driven by kind+status (Approve/Reject/Not now/Activate/Convert to Target/Merge/Drop/Supersede/Reverse), 👍/👎 rating, mentions chronology, a manual create sheet (idea/note/decision). Per-idea Discuss chat (`IdeaChatViewModel`, `chat_conversations.context_type='idea'`) is the deliberate house-pattern copy of the Target/Meeting chat VMs. Swift writes verdicts/merges/conversions directly via GRDB (`IdeaQueries`) — the feedback dual-path precedent. The header-row **Find Ideas** button, next to Create (`IdeaBackfillSheet`), drives the CLI backfill over a from/to range (presets 2 weeks/month/quarter); run state (`isBackfilling`/`backfillSummary`/`backfillError`) lives on `IdeasViewModel` so it survives navigation (the async-state house rule). Settings → **Ideas** card (`ConfigService.ideasEnabled`/`ideasMineIntervalHours` ↔ `ideas.enabled`/`ideas.mine_interval_hours`) exposes the two everyday knobs.
- Contracts: `docs/inventory/ideas.md` (IDEA-01 floor honesty, IDEA-02 no invented provenance, IDEA-03 links not deletes, IDEA-04 resurfacing respects the verdict, IDEA-05 re-mining idempotency).
- Design/plan: `docs/superpowers/specs/2026-08-07-ideas-registry-design.md`, `docs/superpowers/specs/2026-08-08-ideas-backfill-design.md`.
- **Decisions split + cross-source digests (2026-08-12):** the registry narrows to ideas & proposals only — mined decisions are now born `active` (`applyNewIdeaOp` sets `Status: "active"` for `new_decision`; migration 00053 flips the existing `proposed` backlog), and the review queue (Go `CountIdeasForReview`; Swift `IdeaQueries.fetchForReview`/`countForReview`/`fetchList`'s `excludingReviewQueue` arm) excludes `kind = 'decision'` outright — decisions never ask for approval, they're a quiet journal. The Ideas tab narrows to Idea/Note kinds; the Decisions ledger (Supersede/Reverse, 👍/👎, mentions chronology, `seen_at`-based unread) moves to Digests → Decisions, reading `ideas WHERE kind = 'decision'` ordered by last mention. The Digests tab becomes a cross-source feed grouped by day: existing Slack `digests` rows, new `StreamDigest` Gmail/Jira rows (`stream_digests`, unread via the new `read_at` column), and meeting recaps (no unread concept) — the old digest→`decision_reads` catch-up cascade is removed as vestigial (the ledger is an independent journal with its own `seen_at`). New `streams` config block (`streams.enabled` default **true**, `streams.interval_hours` default 6) decouples Gmail/Jira stage-1 stream-digest generation and Jira comment sync from `ideas.enabled` — `Pipeline.RunStreamDigests` runs as its own daemon phase (`phaseStreamDigests`, before `phaseIdeas`) independently of whether stage-2 consolidation (`ideas.enabled`) is on; `wireIdeasPipeline` now wires whenever `streams.enabled || ideas.enabled`. See the 2026-08-12 entries in `docs/inventory/ideas.md` and `docs/inventory/inbox-pulse.md`. Design: `docs/superpowers/specs/2026-08-12-decisions-split-cross-source-digests-design.md`.
