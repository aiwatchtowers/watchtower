# Files outside the database — Stage A (2026-10-25, board #604)

- **Why.** Once the database is encrypted (#603), everything Watchtower writes outside it is the readable copy: logs, prompt temp files, Claude Code's session store, sidecars and caches. Stage A stops writing company content where it is not needed and moves small state into the database. Part of board group #595.
- **Who.** Everyone, no switch. Inventory: [FILES-01](../inventory/files.md) (FILES-02 planned), CHAT-01/CHAT-04 amended ([chat.md](../inventory/chat.md), ask #571).
- Design: `docs/superpowers/specs/2026-10-25-files-outside-db-design.md` (the full inventory of files, G1–G11 and S1–S16); plan: `docs/superpowers/plans/2026-10-25-files-outside-db-stage-a.md`. Owner approvals: asks #571, #577.

## Logs carry ids, never content (G3, FILES-01)

- **Rule.** Log lines name things by id (`channel=<acct>:<id>`, `user=<acct>:<id>`, `event=<id>`), with counts, durations, phase and error class. Pipelines log output fingerprints, never AI or source text.
- **Two-view error.** `logredact.Errorf(format, args...)` with `logredact.Text(s)` arguments builds an error whose `Error()` shows each `Text` only as a fingerprint — `<N bytes, shape, sha256:…>` — so every log line, `%v`/`%q`, wrapper and progress line is safe by default. `logredact.Full(err)` walks the chain and gives the whole text. It is called only where the owner reads an error: `pipeline_runs.error`, account status text, history backfill `last_error`, chat error events, `--progress-json` errors and the CLI's final stderr (not in the detached daemon, whose stderr is `daemon.log`). The classifiers that match a provider's words (`auth`, `rate_limit`, …) read `Full` too. A 120-char excerpt was rejected in review: a short body would pass through whole.
- **Where it applies.** CLI stderr and result envelopes (`internal/ai`, `internal/codex`, `internal/digest` generators), HTTP bodies (`internal/jira`, `internal/ollama`), Slack sync, meeting, digest, tracks, targets, briefing and people pipelines.
- **Guard.** `internal/logcanary` runs a pipeline with a canary in every synced field and fails when a canary reaches the log writer (`TestFILES01_*`, one per package).
- **Caps.** The daemon's stderr follows `watchtower.log`'s rotation (it used to grow `daemon.log` without bound); `sessions.log` rotates at 20 MiB.
- **v1 limit.** Logs written by an earlier version keep their text until rotation replaces them; deleting them is Stage C's one-time step.

## Prompts reach the CLI over pipes (G7, G8)

- **Pipes.** `fsutil.AttachPayloads(cmd, contents...)` hands each payload to the child as an inherited pipe (`ExtraFiles`, `/dev/fd/3…`): the claude system prompt (`--system-prompt-file /dev/fd/N`) and a secret-bearing MCP config (`--mcp-config /dev/fd/N`) never touch the disk. A writer goroutine per pipe feeds it; a child that exits without reading ends it with EPIPE. A respawn builds fresh pipes. The chat child's seatbelt profile lets it read `/dev/fd/N` (`TestChildSandbox_RealProfileReadsInheritedFD`).
- **Codex fallback.** codex stats `model_instructions_file` and refuses a pipe, so it keeps a 0600 `wt-system-prompt-*` file, held for codex's whole run and removed once it exits (a deferred `fsutil.HoldTempFile` release), not earlier: codex re-reads the file for every model request of its run, and a file removed at its first output fails the next request with "failed to load workspace requirements" (codex-cli 0.159.2). The holder keeps a shared `flock` on the file and the sweep below skips any file it cannot lock, so a long run — or a Mac asleep through one — never loses it; the kernel drops the lock when the holder dies. The probe fails closed: a file the sweep cannot open or lock is kept, and the probe failure joins the sweep's error (the daemon logs it; the name never does). A hold that cannot lock its file still removes it on release and is logged as unshielded (`codex.holdPromptFile`). The lock is Watchtower's, not codex's: a codex child that outlives a killed Watchtower loses the file to a later sweep, but its reply has no reader by then. Trade-off: a process killed mid-run now leaves the file until a sweep finds it 10 minutes stale (before, a kill after codex's first output left nothing); the file is 0600 in the per-user `$TMPDIR`, and it lives as long as the codex child does.
- **Sweep.** Every process start (`cmd/root.go`, `go sweepStaleTemp()`) removes `$TMPDIR` files matching `fsutil.StaleTempPatterns` — `wt-system-prompt-*`, `wt-chat-prompt-*`, `wt-chat-mcp-*`, `wt-mcp-*.json` — older than 10 minutes and not held (`fsutil.HoldTempFile`'s flock). `wt-chat-turn-*` and `wt-mcp-status-*` live for a whole session and are never swept. The same sweep removes a codex run's private temp home (`fsutil.StaleTempHomePatterns`: `wt-agent-codex-home-*` for `agent()`, `wt-review-codex-home-*` for the spec reviewer), which holds the run's rollout: a live run holds `.wt-hold` inside it (`fsutil.HoldTempHome`), so only a killed run's home older than 10 minutes goes (2026-11-06, transport Task G2). The daemon also sweeps its extract spool `<workspace>/tmp/extract` (G9).
- **Upgrade edge case.** The earlier version kept `wt-chat-prompt-*`/`wt-chat-mcp-*` files for a chat session's whole life. A session of the old version still running more than 10 minutes after the new version's first process start loses them to the sweep; its claude child already read them, but a respawn of that old session fails and the chat shows an error. The next app launch runs new sessions. Accepted: the window is one app update.
- **Desktop text over stdin (S6, S7).** The Desktop no longer writes `watchtower-text-*`, `transcript-*`, `segments-*`, `speakers-*`, `dictation-*` or `watchtower-automation-*` temp files: meeting recap and topics, track compose, target extract and track instructions pass `--text-file -`, dictation `--transcript-file -`, `transcript save` reads one JSON object on `--stdin`, and `automations validate -`/`save --file -` read the recipe on stdin. `StaleTempSweep` removes those prefixes' leftovers (older than 600 s) at launch.

## No Claude session store (G11)

- Every `ai.Client`/digest claude call and the chat session child pass `--no-session-persistence`, so `~/.claude/projects/<cwd-slug>/*.jsonl` is never written for Watchtower's own calls (the workbench terminal's Claude Code sessions are the agent's own and are not affected).
- **Chats replay.** The main chat never passes `--resume`: a new child gets the system prompt over its pipe and the history as `ReplayFromDB` (the old `session_lost` path). `ChatSessionConfig.resumeSessionID`, `ChatContinuity.initialLeaf` and the stored-tip check are gone; a new Swift session has no continuous leaf, so its first turn sends `replay: true`. Before a turn's rows are written, `ChatViewModel` awaits the driver's queued writes so a stopped reply's final save is in the database the replay reads. `chat_conversations.session_id` stays and is not read (the main chat's driver still records it).
- **Embedded chats** (`EmbeddedChatEngine`) neither save nor load a session id: every turn sends the system prompt and `EmbeddedChatReplay.block` over the stored rows, on every provider. The surfaces' resumed-turn context blocks and the code question's usage attachment are gone (the usages are part of the context every system prompt carries). `WatchtowerAIService.buildArgs` no longer passes `--session-id`.
- **Cost.** A respawned chat re-sends its history once (capped by the replay budget).

## Small state into the database (migration 00157)

| Table | Was | Writer | Reader |
|---|---|---|---|
| `automation_draft_cache` (`conversation_id` → `chat_conversations` ON DELETE CASCADE, `seq`, `entry_json`, `at`) | `<workspace>/automation-drafts/<id>.jsonl` (G2) | Go, `draft_automation` on `automation_editor` (newest 5 kept) | Desktop Draft panel and list rows; Desktop deletes a saved or discarded draft's rows |
| `pending_transcripts` (`recording`, `event_id`, `title`, kept `transcript` + `meta_json`; a dismiss is the `{"dismissed":true}` tombstone) | `rec_*.meta`/`.txt`/`.json` sidecars and the pending-recording defaults (S3, S4) | Desktop `MeetingRecorderCenter` through `PendingTranscriptStore` | Desktop recovery scan and retry |
| `chat_queued_drafts` (`surface_key`, `text`, `at`) | `embeddedChat.queuedDraft.*` UserDefaults (S15) | Desktop `DatabaseDraftMirror` | the same |

- **Legacy imports (once, then deleted).** The daemon's `importLegacyDraftCache` moves each `.jsonl` in one transaction and skips a conversation that already has rows (a failed removal never duplicates); a file of a missing conversation is removed; one that does not parse is deleted (a cache: no recipe text outside the database); one that cannot be read stays for the next start. `DatabaseDraftMirror` moves the queued-draft defaults when its writer is set (this process's own save or clear wins; `restore` sees them at once).
- **Recording upgrade rule.** The sidecar build kept a recording pending exactly while its `rec_X.meta` existed, and that holds across the upgrade. `LegacyRecordingSidecarImport` (when the pool opens) turns a stem with a `.meta` into a pending row with its kept transcript, and a stem without one (a lone `.txt` or `.json`, or the pair) into a dismissed tombstone, its text not imported. A stem counts as imported once its `.meta` is gone (deleted last); every failed delete is logged and retried next launch. Then a one-time pass (UserDefaults `recorder.legacyAudioTombstoned`, set only when it finished) tombstones every `rec_*` audio with no `.meta`, no row and no saved transcript, skipping busy recordings and audio modified after `recorder.legacyAudioCutoff` (stamped once, at this build's first launch, before the pass can run or fail), so a recording dismissed on the old build never comes back and one made in a launch whose pass did not finish is never taken for it.
- **Recording rules.** The pending row is written once the capture runs (a slow or failing store never delays or stops it); a crash before it lands is recovered from the audio alone. Later row-less `rec_*` audio that no saved transcript points at is offered without its event link; a row whose audio a saved transcript points at is never offered (a failed removal after a save). A dismiss writes a tombstone row. At launch, rows whose audio is gone (tombstones included) are pruned, except busy ones and rows written since the launch began (a phone copy in flight). Phone ingest reserves its file name with an `INSERT … ON CONFLICT DO NOTHING` row; without a database it refuses (`PhoneIngestError.databaseUnavailable`). Store writes await the writer (board #670); reads are synchronous.
- **Notification snapshot (S16).** `WorkbenchNotificationPolicy.Snapshot.persisted` (UserDefaults) stores `ContentDigest.of(text)` (`sha256:` + hex) for the workbench name, target and ask titles; `decide` reads only ids, statuses and watermarks from the previous snapshot.
- **Slice-asset keys (S12).** `SliceAssetStore` keeps each staged file's `AssetDescriptor` (with `K_asset`) in `hubstate.db`'s `slice_assets` (key `<record>/<file>`), never a `.desc` file; a `.desc` left by an earlier build is moved into a row at init.
- **Workchat pastes (S9).** `WorkchatAttachmentStore` writes 0600 files in 0700 folders; a session's exit removes its folder, and the launch sweep removes every non-running session's folder whatever its age.
