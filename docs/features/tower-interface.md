# Tower interface — one command interface for the Mac and the phone

Spec: `docs/superpowers/specs/2026-11-15-mobile-inbox-design.md` §2.1 (#1170). Stage 0: the core in `internal/tower` and `internal/tower/api`, the request ledger and the builtins. Stage 0 also adds the generator and the `WatchtowerInterface` package, the daemon socket, the change watch and the pause (below). Later stages add the Inbox commands to this note.

## Commands and envelope

- A command is a name (`domain.verb`) with a request type and a response type in `internal/tower/api`, registered once with `tower.Register(r, name, handler, tower.Spec{…})`. A duplicate name panics. `Registry.Commands()` lists them sorted, with the `reflect.Type` of each request and response (the generator's input).
- `tower.Spec`: `Read` (no ledger, no `request_id`), `Idempotent` (a guarded write), `Grant` (the hub grant), `ChangeTables` (a read or watch: the tables whose change re-reads it; a write: the tables it changes), `Watch` (a watch command: `Call` runs it like a read, and the socket then streams its changed events). `IdempotentFor`/`GrantFor` decide from the params when set (one command whose verbs differ, such as `inbox.act`).
- Envelope (`api.EnvelopeVersion` = 1): a request is `{v, id, command, params}`; a response is `{id, status, result | refusal{code, sentence}}` with status `ok`, `refused` or `unknown`. `Tower.Call` never fails: an unknown command, another envelope version, unreadable params or a write without `request_id` answer `refused` with `unsupported`.
- Refusal codes are exactly `not_found`, `changed`, `args_changed`, `reply_waiting`, `not_permitted`, `unsupported`. A handler refuses with `tower.Refuse(code, sentence)`; the sentence is written in Go and both clients show it as is. Any other handler error answers `unsupported` with `Options.Sentence(command, err)` (default: the error text).
- A handler gets a `*tower.Ctx` (`DB`, `Origin` — transport `socket`|`hub` and device —, `Now`). It writes through `Ctx.Write(ctx, fn)`: one `BEGIN IMMEDIATE` transaction around `fn`, committed, then `Options.Changed(spec.ChangeTables)`. `Changed` is called only after a commit, never on a rollback. Keep `fn` short: no network, LLM call or render inside it.

## Ledger

`tower_requests` (migration 00192): `request_id` PK, `command`, `state` `begun`|`done`, `result_json`, `refusal_json` (a non-idempotent refusal on a `done` row), `at` (UTC `%Y-%m-%dT%H:%M:%SZ`). Written only by `internal/tower`. Every write command embeds `api.WriteParams` (`request_id`, a UUID the client makes once per press and keeps across its retries).

- **A repeat of a `done` id** answers the stored result, byte for byte, without running the handler.
- **Guarded (idempotent) commands** write their `done` row inside the same transaction as their write (`Ctx.Write`), so `done` exists exactly when the write committed. A guarded command calls `Write` once, and `fn`'s result is the command's response. A handler that never calls `Write` gets its `done` row after it returns. A fault or a refusal rolls back and leaves no row, so a resend may succeed. A `begun` row of a guarded command is re-run. A duplicate that committed first wins: the later write rolls back and answers the first result (`FinishTowerRequestTx` never overwrites a `done` row).
- **Non-idempotent commands** (approve, retry, Run Now, the `reply` press) commit `begun` in their own short transaction before they act and write `done` after the handler returns. A repeat of a `begun` id answers `unknown` and never acts; so does a duplicate that began first, and a handler error after `begun` (it may have acted). A refusal is a definite no-act: it is recorded `done` with the refusal (`RefuseTowerRequestTx`), so a resend of that id answers the same refusal.
- A `request_id` recorded for another command is refused (`unsupported`).
- **Prune.** The daemon (`runSyncDaemon`) runs `tower.RunPrune` through `tower.StartPrune`, whose stop (deferred) waits for the loop to return before the database closes: once at start and then every `tower.PruneInterval` (1 h), with or without the hub, it deletes rows of both states older than `actions.LedgerRetention` (`ActionMaxAge` 7 days + `retentionMargin` 1 day), the window the hub's own ledger keeps. The hub refuses an action older than `ActionMaxAge` before a handler sees it, so a phone action replayed after a long Mac sleep either finds its row or is refused; it never runs twice.

## Builtins

`tower.RegisterBuiltins(r)` registers two reads:

- `tower.hello` → `api.HelloResponse{interface_version, build, sync_paused, no_sync}` from `tower.InterfaceVersion` (generated, see Generator) and `Options.Build`/`Paused`/`NoSync`.
- `tower.ping` → `api.PingResponse{at}`, the daemon's clock in UTC RFC 3339.

## Socket

The daemon (`runSyncDaemon` → `serveTower`) serves the tower on a unix socket, hub or no hub; when the hub runs, it is in the same process and calls the same `Tower.Call`. A socket that cannot be served is logged and the daemon syncs without it.

- **Path.** `tower.SocketPath(workspace)`: `<workspace>/tower.sock` when that is at most `SunPathMax` (103) bytes, else `<TMPDIR>/wt-<uid>/<first 12 hex of sha256(workspace)>.sock`. `ServeWorkspace` writes a fallback path into `<workspace>/tower.sock.path` (`SocketPathFile`, 0600, temp file and rename), which clients read, and removes it on stop; serving in place removes a stale one.
- **Privacy.** `Serve` makes the socket's directory a 0700 directory of this user (creates it 0700, tightens a wider one, refuses one another user owns) and binds the socket 0600, replacing a stale socket (the daemon holds the sync lock) and refusing a path that is not a socket. A connection whose peer uid (`platform.PeerUID`, the hub control socket's check; seam `peerUID`) is not `os.Getuid()` is closed unanswered.
- **Frames.** Newline-delimited JSON: an `api.Request` in, an `api.Response` with the same `id` out. One connection's calls run concurrently (at most 64 in flight), so answers can come out of order; a slow call (an approve that waits for its tool) holds no other call back. A call runs on the server's context, not the connection's: a client that disconnects mid-write leaves the ledger to record the outcome for its resend. A line that is not a request answers `refused`/`unsupported` and the connection goes on; a frame longer than `MaxFrame` (1 MiB) closes that connection only. A frame write that takes over 10 s closes the connection.
- **Watch.** A command with `Spec.Watch` answers `ok` once (`Call` runs its handler), then streams `api.ChangedEvent` frames — `{id, event: "changed", tables?}`, `id` the watch request's — until the client closes the connection, which keeps answering other calls meanwhile. The watch subscribes before it answers, so no change after the `ok` is missed. Without `Options.Changes` a watch is refused (`unsupported`).

## Client (Swift)

`TowerClient` (`WatchtowerInterface/…/Client/`, an actor) is the one state machine every screen bound to the tower uses, over a `TowerTransport` (`call`, which throws `TowerTransportError.down` when the tower is unreachable; `watch`, a stream of `ChangedEvent` that ends `.down` or `.refused`). It takes an injected `Clock<Duration>` (tests use a manual clock) and two daemon closures: `restartDaemon` (restart from the app's own CLI, nil on the phone) and `startDaemon` (the start queue).

- **Screen states.** `idle` → `loading` (first read) → `ready(stale:)`; `reconnecting`; `failed(TowerFailure{kind: down|version|refused, sentence})`. `stale` is the time of the last read that answered while the shown data is not confirmed current (the tower came back and the re-read is on its way, or a later read was refused); a refused read with nothing read before is `failed(.refused)` with Go's sentence. `TowerFailure.actionTitle` is Restart for `version`, Retry otherwise; both call `retry()`.
- **Handshake.** The first call says `tower.hello`, and so does every reconnect attempt. Another `interface_version` (or a refused hello) restarts the daemon once through `restartDaemon` when it returns true, then reconnects; otherwise `failed(.version)` ("Watchtower's background service is a different version."). Nothing else is sent to a daemon of another version.
- **Reconnecting** (`TowerTiming`). A call that throws `.down`, or a watch that ends `.down`, puts the client in `reconnecting`: attempts at 0.2 s after the drop, doubling to 2 s (0.2, 0.6, 1.4, 3.0, 5.0 s…, counted from the drop); `showsReconnectingLine()` turns true after 1 s down (the state is re-published then); after 15 s down, `failed(.down)` ("Watchtower's background service isn't running"). Calls wait meanwhile and are re-sent unchanged; a call started while `failed` starts a new cycle at once. `retry()` after `failed(.down)` awaits `startDaemon` (after `failed(.version)`, `restartDaemon`), then reconnects from the 0.2 s backoff; otherwise it re-reads.
- **Return.** Every open watch is re-opened, and the screen's last `read` is re-issued once (unless a read is already waiting to be re-sent); its result goes out on `refreshes()` as a `TowerRefresh{command, result}`.
- **Actions.** `act(command, key:, params:)`: `key` is a row's id plus its verb. A new press makes a lowercase UUID `request_id`, passed to `params`, and keeps it until a final answer (`ok`, refused, unknown); a press that failed (15 s down) keeps it, so Retry re-sends the same id. A second press while one is on its way waits for that one. `actionState(key:)` is `busy` while on its way, `refused(sentence)` or `unknown` after; `unknown` is never re-sent: the client re-issues the last read instead.
- **`SocketTransport`** (WatchtowerCore, `Services/Tower/`): the Mac's transport. Every new connection reads `<workspace>/tower.sock.path` when it exists (empty or unreadable: down, logged), else uses `<workspace>/tower.sock`. Calls share one connection (answers matched by `id`; a closed connection fails every waiting call with `.down`, and the next call opens a new one); each watch has a connection of its own, closed when its consumer stops. Frames past 64 MiB close the connection.
- **`TowerText`** holds every user-facing string of the client (`TowerTextTests` pins each).

## Change watch

`tower.Changes` (`NewChanges(db, PollInterval)`, passed as `Options.Changes`) is the daemon's own change watch, independent of the hub.

- **Own writes.** `New` wires `Options.Changed` to also `Publish` the command's `ChangeTables`, so a write through `Call` delivers `changed` with its tables at commit, before `Call` returns.
- **Other processes.** A `PRAGMA data_version` poll every `PollInterval` (250 ms) on a read-only handle of its own (`db.OpenExisting`; the daemon's pool has one connection) publishes `changed` with no tables when the version moved; the first read is the baseline. It runs only while at least one watch is subscribed: the first `Subscribe` starts it and the last `cancel` stops it and waits, so no read runs with no watch open. An in-memory database has no poll (own writes still publish). An own write may be seen by the poll too: the client reads once more.
- **Filter.** `Subscribe(filter)` delivers an event whose tables meet the filter (one table in common), or that has none; a nil filter takes every event. A publish never blocks: each watch queues 16 events and a full queue drops the new one, which loses nothing, because the queued event already makes the client read after that write.

## Pause

- **The owner's pause.** `sync.pause` and `sync.resume` (guarded writes, `api.PauseRequest{request_id}` → `api.PauseResponse{paused}`, no `ChangeTables`, registered by `tower.RegisterPause` in `commands.RegisterAll`) write and remove `<workspace>/sync.paused` (`PausePath`; `SetPaused` writes a temp file and renames it, mode 0600; `IsPaused` = the file exists). The daemon is its only writer, and it is not in `config.yaml`, so it survives a restart. Without `Options.Workspace` both are refused. `tower.hello`'s `sync_paused` is `IsPaused(Options.Workspace)` unless `Options.Paused` says otherwise.
- **`--no-sync`.** `watchtower sync --daemon --no-sync` (the app's start before onboarding finishes) is a start argument, never stored: `tower.hello` says `no_sync: true` and no `sync.paused` is written. `--detach` re-execs with the same arguments, so the child keeps it.
- **What a pause holds.** `runSyncDaemon` gives the daemon `SetSyncPaused(func() bool { return noSync || tower.IsPaused(ws) })`. While it says paused, no sync cycle starts (a trigger, a tick, a wake; `startCycleOn` returns nil) and a running one finishes; the startup calendar sync is skipped; the automations scheduler (no scheduled run) and the plan-usage poller are stopped through `runUnlessPaused`, which asks again every `pauseRecheck` (5 s) and restarts them on resume. A restarted scheduler ticks at once, so a slot missed during the pause follows AUTO-10's catch-up rules, as after a sleep. The executor (Run Now, approval apply), the socket, the hub and the Inbox keep running. After a resume, the next sync cycle starts on the next poll tick or a Sync Now.

## Generator

`go run ./internal/tower/gen -root <repo>` (`make gen-interface`) writes the Swift side of the interface from the Go types; never hand-edit its output. `-check` (`make gen-interface-check`, in CI's Go Test job and in `make lint-all`) writes into a temporary folder and exits 1 with a unified diff when any file differs.

- **Input.** The commands `commands.RegisterAll(r, commands.Deps{})` registers (`internal/tower/commands`, the one registration table; a zero `Deps` is valid) plus the frame types `api.Request`, `api.Response` and `api.ChangedEvent`, and every type they reach. A type no command reaches is not generated.
- **Output.** In `WatchtowerInterface/Sources/WatchtowerInterface/Generated/`: `TowerTypes.swift` (every type, sorted by name), `TowerCommands.swift` (`TowerCommand: String, CaseIterable`, one case per command — `tower.hello` → `towerHello` — with `isRead` from `Spec.Read`) and `InterfaceVersion.swift` (`InterfaceVersion.current`); `internal/tower/interface_version.go` (`const InterfaceVersion`, answered by `tower.hello`); and `WatchtowerInterface/Tests/WatchtowerInterfaceTests/Generated/GoldenRoundTripTests.swift`. Every file starts with `// Code generated by go run ./internal/tower/gen. DO NOT EDIT.`
- **The version.** The first 16 hex characters of the SHA-256 of `TowerTypes.swift` followed by `TowerCommands.swift`, as generated. Any change to a wire type or to the command list changes it.
- **Mapping.** `string`→`String`, `bool`→`Bool`, `int`→`Int`, `int64`→`Int64`, `float64`→`Double`, `[]T`→`[T]`, `map[string]T`→`[String: T]`, `json.RawMessage`→`RawJSON` (hand-written: any JSON value, kept as canonical sorted-key bytes). A pointer or an `omitempty`/`omitzero` field is optional. A struct becomes `public struct X: Codable, Hashable, Sendable` with `public var` properties (named from the Go field: `RequestID` → `requestID`), a public memberwise `init` (optionals default to `nil`) and `CodingKeys` from the JSON tags; embedded structs (`api.WriteParams`) are flattened as `encoding/json` does. `time.Time`, any type with its own JSON encoding, `[]byte`, `any`, other number kinds, a non-string map key, a pointer element or two Go types with one name fail the generator with the field's path (`Sample.At`).
- **Enums.** A `type X string` with `func (X) EnumValues() []string` becomes a Swift enum with one case per value (`not_found` → `notFound`) plus `case unknown(String)`: decoding an unlisted value gives `.unknown(value)`, encoding writes it back, and equality and hashing go by the raw value. A value whose case would itself be named `unknown` takes the type's name (`Status` "unknown" → `.unknownStatus`). A named string type without `EnumValues` is a plain `String`.
- **Nil slices and maps.** A slice or map field without `omitempty` is non-optional in Swift (`[T]`, `[String: T]`). Go writes a nil one as `null`, so a struct with such a field gets a generated `init(from:)` that decodes a missing or `null` one as empty (`[]`/`[:]`); Swift encodes it back as `[]`/`{}`, which Go reads as empty. Goldens write empty collections as `[]`/`{}`. The generator's sample types are also generated into the Swift tests (`Generated/SampleTypes.swift`), where `NilCollectionsTests` decode Go's own encoding of a zero sample (`internal/tower/gen/testdata/sample_nil.json`).
- **Case names.** An enum value with no Swift case of its own (empty, starting with a digit, or two values with one camel-case name) and two fields with one Swift property name fail the generator.
- **Goldens.** Every generated root (the frame types and each command's request and response) that has fields has `internal/tower/api/testdata/<Type>.json`. `TestEveryRegisteredTypeHasAGolden` checks each exists, decodes with `DisallowUnknownFields` and re-encodes to the same canonical JSON; the generated `GoldenRoundTripTests` (`test<Type>RoundTrip`) decode each into its Swift type and compare the sorted-key re-encode (null members dropped on both sides), and `testUnknownEnumValueSurvives` round-trips `"zz_future"`. A new command adds its goldens with its registration, then runs `make gen-interface`.
- **The package.** `WatchtowerInterface/` (swift-tools 5.10, macOS 14 / iOS 17) has no package dependencies and imports Foundation only (`PublicAPISurfaceTests.testInterfacePackageIsFoundationOnly`). `WatchtowerCore` and the phone app depend on it. `make interface-test` runs its tests; SwiftLint (`make lint-swift`) skips its `Generated/` folders.
