# Chat Redesign (2026-09-26)

- The main AI Chat runs on warm per-conversation sessions: `watchtower ai session --conversation N [--provider --model --surface main --project-id K --resume SID --db-path]` (`cmd/ai_session.go`, `internal/chat/session.go`) keeps one `claude -p --input-format stream-json --output-format stream-json --include-partial-messages --verbose` child for the conversation's life and speaks **protocol v2** — NDJSON events on stdout (`session_ready`/`turn_start`/`text_delta`/`tool_start`/`tool_end`/`usage`/`turn_done`/`error`; there is **no `reset`**, text is never wiped) for JSONL commands on stdin (`turn`/`cancel`/`close`). `cancel` sends Claude's `interrupt` control request; no `result` within 5 s → the child is killed and the next turn `--resume`s. Codex and Ollama (`NewTurnBackend`) run one provider call per turn behind the same protocol, always with replay (`ReplayFromDB` over the active branch) and rejecting binary attachments (`attachment_unsupported`); Codex delivers the system prompt + replay + user text entirely on stdin (`codex exec -`), never via `-c developer_instructions=...` or positional argv, while Ollama runs runtime B's in-process tool registry (`agentloop.NewClient`) so its tool calls become the same visible steps. Error codes: `auth`, `rate_limit`, `provider_unavailable`, `session_lost` (retried once with replay), `attachment_unsupported`, `interrupted`, `internal`. Both the session child and `ai query` pass `--strict-mcp-config` (only Watchtower's server + the owner's Quick Connections, never the owner's claude.ai connectors) and hide the newer CLI built-ins too (`ai.DisallowedTools`; `ToolSearch` stays allowed); the session child alone unhides **`WebSearch`** (`ai.SessionDisallowedTools` + `ai.WebSearchTool` in `--allowedTools`, Claude backend only — `WebFetch` stays hidden everywhere, since fetching an arbitrary URL is the exfiltration channel for a prompt-injection payload in synced content), and its prompt swaps the "NO internet" rule for `blocks.WebSearchRules` (public knowledge only, no private data in queries, web text is data, cite URLs; `PromptOptions.WebSearch`), with results parsed into `web` source chips (`webSearchSources`); the session child runs in a dedicated empty, stable cwd (`chat.NeutralWorkDir`, `$TMPDIR/watchtower-chat-cwd`) so no project `CLAUDE.md` leaks into answers and `--resume` still finds the session. `ai query` stays for the Discuss chats. A warm process spans many turns, so the chat-mode MCP server reads the current turn id from a 0600 `--turn-file` (`tools.Binding.TurnIDFunc`; `--turn` stays for one-shot use).
- **The system prompt is Go-owned** (`internal/chat.BuildSystemPrompt`, budget `PromptBudgetChars` = 40k chars without project files): identity/time/owner (`db.ResolveOwner`) + language directive, connected sources + the per-account Slack link rule, tools & linking rules, the actions contract (`ActionsContract`, a Go port of Swift `AgentToolsContract.promptBlock(.main)` — a dual path with the Swift copy the target chat still uses, pinned by fixtures on both sides), the artifacts contract (`ArtifactsContract`), enabled skills, the memory hot map (gated `memory.surfaces.chat`), the project block, a short app guide. Written to a 0600 temp file passed via `--system-prompt-file`, never argv, and never re-sent on `--resume` (the resumed history already carries it — verified on claude 2.1.283: a session started with `--system-prompt-file` and resumed without it still follows that prompt); because of that, `Session` opens every turn's stdin text with a `[Current time: …]` line (`turnTimeLine`, never stored), which the prompt says wins over its spawn-time `Current time`, and a fresh child's session id is taken from its first line (init), so a turn killed after a cancel still reports it and the respawn resumes rather than starting blank. The DB schema is no longer in any chat prompt.
- **Data — migration `00076` adopts the tables Swift used to create lazily into goose.** `normalizeLegacyChatTables` runs in `(*DB).migrate()` before `goose.Up` to add the columns an old Swift-created install may lack; the SQL migration then creates/extends everything, so the chat tables are now **present on every database from the moment it opens, including a headless daemon** — `ChatTablesPresent` stays only as a defensive guard for a handle opened on a pre-00076 file. New: conversation `pinned`/`archived_at`/`title_source` (`prefix|ai|user`)/`provider`/`model`/`project_id`/`active_leaf_message_id`; message `status` (`complete|partial|error`)/`provider`/`model`/`tokens_in`/`tokens_out`/`parent_id`/`error_code`, plus `error_message` (migration `00091`: the session's own error text, shown under the code's generic phrase on the error card, whose sign-in hint follows the row's provider); tables `chat_turn_steps`, `chat_attachments`, `chat_artifacts`, `chat_projects`, `chat_project_sources`, and trigger-maintained `chat_fts`. Messages form a tree via `parent_id` (legacy rows backfilled to a linear chain); regenerate/edit create a sibling (`‹ i/n ›`); the visible thread is root → `active_leaf_message_id`, and every Go reader filters to it (`db.ActiveChatPath`, and the memory-facing `ListOwnerChatTurns`/`ListRecentChatTurns` — the write-time evidence check `OwnerChatTurnExists` is branch-agnostic by design, see `docs/inventory/memory.md`). **Writers:** Swift writes every chat table; Go writes only titles — `watchtower chat title <id>` (prompt `chat.title`, light tier), never over `title_source='user'`.
- **Swift:** `ChatSessionPool` on `AppState` (max 3 live sessions — a running turn is never cut to make room, a 4th conversation queues — LRU eviction of idle sessions, idle TTL 10 min on a 30 s poll via the pure `ChatSessionPolicy.decide`, prewarm on open/first keystroke, crash → respawn with `--resume` or replay; `QuitCoordinator` closes sessions BEFORE stopping the daemon: `close`, then SIGTERM after a 2 s grace, then SIGKILL after 3 s more). `ChatViewModel` persists the user message before sending and partial assistant text on stop/crash, persists every tool step immediately, and fires `chat title` after the first completed turn. UI: left history (Pinned/Today/Yesterday/7/30 days/Older + Projects, ⌘K search), steps block, error/stopped cards, and — once a turn finishes — one collapsed sources row (`SourcesSummaryRow`) that opens a grouped, deduped Sources panel sharing the artifact panel's `.inspector` slot (`ChatInspectorPolicy`: the two never close each other; `ChatSourceGrouping` in WatchtowerCore groups by Go's optional `Source.group`/`snippet`/`date`, deriving a legacy group from the title for rows persisted without them).
- **Files & artifacts:** attachments (images png/jpeg/gif/webp ≤5 MB, PDF ≤32 MB, text-like ≤256 KB per file; one message's files together ≤30 MB as sent — base64 for images/PDFs — `chat.MaxTurnAttachmentEncodedBytes`, so a set over it, or a single PDF over ~22 MB, is rejected up front as `attachment_unsupported` rather than failing at the provider) are stored 0600 under `<workspace>/chat_files/`, sha256-deduped per conversation, and travel as paths in the `turn` command on stdin — Go builds the content blocks, base64-encoding the file itself into the stdin block (never the path). Artifacts are `:::artifact key="…" kind="…" title="…"` fences (`document|table|email|slack|event|code`) parsed streaming-aware by `ArtifactParser`, versioned per (conversation, key) in `chat_artifacts`, shown in a side panel whose kind actions only **open or copy** — Gmail compose URL (`mailto:` fallback), Slack body to clipboard + deep link, Google Calendar template URL; a source scan (`ArtifactChat05ScanTests`) additionally pins that the artifact-side files never reference `Process`/`URLSession`/the CLI/`ChatSessionPool`. Selection comments on an artifact's passages, sent as one batched owner turn, and the matching quote-reply flow on chat answers are covered under "Projects" below (Phase 6, 2026-09-29).
- **Actions:** new External registry tools `add_jira_comment`, `transition_jira_issue`, `assign_jira_issue`, `update_jira_issue` (surfaces main + target, always behind Approve — `SetTrust` refuses `execute` for any `External` tool); `create_idea`/`create_track`/`remind_me` widened to surface `main` alongside the reaction path. Because `create_idea` and `remind_me` default to trust `execute` (not `External`), widening their surfaces to `main` means they can now run on Approve-free auto-apply from the main chat too, not just from a reaction — a real behavior change, not just a surface list edit.
- **Projects, mentions, skills:** a project has instructions, pinned sources (Jira projects, Slack channels, targets, tracks, people) and files; `ai session --project-id` puts them in the prompt, and the Go Claude backend attaches the project's images/PDFs to the first turn of every fresh provider session (not a `--resume`, whose history already holds them) — within what the owner's own files leave of the 30 MB per-message cap (a file that does not fit is skipped with a warning; the prompt lists one over the cap on its own as not attached, and a turn whose owner files leave too little room says so in its text), and again on the next turn if that turn ended in an error — once: after two failed turns carrying them they are given up for that `ai session`, so a file the provider refuses cannot fail every turn. A turn killed after a cancel counts as delivered (its session is resumed, not refilled). Deleting a project keeps its chats, deletes its files. `@` opens a local-DB picker over people/Jira issues/channels/targets/tracks; `/` as the first character lists enabled skills — every enabled skill is now available in the main chat too, not just the Discuss chats.
- Contracts CHAT-01..05 in `docs/inventory/chat.md` (owner text never lost, no silent tool activity, bounded warm sessions, content off argv, artifacts never send). Spec `docs/superpowers/specs/2026-09-26-chat-redesign-design.md`, plan `docs/superpowers/plans/2026-09-26-chat-redesign.md`. **v1 limits (accepted):** Codex gets no guaranteed token streaming or steps and no binary attachments; project edits (instructions, sources, files, delete) drop the project's chats' stored Claude sessions in the same transaction and retire their warm processes (a running turn finishes first and records no session id), so each chat's next turn starts fresh with the new prompt and replays — at the cost of that replay; Slack/Gmail/Calendar artifacts open ready instead of sending (new OAuth scopes for real sends are a separate decision); no numbered citations, page fetching or vectors (web search is Claude-only, and the Discuss chats on `ai query` have none); a Go-owned tool loop for Ollama (runtime B) is a follow-up, not part of this branch.
