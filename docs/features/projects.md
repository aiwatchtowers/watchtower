# Projects — Claude Code works a folder-bound board (2026-09-29, POC)

- A **project** is a folder (`projects`, migration `00081`; `folder_path` symlink-resolved and UNIQUE) with sources (`project_sources`), attached markdown documents (`project_documents`, `rel_path` inside the folder), owner↔agent comments (`project_comments`: on a target, on a document with a text anchor `anchor_quote/prefix/suffix/heading`, or a reply; roots `open|resolved|outdated`) and a board of ordinary `targets` rows carrying `project_id` (`level='custom'`, `custom_label='project'`, `source_type='chat'`). Separate from the AI Chat's `chat_projects`, which stay as they are.
- **PROJ-01:** a project target never reaches a non-board reader — `TargetFilter.ProjectID` 0 = exclude (the default for every existing caller), plus `project_id IS NULL` in next-step, briefing targets, counts, due-notify, catch-up, memory mirrors, day plan, channel stats and the extract/dedup snapshots; Swift `TargetQueries.fetchAll/fetchCounts/fetchDistinctTags` (so the Targets badge), the chat `@` picker, and "Wipe LLM data" (which would otherwise delete them as `source_type='chat'`).
- Work is done by Claude Code in the folder — the owner's own terminal or the Desktop's embedded SwiftTerm terminal (`TerminalCenter` on AppState, one process per `terminal_sessions` row — migration `00084`, a named claude/shell session that `watchtower terminal title` AI-names from its first owner messages — launched as `claude --session-id <uuid>` and relaunched with `--resume` only when `~/.claude` holds its transcript (never `CLAUDE_CONFIG_DIR`, a dual path with Go `defaultTerminalClaudeDir`); SIGHUP → SIGKILL after 3 s, closed by `QuitCoordinator`). Both see the board through `watchtower mcp --project N` (**DEV-06**: writes only project N's rows, applied directly under `tools.Binding.DirectApply` with an `agent_actions` audit row, never an `External` tool; plain `watchtower mcp` stays read-only, DEV-01) and a `SessionStart` hook running `watchtower project brief --project N` (≤ 4000 chars, always exit 0).
- `watchtower integrate claude-code --project N` installs, locally and never committed: the `watchtower-project` skill (setup, plan = board, comment discipline; DEV-04 marker + digest), the hook merged into `.claude/settings.local.json` (a malformed file is left byte-identical and reported; a well-formed one has its keys re-sorted alphabetically by the merge — values byte-exact, so a diff of the file shows only that reordering), `claude mcp add --scope local watchtower-project`, and `.git/info/exclude` lines; `integrate remove --project N` undoes exactly those (**PROJ-04** never overwrites the owner's own content). `watchtower project create|list|show|board|import-docs|attach-doc|delete|brief`; `create` (and `import-docs <id>`, additive, idempotent, `--dry-run`) mechanically attaches the folder's root `README.md` plus `.md`/`.txt` files directly inside a `specs`/`plans` directory under `docs/` (`internal/projectdocs`, no AI, symlinks never followed, ≤ 50 new per run, README first then newest) as `project_documents.origin='import'` (migration `00083`; `agent` for `attach_document`, which also flips an imported or owner row to `agent` on re-attach; `owner` for the Desktop Documents pane's **Add Document…**, which runs `watchtower project attach-doc <id> <path>` — `attach_document`'s checks via `tools.ResolveProjectDocumentPath`, absolute paths allowed, an already attached path left untouched) — only an `agent` row is ever "revised": the Desktop badge, the document list's revised dot and the "ready for review" notification skip `import` and `owner` rows until an agent re-attach turns them `agent`; a path below `docs/` it cannot read is skipped and reported (`unreadable`, `<rel_path>: <reason>`), only an unreadable folder or `docs/` fails the import, and `create --json` reports a failed import in `docs_import_ok`/`docs_import_error` (the Desktop's project page shows a failed import, unreadable paths and files past the cap, each with the retry command); board targets carry `priority` (`create_targets`/`update_target`), and board siblings sort by priority, then status (the brief lists subtrees holding in-progress, then blocked work first, keeping priority order within a rank, so the 4000-char cut never drops active work); `delete` runs the removal first and deletes rows in one transaction (**PROJ-02** nothing left behind).
- Desktop: sidebar **Projects** tab (list + badge = unread agent comments + revised documents) with a collapsible, resizable (`projects.panelWidth`) two-level panel (projects + standalone **Terminals** → one project's sessions, in a stable drag-reorderable order, `TerminalSessionOrder`; the page header's **Terminal | Board | Documents** toggles — `ProjectsViewModel.showView`/`hideView` over `WorkspaceLayout.isShowing`/`showProjectView`/`hide` — put a view on screen without hiding the terminal (Terminal: a session already in a slot, else the live one, else `openMostRecentSession` with `keeping`), and turning one off closes that pane of a split; in a split each pane's slim header also picks what it shows; a single pane has no header, so the terminal gets the height). The project page renders a per-project `WorkspaceLayout` (WatchtowerCore, UserDefaults `projects.layout.<id>`; single pane, side-by-side split with a draggable divider, any pane expandable; both slots stay in the view tree while one is expanded so pane state survives) — the layout is the only record of what is on screen, and every session placement goes through `ProjectsViewModel.Placement` (`show` = panel click, `keeping` = Send comments/Open terminal/Work on it keep the pane they came from in a split (a single pane switches to the session), `replacing` = a pane's own picker, `inPlace` = buttons inside the pane). **Work on it** on a board card/detail (`WorkOnTargetButton` → `ProjectsViewModel.workOn`) opens the target's most recent session (`TerminalSessionPolicy.sessionForTarget`, resumed/reopened) or creates one titled after the target and launched with the fixed argv prompt `Work on target #<id> using the watchtower-project skill.` — the title never reaches argv. A standalone terminal (`terminal_sessions.project_id IS NULL`, Claude Code or a shell in Home or a chosen folder) gets no project MCP/hook and writes nothing to project tables; several may run, all closed on quit. Documents render in a selectable `NSTextView`; a comment anchors on the rendered plain text and is re-located on every file change by the pure `CommentAnchor` (exact quote → best prefix/suffix among duplicates → else `outdated`, never re-attached elsewhere); the Desktop never writes a project document (**PROJ-03**). The board edits status/priority/title with the `TargetQueries` mutators and orders siblings with `ProjectBoardOrder` (priority → status → id, a dual path with Go's `boardSiblingOrder`) and polls a fingerprint because agent writes come from another process. The Board pane also has a **List | Kanban** mode (`ProjectBoardKanban`, pure, WatchtowerCore): leaf targets only, one column per status (Done capped at the 10 most recently updated unless Show done; unknown statuses in an Other column), dragging a card sets its status through the same `ProjectBoardViewModel.setStatus(_:for:)` writer as the status menu, and the mode + parent filter are remembered per project in UserDefaults (`projects.boardMode.<id>`/`projects.boardKanbanFilter.<id>`). `ProjectsViewModel.deleteProject` closes the terminal, runs `project delete`, reloads; a project deleted from the CLI closes its terminal on the next reload. `ProjectNotificationCenter` (pure `ProjectNotificationPolicy`, 30 s poll, per-project watermark, bursts ≥ 3 coalesced, never the owner's own writes; `projects.notifications` default on) notifies on an agent question, a document ready for review, all comments answered, a target done.
- Briefing: `gatherProjects` adds a `=== PROJECTS ===` block (`briefing.daily` v8, before MEMORY REVISIONS, which stays last; project activity alone is enough for a briefing); a stored template whose `%s` count differs from the default falls back to the default.
- **Selection comments reach the agent as one owner turn (Phase 6, 2026-09-29):** the AI Chat's own artifact side panel gains the same idea — the owner selects a passage of a rendered artifact and drafts a comment (`chat_artifact_comments`, migration `00082`, Swift-written and Swift-read only; Go neither writes nor reads it and the assistant never sees a row directly), collects several, and **Send N comments** sends them as one ordinary owner chat message (`ArtifactCommentMessage`/`CommentBatchComposer`) — never one by one. Every open/sent comment re-anchors onto the artifact's next version at each panel reload: found → it moves onto that version, gone → `outdated`; a resolved comment only loses its highlight, and an `outdated` one is never silently re-attached even if its exact text reappears later. `ArtifactsContract` gains one line telling the assistant to answer with a new version of the same key, and CHAT-05's source scan is extended to the comment files (no process/CLI/network/session reference; adding a comment sends nothing). A finished assistant answer's **Quote in reply** opens it in a sheet built on the same `DocumentTextView`, and each selected passage joins a **pending quote batch** shown above the composer — nothing is sent per quote; the owner's own send carries the whole batch plus the typed text as one turn (`ChatQuoteReply`, the same `CommentBatchComposer` rule). Specs, plans and designs are review documents (#105): the skill attaches each and sets its review target `in_review` until the owner approves (a `Review: <title>` leaf for a plan or a sub-targeted feature, so the PROJ-05 rollup never overwrites it); the Documents list labels an agent document on an `in_review` target **In review** (`ProjectDocumentListItem.awaitingReview`) and `ProjectNotificationPolicy.readyDocuments` also announces a target the agent put in review ("awaits your review", same revision key; an owner's own move — the latest `target_status_history` actor — is not announced back; a pre-#105 persisted snapshot reads as review unknown, `reviewKnown`). The Documents list is grouped by kind (Specs / Plans / Docs / Imported, pure `ProjectDocumentGrouping`; collapsed groups and the title search live on `ProjectsViewModel`), and an open document offers a Contents menu from its rendered headings (`DocumentScrollTarget` on `DocumentTextView`). On a project document, selecting text shows a floating **Comment** button at the selection (plus "Comment…" in the context menu — the shared `CommentableDocumentText` over `DocumentTextView`, also used by the artifact panel, replacing both header Comment buttons; a composer opened on an older render refuses to save and keeps the typed text); a comment becomes an in-memory draft (`ProjectCommentDrafts`, owned by `ProjectsViewModel`: survives document/pane/tab switches, and a quit with drafts left asks first — no `project_comments` draft state, so no Go reader can leak one to the agent), highlighted and listed under Drafts, and **Send N comments to Claude** first writes every draft still on the text in one transaction (all or none, guarded against a double click; a lost-passage or emptied draft stays unsent and is named) and then types exactly one line — `Address the N open comments on <rel_path> (watchtower document <id>) using the watchtower-project skill.` — into the project's *running* embedded terminal, switches the page to the Terminal pane so the owner sees it land, and leaves it unsubmitted (`ProjectCommentPrompt`/`TerminalCenter.sendPrompt`): the owner presses Return themselves, because an auto-submitted Enter could confirm whatever the TUI happens to be showing (a permission dialog's highlighted default, a half-typed prompt) without the owner ever seeing it. It writes nothing to the DB and never starts a session, and a crafted `rel_path` can neither inject a newline nor any other control sequence (every control/newline scalar becomes a space, and none of the remaining bytes include a carriage return). With no running session the bar instead points at the next session's brief and offers **Open terminal**.
- **Status rollup (2026-09-30, PROJ-05):** a project parent's status follows its children — migration `00085`'s triggers (`targets_project_status_rollup_{ai,au,ad}`) re-derive it on every child insert/delete/status/parent change (all closed with a done → done, all dismissed → dismissed, every open child blocked → blocked, any in_progress|in_review|done → in_progress — in_review since 00086 — else todo; no children untouched) and walk up while a status changes, never re-deriving a dismissed ancestor, one recursive CTE per trigger so it needs no `recursive_triggers`; a parent's own update stands until a child changes, and the skill tells the agent never to set a parent's status.
- **Project sources scope search and the brief (2026-10-01, board #90):** in a project session `search_knowledge` resolves the project's `slack_channel`/`jira_project`/`confluence_space` sources (`tools.ProjectKnowledgeScope`: a channel id, `#name` or archive URL against `channels`; a project/issue key or browse URL; a space key or `/spaces/KEY`|`/display/KEY` URL — an unresolvable ref is skipped and named in the result's `scope_note`) into a `kb.Scope` and, by default, **boosts** it: `kb.Search` runs each query a second time restricted to the scope and fuses that list in too (an in-scope chunk outside the global top 50 is still retrieved, nothing outside is dropped), hits carry `in_scope`. `project_scope: only` hard-filters, `off` ignores the sources, an explicit `sources` filter applies on top of either; `project_scope` outside a project session, and `only` with a `sources` filter naming none of slack/jira/confluence, are refused. `project brief` gains a "Recent in project sources (last 14 days)" section (`kb.Recent`, ≤ 8 documents, ≤ 1200 runes) after the comments, only when neither the targets nor the comments were cut and at least one document fits, so it never takes their room ("nothing indexed yet" instead of "none." when the index holds nothing from those sources; queries bounded at 2 s, a failure is the section's one line plus stderr); the same change fixed a pre-existing ≤ 10-rune overflow of the 4000 cap when the board filled the budget exactly with no comments.
- **Project documents in search (2026-10-01, board #89, PROJ-08):** attached documents are indexed into kb as source `project_doc` (`internal/kb/source_project.go`: the file read from the folder — a regular file resolving inside it, symlinks followed, ≤ 2 MiB (anchor `truncated` past it), split at `#`–`###` headings; anchor `project_id`/`document_id`/`rel_path`, link `file://…`; a gone/irregular/escaping file is title-only with anchor `unreadable`). Visible **only** in that project's own sessions: `kb.Request.ProjectID`/`kb.DocOptions.ProjectID`, filled from `tools.Binding.ProjectID` by `search_knowledge`/`get_knowledge_document`; every other caller passes 0 and sees none, and `sources: ["project_doc"]` outside a session is refused. Not boosted by `project_scope`. The daemon re-renders a document whose file mtime differs from the indexed one (no cursor — an older mtime counts too) and never reads a folder macOS guards (`privacyProtected`: `~/Documents`, `~/Desktop`, `~/Downloads`, `~/Library/CloudStorage`, `~/Library/Mobile Documents`, `/Volumes`, case-insensitive) nor follows a symlink out of a project folder (`resolveInside`); `kb.IndexProjectDocs(projectID)` — run by `project resync`, by `kb reindex` for every project, and by `attach_document` (`tools.ProjectTools(files, cfg.Knowledge.Enabled)`, best-effort: a failure is `index_warning` in the result) — indexes one project now, protected or not. `db.DeleteProject` drops the project's entries in its transaction (PROJ-02). v1 limit: in a protected folder, a document the owner adds or edits outside an agent attach becomes searchable at the next attach or Re-run Setup.
- **Re-run setup (2026-10-01, board #91):** `watchtower project resync <id> [--json]` (`cmd/project_resync.go`) brings an existing project up to the current setup, **additively**: `projectdocs.Import` (the `import-docs` rules) plus `devpack.InstallProject` (the `integrate claude-code --project` rules — PROJ-04: an edited skill stays `drifted`, settings merge; the MCP registration is removed and re-added, the Repair behaviour, so a moved binary is picked up), each step running even when the other failed. It never touches targets, statuses, comments, attached documents, sources or the description and never creates targets — it prints suggestions instead (setup when the description is empty, sources when there are none, a first board when it is empty, a look at newly attached documents). `--json` (`docs_ok`/`integration_ok` + errors, `suggestions_error`, `skill`, `hooks_added`, `excluded`, `mcp_registered`/`mcp_command`, `suggestions`) always exits 0 once the project is found, the `create --json` precedent; the text form exits non-zero on a failed step. Desktop: **Re-run Setup** in the project header (`ProjectsViewModel.resync`, result kept per project on the AppState-owned VM until dismissed, `ProjectResynced.summaryLines`; it and Repair share one per-project busy guard, since both run the folder install). The skill keeps pointing the agent at `import-docs` and has it suggest Re-run Setup to the owner rather than re-install the folder from inside its own session.
- **Review status + status history (2026-09-30, PROJ-06):** migration `00086` rebuilds `targets` (re-creating 00085's triggers) so a project target may be `in_review` (CHECK: project targets only; the rollup counts it as started) and adds `target_status_history`, written only by triggers on every project-target creation/status change with `actor` copied from a per-write `targets.status_actor` claim (`agent` = project MCP tools, `owner` = Desktop writers and anything unclaimed, `system` = the rollup, unsnooze and the Jira status sync), cleared again by the trigger; `get_target` (project session) returns `status_history`, and the CLI `project board`, the `project_board` tool and `project brief` show time in the current status (the Desktop only decodes the history — its UI is a later PR); a target that joins a project later starts its history at its next status change.
- **Board language (2026-10-01, board items #122 → #153):** the board always follows the session language — the language the owner uses with the agent, not the repo's. The brief and `project_info` carry one constant `Board language:` line (`tools.BoardLanguageLine`) and the skill's Board language section makes every session write targets/intents/comments in it (identifiers, paths, plan refs unchanged). The #122 per-project override was retired by #153: `watchtower project update`, MCP `update_project`'s `board_language`, the Desktop menu and the `terminal title` override are gone; the `projects.board_language` column (migration `00087`) stays but is never read (no migration to drop it). Advisory only — no write is refused for its language, nothing on the board is translated.
- **Target images (2026-10-01, board target #117):** `create_targets` items take `images` and `update_target` takes `add_images`/`remove_image_ids` — absolute paths the project MCP checks read-only before any row (`projectfiles.Check`: regular file, no symlink, PNG/JPEG/GIF/WebP by content sniff, ≤ 5 MB = the chat image cap), then copies into `<workspace>/project_files/<project_id>/<sha256>.<ext>` (0700/0600, `internal/projectfiles`, outside the folder so nothing is ever committed; one copy per content per project) and records in `project_target_images` (migration `00088`, UNIQUE(target_id, sha256), ≤ 20 per target) inside the same transaction as the target writes; a failed write discards the copies no row names. `get_target` lists them with the stored `path` (the agent can read it). PROJ-02: `project delete` removes the directory after the rows, `targets delete`/a detach discard copies nothing else names (`Store.Discard`, never a path outside the store). Desktop: read-only thumbnails in the board's target detail card (opened over the board, `ProjectTargetDetailCard`) (`ProjectTargetImagesSection`, ImageIO decode off the main actor via `ProjectImageLoader`), a click opens the full image in a sheet; the fingerprint poll covers attaches. The skill tells the agent to attach an image the owner shared in the message a target comes from. A failed write discards only the copies it created (`Image.Created`) and folds a cleanup failure into its error; `project delete --json`/`targets delete --json` report `files_ok`/`files_error`, which the Desktop surfaces. v1: no Desktop attach/detach; a pasted image with no file path cannot be attached (the skill asks the owner for the file); TCC attribution of an image read under `~/Desktop` from the embedded terminal, and a detach or failed write racing another session's reuse of the same copy, are listed in `docs/inventory/projects.md`'s v1 limits.
- **Board drift (2026-10-01, PROJ-07):** project targets carry optional `branch`/`pr` (migration `00089`, set by `create_targets`/`update_target`; a branch is the plain local name). `watchtower project check --project N [--json] [--stale-days 3] [--no-network]` (`internal/projectcheck`, mechanical, read-only git subcommands only, no git process outside a repository, never fetches) flags `merged_but_open` (merge commit; fast-forward of a local branch whose tip its reflog shows committed on it; `git cherry` rebase merge; squash by patch id; gh PR merged — a parent's fix points at its sub-targets), `done_but_unmerged` (done in the last 14 days, unless open work still carries the branch/PR), `branch_missing`, `pr_closed_unmerged` and `stale`; a failed git call or a deadline never becomes a finding (`incomplete`). `integrate claude-code --project N` also installs a `Stop` hook (`project check --project N --stop-hook`, offline, 8 s git budget — the DB open/migration is never cut off by it — always exit 0, panic recovered) that returns only the certain kinds (never `stale`/`done_but_unmerged`) as `{"decision":"block"}`, once per stop (`stop_hook_active` → silent); a deleted project's leftover hook is silent; delete/`integrate remove` take it away with the SessionStart hook. `project brief` shows every finding (4 s offline budget), and so does the Desktop board (`ProjectDriftBanner` over `ProjectsViewModel.refreshDrift` → `project check --json --no-network`, on appear/Refresh and every 30 s while the Board pane polls; a failed or partial check is shown as such); `integrate status --json` reports `stop_hook` and the Desktop offers Repair without it.
- v1 limits (accepted): an owner whose login shell sets `CLAUDE_CONFIG_DIR` gets no terminal-session resume (a relaunch offers Start fresh) and no AI session titles, since transcripts are read from `~/.claude` only; a folder under `~/Documents`, `~/Desktop`, `~/Downloads` or `~/Library/CloudStorage` makes macOS attribute Claude Code's file access to Watchtower (the New-project flow warns); `project_sources` scope search only through their Slack channels, Jira projects and Confluence spaces (people and links stay informational); no multi-agent locking.
