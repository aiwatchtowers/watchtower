# Workbench — Claude Code works a folder-bound board (2026-09-29, POC; renamed 2026-10-02)

- A **workbench** is a folder (table `projects`, migration `00081`; `folder_path` symlink-resolved and UNIQUE) with sources (`project_sources`), owner↔agent comments (`project_comments`: on a target, or a reply; roots `open|resolved|outdated`), the agent's asks to the owner (`owner_asks`, see **Owner asks**; until 2026-10-03 attached documents and document comments — see there) and a board of ordinary `targets` rows carrying `project_id` (`level='custom'`, `custom_label='project'`, `source_type='chat'`). Separate from the AI Chat's projects (`chat_projects`), which keep the name Projects. Until 2026-10-02 this feature was itself called Projects; see **Rename** below for what still says `project`.
- **PROJ-01:** a workbench target never reaches a non-board reader — `TargetFilter.WorkbenchID` 0 = exclude (the default for every existing caller), plus `project_id IS NULL` in next-step, briefing targets, counts, due-notify, catch-up, memory mirrors, day plan, channel stats and the extract/dedup snapshots; Swift `TargetQueries.fetchAll/fetchCounts/fetchDistinctTags` (so the Targets badge), the chat `@` picker, and "Wipe LLM data" (which would otherwise delete them as `source_type='chat'`).
- Work is done by Claude Code in the folder — the owner's own terminal or the Desktop's embedded SwiftTerm terminal (`TerminalCenter` on AppState, one process per `terminal_sessions` row — migration `00084`, a named claude/shell session that `watchtower terminal title` AI-names from its first owner messages — launched as `claude --session-id <uuid>` and relaunched with `--resume` only when `~/.claude` holds its transcript (never `CLAUDE_CONFIG_DIR`, a dual path with Go `defaultTerminalClaudeDir`); SIGHUP → SIGKILL after 3 s, closed by `QuitCoordinator`; a session is only running or not — there is no Close action (removed 2026-10-01; Delete… removes the row, and `terminal_sessions.closed_at` is a legacy column nothing reads or writes). Both see the board through `watchtower mcp --workbench N` (**DEV-06**: writes only workbench N's rows, applied directly under `tools.Binding.DirectApply` with an `agent_actions` audit row, never an `External` tool; plain `watchtower mcp` stays read-only, DEV-01) and a `SessionStart` hook running `watchtower workbench brief --workbench N` (≤ 4000 chars, always exit 0).
- `watchtower integrate claude-code --workbench N` installs, locally and never committed: the `watchtower-workbench` skill (setup, plan = board, comment discipline; DEV-04 marker + digest), the hook merged into `.claude/settings.local.json` (a malformed file is left byte-identical and reported; a well-formed one has its keys re-sorted alphabetically by the merge — values byte-exact, so a diff of the file shows only that reordering), `claude mcp add --scope local watchtower-workbench`, and `.git/info/exclude` lines; `integrate remove --workbench N` undoes exactly those (**PROJ-04** never overwrites the owner's own content). `watchtower workbench create|list|show|board|delete|brief|check|resync|git|ask-guard|session-state`; `create` indexes the folder's text files for the workbench's own search at once (PROJ-08; best-effort when `knowledge.enabled` is on: `create --json` reports `index_ok`/`index_error`/`index_skipped`, and a failed index is also a stderr warning naming the retry — until 2026-10-03 `create` instead attached the README and the `docs/**/{specs,plans}` files as documents, and `import-docs`/`attach-doc` existed; both went with attached documents, see **Owner asks**); board targets carry `priority` (`create_targets`/`update_target`), and board siblings sort by priority, then status (the brief lists subtrees holding in-progress, then blocked work first, keeping priority order within a rank, so the 4000-char cut never drops active work); `delete` runs the removal first and deletes rows in one transaction (**PROJ-02** nothing left behind).
- Desktop: sidebar **Workbench** tab (list + badge = open asks + unread agent comments) with a collapsible, resizable (`projects.panelWidth`) two-level panel (**Workbenches** + standalone **Terminals** → one workbench's sessions, in a stable drag-reorderable order, `TerminalSessionOrder`; level 2's header is the workbench switcher (board #250, no Back button: `WorkbenchSwitcher`/`WorkbenchSwitcherPopover` over `WorkbenchQueries.switcherSummaries` + `WorkbenchSwitcherPresentation`, read when the popover opens; rows by latest session activity, live counts from `TerminalCenter`, never the DB; picking one = `WorkbenchesViewModel.switchTo` — drill in, open the live-focused session else the latest active, none → the page alone; popover labels **Find workbench**, **RECENT**, **New Workbench…** (the list's NSSavePanel flow) and **All Workbenches**; **All Workbenches** = `showAllWorkbenches` (⇧⌘O is Open Quickly's, ruling R26), which also shows the panel); the panel's visibility is `WorkbenchesViewModel.panelVisible` (UserDefaults `projects.panelVisible` through the injected `defaults`, default shown), toggled by the title row's sidebar button or ⌥⌘S; while it is hidden over a workbench page (`headerSwitcherWorkbench`) the title row carries `▦ <workbench> ▾ › ● <session> ▾` (board #251, variant H): the same `WorkbenchSwitcher`, then `SessionSwitcher`/`SessionSwitcherPopover` over `SessionSwitcherPresentation` (the session in focus = `headerSession`: the visible one, else the active one, else "No session"; rows in `orderedSessions` order with ⌘1…⌘9, **Find session** by title or `#id`, **New Session ⌘T**, **Show Sessions Panel ⌥⌘S**; a pick = `showSession(id:)`); ⌘1…⌘9 (`openSession(atShortcut:)`) and ⌘T (`newSessionOnPage`) are hidden title-row buttons enabled only on a workbench page (`hasWorkbenchPage`), acting on `selectedWorkbenchID` with the panel shown, hidden or at level 1 — no "waiting for an answer" state in v1 (running / not started only); the page header's **Terminal | Board | Files** toggles — `WorkbenchesViewModel.showView`/`hideView` over `WorkspaceLayout.isShowing`/`showWorkbenchView`/`hide` — put a view on screen without hiding the terminal (Terminal: a session already in a slot, else the live one, else `openMostRecentSession` with `keeping`), and turning one off closes that pane of a split; The workbench page renders a per-workbench `WorkspaceLayout` (WatchtowerCore, UserDefaults `projects.layout.<id>`; single pane, side-by-side split with a draggable divider, any pane expandable; both slots stay in the view tree while one is expanded so pane state survives) — the layout is the only record of what is on screen, and every session placement goes through `WorkbenchesViewModel.Placement` (`show` = panel click, `keeping` = the Terminal toggle and Work on it keep the pane they came from in a split (a single pane switches to the session), `replacing` = a pane's own picker, `inPlace` = buttons inside the pane). **Work on it** on a board card/detail (`WorkOnTargetButton` → `WorkbenchesViewModel.workOn`) opens the target's most recent session (`TerminalSessionPolicy.sessionForTarget`, resumed) or creates one titled after the target and launched with the fixed argv prompt `Work on target #<id> using the watchtower-workbench skill.` — the title never reaches argv. A standalone terminal (`terminal_sessions.project_id IS NULL`, Claude Code or a shell in Home or a chosen folder) gets no workbench MCP/hook and writes nothing to the workbench tables; several may run, all closed on quit. The Desktop writes a workbench folder file only through the Files editor's rules, and no workbench tool writes the folder (**PROJ-03**, amended 2026-10-03). The board edits status/priority/title with the `TargetQueries` mutators and orders siblings with `WorkbenchBoardOrder` (priority → status → id, a dual path with Go's `boardSiblingOrder`) and polls a fingerprint because agent writes come from another process. The Board pane also has a **List | Kanban** mode (`WorkbenchBoardKanban`, pure, WatchtowerCore): leaf targets only, one column per status (Done capped at the 10 most recently updated unless Show done; unknown statuses in an Other column), dragging a card sets its status through the same `WorkbenchBoardViewModel.setStatus(_:for:)` writer as the status menu, and the mode + parent filter are remembered per workbench in UserDefaults (`projects.boardMode.<id>`/`projects.boardKanbanFilter.<id>`). `WorkbenchesViewModel.deleteWorkbench` closes the terminal, runs `workbench delete`, reloads; a workbench deleted from the CLI closes its terminal on the next reload. `WorkbenchNotificationCenter` (pure `WorkbenchNotificationPolicy`, 30 s poll, per-workbench watermark, bursts ≥ 3 coalesced, never the owner's own writes; `projects.notifications` default on) notifies on an agent question (a target comment), a new open ask (`askOpened`, "Agent asks: <title>", see **Owner asks**), a target done and a proposal awaiting approval.
- Briefing: `gatherWorkbenches` adds a `=== WORKBENCHES ===` block (`briefing.daily` v9 — v8 called it `=== PROJECTS ===`; since v11 it also lists each workbench's open owner asks by title, `Open asks waiting for the owner (N)`, capped like the target lines; before MEMORY REVISIONS, which stays last; workbench activity alone is enough for a briefing); a stored template whose `%s` count differs from the default falls back to the default.

A finished assistant answer's **Quote in reply** opens it in a sheet built on the same `DocumentTextView`, and each selected passage joins a **pending quote batch** shown above the composer — nothing is sent per quote; the owner's own send carries the whole batch plus the typed text as one turn (`ChatQuoteReply`, the same `CommentBatchComposer` rule). - **Status rollup (2026-09-30, PROJ-05):** a workbench parent's status follows its children — migration `00085`'s triggers (`targets_project_status_rollup_{ai,au,ad}`) re-derive it on every child insert/delete/status/parent change (all closed with a done → done, all dismissed → dismissed, every open child blocked → blocked, any in_progress|in_review|done → in_progress — in_review since 00086 — else todo; no children untouched) and walk up while a status changes, never re-deriving a dismissed ancestor, one recursive CTE per trigger so it needs no `recursive_triggers`; a parent's own update stands until a child changes, and the skill tells the agent never to set a parent's status.
- **Workbench sources scope search and the brief (2026-10-01, board #90):** in a workbench session `search_knowledge` resolves the workbench's `slack_channel`/`jira_project`/`confluence_space` sources (`tools.WorkbenchKnowledgeScope`: a channel id, `#name` or archive URL against `channels`; a project/issue key or browse URL; a space key or `/spaces/KEY`|`/display/KEY` URL — an unresolvable ref is skipped and named in the result's `scope_note`) into a `kb.Scope` and, by default, **boosts** it: `kb.Search` runs each query a second time restricted to the scope and fuses that list in too (an in-scope chunk outside the global top 50 is still retrieved, nothing outside is dropped), hits carry `in_scope`. `workbench_scope: only` (deprecated alias `project_scope`, accepted; both together are refused) hard-filters, `off` ignores the sources, an explicit `sources` filter applies on top of either; `workbench_scope` outside a workbench session, and `only` with a `sources` filter naming none of slack/jira/confluence, are refused. `workbench brief` gains a "Recent in workbench sources (last 14 days)" section (`kb.Recent`, ≤ 8 documents, ≤ 1200 runes) after the comments, only when neither the targets nor the comments were cut and at least one document fits, so it never takes their room ("nothing indexed yet" instead of "none." when the index holds nothing from those sources; queries bounded at 2 s, a failure is the section's one line plus stderr); the same change fixed a pre-existing ≤ 10-rune overflow of the 4000 cap when the board filled the budget exactly with no comments.
- **Workbench folder in search (2026-10-01, board #89, PROJ-08; folder files since 2026-10-03):** every `.md`/`.markdown`/`.txt` file of the workbench folder that git does not ignore is indexed into kb as source `project_doc` — no attaching, no setup. `workbenchdocs.ListTextFiles` lists them: inside a repository (`gitbin.InsideRepository`) `git ls-files -z --cached --others --exclude-standard -- .` through `internal/workbenchgit`'s environment rules with a 5 s budget (no git installed → the walk), otherwise a walk that never follows symlinks; both skip the Go twin of `CodeFileTree.hiddenNames` (`.git`, `.build`, `node_modules`, `.claude/worktrees`, …) and the installed skill directories, list regular files only, and keep the 2000 newest by mtime (the cut is logged). A failed git run is an error for that pass (logged, entries kept), never an empty set. Indexing goes through the shared file-set mechanism (`internal/kb/fileset.go`, `kb.FileSet`/`kb.IndexFileSet`, meant to carry board #211's chat project files later): one `kb_documents` row per file keyed `wbdoc:<project_id>:<rel_path>`, title = the path, split at `#`–`###` headings, anchor `project_id`/`rel_path` (+ `unreadable`/`truncated`), link `file://…`, a regular file resolving inside the folder (symlinks followed inside it only), ≤ 2 MiB. Visible **only** in that workbench's own sessions: `kb.Request.WorkbenchID`/`kb.DocOptions.WorkbenchID`, filled from `tools.Binding.WorkbenchID` by `search_knowledge`/`get_knowledge_document`; every other caller passes 0 and sees none, and `sources: ["project_doc"]` outside a session is refused. Not boosted by `workbench_scope`. The daemon's knowledge phase lists every unprotected folder (`Changed` compares mtimes in either direction; `Keys` drops a file that left the listing — deleted or newly ignored), never reads a folder macOS guards (`privacyProtected`: `~/Documents`, `~/Desktop`, `~/Downloads`, `~/Library/CloudStorage`, `~/Library/Mobile Documents`, `/Volumes`, case-insensitive; their entries are kept) and skips a deleted folder quietly. `kb.IndexWorkbenchDocs(workbenchID)` indexes one workbench now, protected or not, rendering every listed file gated by its content hash (so an edit in the same second as the last index is never missed) and dropping the entries of files no longer listed — run by `workbench resync`, `workbench create` (best-effort when knowledge is on) and `kb reindex` for every workbench (one failing folder no longer stops the others); `ask_owner` with a `doc_path` indexes that one file (`index_warning` on failure). Chunking happens before the write transaction (`prepareDoc`), so a 2 MiB file never holds the write lock. `db.DeleteWorkbench` drops the workbench's entries in its transaction (PROJ-02). Migration `00100` deleted the pre-2026-10-03 `project_doc` entries. v1 limit: in a protected folder, a file edited on disk becomes searchable at the next Re-run Setup, `kb reindex` or review ask naming it.
- **Re-run setup (2026-10-01, board #91):** `watchtower workbench resync <id> [--json]` (`cmd/workbench_resync.go`) brings an existing workbench up to the current setup, **additively**: the folder's search index (`kb.IndexWorkbenchDocs`, PROJ-08; until 2026-10-03 the document import) plus `devpack.InstallWorkbench` (the `integrate claude-code --workbench` rules — PROJ-04: an edited skill stays `drifted`, settings merge; the MCP registration is removed and re-added, the Repair behaviour, so a moved binary is picked up), each step running even when the other failed; since the rename it also migrates a pre-rename folder (see **Rename**). - **New Workbench… vs Add Existing Folder… (2026-10-01, board #158):** the panel header's + is a menu. **Add Existing Folder…** is the original NSOpenPanel flow (`name: nil`, the CLI names the workbench after the folder). **New Workbench…** is an NSSavePanel ("Workbench name:", starts in `~/Projects` when it exists, else home) whose entered name is both the folder and the workbench name; `NewWorkbenchFolder` (WatchtowerCore) `check`s it read-only (absent → create, empty but for `.DS_Store` → reuse, a file or non-empty folder → refused with the error line under the list), the `WorkbenchFolderPolicy` TCC warning runs next, and only then `prepare` creates the folder (non-intermediate, re-checked) and `createWorkbench(folder:name:)` runs — so "Choose another folder" leaves nothing on disk. - **Board drift (2026-10-01, PROJ-07):** workbench targets carry optional `branch`/`pr` (migration `00089`, set by `create_targets`/`update_target`; a branch is the plain local name). `watchtower workbench check --workbench N [--json] [--stale-days 3] [--no-network]` (`internal/workbenchcheck`, mechanical, read-only git subcommands only, no git process outside a repository, git located by `internal/gitbin` — never PATH or the `/usr/bin/git` shim; none found → `git:false`, a note, no git or gh process — never fetches) flags `merged_but_open` (merge commit; fast-forward of a local branch whose tip its reflog shows committed on it; `git cherry` rebase merge; squash by patch id; gh PR merged — a parent's fix points at its sub-targets), `done_but_unmerged` (done in the last 14 days, unless open work still carries the branch/PR), `branch_missing`, `pr_closed_unmerged` and `stale`; a failed git call or a deadline never becomes a finding (`incomplete`). `integrate claude-code --workbench N` also installs a `Stop` hook (`workbench check --workbench N --stop-hook`, offline, 8 s git budget — the DB open/migration is never cut off by it — always exit 0, panic recovered) that returns only the certain kinds (never `stale`/`done_but_unmerged`) as `{"decision":"block"}`, once per stop (`stop_hook_active` → silent); a deleted workbench's leftover hook is silent; delete/`integrate remove` take it away with the SessionStart hook. `workbench brief` shows every finding (4 s offline budget), and so does the Desktop board (`WorkbenchDriftBanner` over `WorkbenchesViewModel.refreshDrift` → `workbench check --json --no-network`, on appear/Refresh and every 30 s while the Board pane polls; a failed or partial check is shown as such); `integrate status --json` reports `stop_hook` and the Desktop offers Repair without it.
- **Terminal session follows `/clear` (2026-10-01, board #160):** `/clear` (and a resume that lands on another conversation) moves Claude Code to a new session id, while the Desktop relaunched the id the row was created with — after `/clear` + an app restart the owner was back in the pre-clear conversation. `TerminalCenter` now starts every `claude` row's process with `WATCHTOWER_TERMINAL_SESSION_ID=<row id>` (`TerminalLaunch.sessionRowEnv`, a dual path with Go `terminalSessionEnv`), and the workbench's existing `SessionStart` hook (`workbench brief --workbench N`, or `project brief --project N` in a folder not resynced since the rename; command line unchanged by this change — no reinstall) reads Claude Code's stdin payload when that variable is set: for `source` `clear`, `compact`, `resume` or `fork` with a canonical lowercase UUID it stores `session_id` on the row (`db.SetTerminalClaudeSessionID`: that workbench's `claude` row only, the same column write as the Desktop's `replaceClaudeSessionID`; read first, so the common resume of the stored id never takes the write lock, and a 1 s lock wait). `startup` is ignored — the launch id is already stored, and a nested headless `claude -p` the agent runs inherits the variable.
