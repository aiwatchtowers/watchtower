# HTML artifacts and previews (2026-10-17, board #535)

HTML the owner wants to look at — a slide deck, a visual report — renders in the app and opens in the browser, whether the assistant wrote it as a chat artifact or an agent wrote an `.html` file into a workbench folder.

## Pieces

- **Artifact kind `html`.** The Go prompt's `ArtifactsContract` (`internal/chat/artifacts_contract.go`) teaches it: one complete, self-contained page, CSS/JS inline, images as `data:` URLs, arrow keys for a deck. The shared fixture `internal/chat/artifacts_examples.md` gains an html example, so Go (`TestArtifactsContract_EmbedsTheSharedExamples`) and Swift (`ArtifactContractFixtureTests`) pin the same grammar. Swift `ArtifactParser.knownKinds` gains `html`, and like `code` an html body never tracks inner ``` fences. Migration `00129` widens the `chat_artifacts.kind` CHECK (table recreation; the Down maps `html` rows to `document`). Export writes `.html`.
- **Panel.** A complete html version renders in `SandboxedHTMLView` (`Views/Common/SandboxedHTMLView.swift`); a version still streaming shows its source. Toolbar: Edit, Copy, Export… plus **Reload**, **Open in Window**, **Present** (the window, full screen at once; Esc leaves full screen) and **Open in Browser**. No passage comments on html (the Comments toggle is hidden; the rendered page has no text anchor).
- **Code viewer.** An active `.html`/`.htm` tab gets **Source | Preview** (`Views/Workbench/CodeHTMLPreview.swift`). Preview overlays the web view on the still-mounted Monaco editor, loads the file with `loadFileURL(_:allowingReadAccessTo:)` scoped to the file's folder, and loads again on every `CodeFileBuffer.diskText` change (autosave, or another process writing the file through the existing watcher) and on Reload. It shows the disk version, so an unsaved edit appears after its autosave. Resources outside the file's folder do not load.
- **`SandboxedHTMLView`.** `WKWebsiteDataStore.nonPersistent()`, no `WKScriptMessageHandler` (no bridge), no UI delegate (`window.open` and dialogs do nothing), JavaScript and element full screen on. Nothing loads until a content rule list (`HTMLPreviewPolicy.contentRules`) is installed: block `.*`, then let back only `about:`/`data:`/`blob:`, plus `file:` in file mode. A rule list that does not compile shows a fixed message instead of the page (fail closed). Every navigation goes through `HTMLPreviewPolicy.allowsNavigation`: only the page itself (any fragment), `about:` documents, and in file mode a subframe under the folder. A clicked link or `location = …` is cancelled. The panel does not take keyboard focus on load (the owner may be typing in the composer); the window and the code preview do, so the arrow keys reach a deck at once.
- **`LocalPreviewServer`** (WatchtowerCore, Network.framework). One per app, started by the first **Open in Browser**, stopped on quit (`TrayAppDelegate`'s quit path, beside the terminals). `NWListener` with `requiredLocalEndpoint` 127.0.0.1, port `.any`, `acceptLocalOnly`. Each registration (`chat:<conversation>:<key>` serves one page from memory as `index.html`; `folder:<path>` serves a folder) gets a 32-byte random hex token as the first path segment; registering the same id again keeps its token and replaces the content, so a browser refresh after a second click shows the newer version. `unregister(id:)` removes one; `stop()` forgets all. The pure half is `LocalPreviewHTTP` (`LocalPreviewRouting.swift`): request-line parsing (16 KB header cap, origin-form targets only, HTTP/1.0 and 1.1), GET/HEAD only (405 with `Allow`), token routing (an unknown token is 404), percent-decoding per segment, `resolve` (no empty, `.`, `..` or dot-prefixed segment, no separator or NUL inside one, the symlink-resolved file must lie under the symlink-resolved root, regular files only, so no directory listing), a content-type table, and `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Connection: close` on every reply. A chat page also carries `Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; form-action 'none'; base-uri 'none'`. A folder file gets no CSP: it is the owner's own file, which they could open from Finder just as well.

## Threat model

HTML in a chat artifact can come from synced data (a Slack message, a mail, a Jira issue) through a prompt injection, and an agent-written file is no more trusted. The assumptions:

- **In the app the page runs JavaScript but reaches nothing.** No network load of any scheme but `about:`/`data:`/`blob:` (and the preview folder's files), no bridge to Swift, no persistent storage, no new windows, no navigation away. It cannot exfiltrate what it renders or read the owner's other files: in file mode WebKit limits reads to the file's folder.
- **In the browser a chat page cannot fetch either.** The CSP denies every fetch, XHR, WebSocket, form, image or font from anywhere, so the browser view keeps the in-app guarantee (a clicked link can still navigate the tab, with no Referer; that is the owner's own click in their browser).
- **The loopback server is not a door.** It binds 127.0.0.1 only and accepts local connections only. A process or web page on the machine that does not know a registration's 256-bit token gets 404, and a known token reaches only that registration's page or folder, never `..`, a dot-file or a symlink out of it. GET/HEAD only, so nothing can be written through it. Content lives until quit (or `unregister`), never on disk.
- **CHAT-05 holds.** No html action sends anything to an external system. `ArtifactChat05ScanTests` additionally scans `SandboxedHTMLView.swift`, `HTMLPreviewPolicy.swift` and `LocalPreviewRouting.swift`. `LocalPreviewServer.swift` is deliberately outside the scan: its reply uses `NWConnection.send`, but it only answers local requests and never opens a connection.

## Tests

`Tests/Core/LocalPreviewRoutingTests.swift` (parsing, wrong token, method not allowed, path traversal including encoded `..` and `%2F`, dot-files, directory requests, symlink escape vs. a link that stays inside, page CSP, registry tokens, content types); `Tests/Core/LocalPreviewServerTests.swift` (a live server on 127.0.0.1: GET, POST → 405, re-registration keeps the URL, unregister → 404, a file name with a space); `Tests/Core/HTMLPreviewPolicyTests.swift` (rule JSON shape, the rules compile in WebKit, navigation decisions in both modes); `Tests/SandboxedHTMLViewTests.swift` (an off-screen `SandboxedHTMLView` whose page `fetch`es a live loopback server is blocked, while the same page in a plain `WKWebView` reaches it — the control); `ArtifactParserTests.testHTMLKindIsKnownAndDoesNotTrackInnerFences`; `ArtifactContractFixtureTests`; Go `internal/chat` contract and prompt golden.

## v1 limits

- The browser does not live-reload; refresh by hand (a chat artifact refreshes onto a newer version only after **Open in Browser** is clicked again).
- A preview's resources outside the file's folder (`../assets/…`) do not load in the app or the browser.
- Links inside a page open nothing in the app.
- Html artifacts take no passage comments.
- Registrations are not removed before quit (a few in-memory pages at most).
