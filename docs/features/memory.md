# Memory (Phases 0–5 slice 4)

- `internal/memory/` — a durable memory vault at `Config.WorkspaceDir()/memory`: markdown nodes (entities/episodes/rollups/beliefs, YAML frontmatter + `[[id|label]]` wiki-links) in a go-git repo. **Files + git history are the source of truth**; the SQLite index (`memory_nodes`/`memory_aliases`/`memory_node_stats` + `memory_fts` FTS5) is derived and rebuildable via `watchtower memory reindex` (MEM-02). Obsidian can open the vault, but nothing requires it.
- Consolidation is a daemon phase (`phaseMemory`, after `phaseInbox`, before `phaseNextStep`), **off by default** (`memory.enabled`). `Pipeline.Run` order (`pipeline.go`): owner-edit commit (MEM-03) → index reconcile → mechanical seeding (people/channels/Jira keys, no AI) → raw-text episode extraction (`memory.extract_episodes`, light tier, chunked per-channel windows against the `workspace.memory_last_extracted_ts` watermark, MEM-01/04) → **semantic tier** → mechanical `index.md` + `map.md` render. The daemon opens the vault lazily (`SetMemoryPipelineOpener`, wired by `cmd/memory.go`'s `wireMemoryPipeline`): while it will not open, each cycle records a failed `memory` pipeline_runs row (shown in Usage: `PipelineRunQueries.fetchByDate` lists a token-less failed run for `memory` only, other pipelines' token-less failures stay filtered) plus one log line, and retries the open next cycle — a transient failure at start no longer disables Memory until a restart.
- **Semantic tier (Phase 3, `memory.semantic.enabled`, dark by default)** in `runSemantic`: dedupe → concept promotion → strong-tier entity-page rewrite (`memory.entity_rewrite`) → belief pass (`memory.revise_beliefs`) → aging → eviction. Beliefs carry rank/hysteresis math (`belief_math.go`): the model only proposes ops; Go disposes (MEM-08). Owner-rank evidence protects a belief from auto-flip (MEM-06); eviction/merge never thin provenance (MEM-07). Strong-tier steps stop launching once output tokens pass `memory.semantic.output_budget`.
- **Surfaces (Phase 4), each dark by default behind `memory.surfaces.{chat,briefing,reflection}`** — the read/write-back layer on top of the semantic tier: (1) **chat** — the Desktop Discuss prompt gains a MEMORY block and owner turns typed in Discuss become owner-rank belief evidence (`chat_ingest.go` stages `role='user'` turns; the belief pass mints `- owner …` lines from validated `chat:<id>` refs). (2) **briefing** — `internal/briefing` adds a *Memory revisions* journal of notable belief transitions (`briefing.daily` v6). (3) **reflection** — a weekly strong-tier `memory.reflect` pass (`reflect.go`, tail of `runSemantic`, deterministic per-workspace stagger) over the vault git log + `## History` churn flags flapping beliefs and appends entity `## Current` notes.
- **Owner rank is code-authored, never model-inferred (MEM-09):** owner-rank evidence is minted only from `role='user'` chat turns or `memory(owner-edit)` commits; the belief-op JSON carries no rank field. **Memory never writes an inbox table (MEM-05/10):** it only sets the `memory_dispute_flags` side table — since the inbox demolition (2026-09-14) the `memory.surfaces.disputes` toggle, the inbox detector branch that minted `decision_made` items from them, and the Dashboard that rendered them are all gone, while the flag writers in the belief pass and `reflect.go` stay (belief math). The flags are still read for display only: the Desktop Memory sidebar badge (`MemoryQueries.fetchDisputedCount`) and the Memory views' dispute marker (the `LEFT JOIN memory_dispute_flags` in `MemoryQueries`, and Go's `DisputePending` on loaded nodes). **Surfaces are read-only over history (MEM-11):** the briefing journal and reflection never mutate a belief's confidence/status — reflection writes only dispute flags + entity `## Current` notes; all belief math flows through `applyBeliefOp`.
- **Universal substrate (Phase 5 slice 1)** — the enabling refactor plus two independently-dark sources. **Provenance-resolver registry (MEM-12, `provenance.go`):** every write-time provenance check routes through one `ProvenanceRegistry` (one `ProvenanceResolver` per ref scheme: `""`/message, `chat`, `mail`, `act`); a ref of an unregistered scheme is rejected at write, generalizing MEM-01 from two hardcoded checks. **Gmail source (`memory.sources.gmail`, default false, `gmail_extract.go`):** each Gmail thread → one episode with `mail:<message_id>` provenance, senders seed as person entities (email-alias identity stitching), own watermark `memory_gmail_last_extracted_ts` (a third watermark, distinct from Gmail sync + Slack extraction); prompt `memory.extract_email_episodes` (light tier). **The mechanical interaction ingest (`memory.sources.actions`, `action_ingest.go`) was removed on 2026-09-14** — all three of its sources died with the inbox demolition (see Attention detection and `docs/inventory/memory.md`'s 2026-09-14 entry). What it fed is deliberately kept but **now starves**: the `owner-action` rank (weight 0.8, between `observed` and `owner`, code-minted only for a validated `act:` ref and **non-protecting** — MEM-15, `hasFreshOwnerSupport` still keys on `rankOwner` only), the `act:` provenance scheme, `memory_engagement` + `RetentionInputs.Engagement`, and the 5D OWNER ACTIONS block. Open owner call: re-feed engagement from Catch-Up's per-topic 👍/👎, or demolish the rank/scheme/aggregate next.
- **Universal substrate (Phase 5 slice 2)** — a third independently-dark source plus a generalization, both extending existing contracts (no new numbered contract). **Calendar source (`memory.sources.calendar`, default false, `calendar_ingest.go`/`runCalendarIngest`, Run step 3b — mechanical, NO AI call):** one ended `calendar_events` row → at most one episode built from the structured row, with a `meeting_recaps` row folded into Story/Outcome where it exists (reused, never re-synthesized); idempotent via the `calevent:<event_id>` alias + content-equality no-op; recurring series → `calseries:<recurringEventId>` entities (`seedCalendarSeries`); own **fourth** watermark `memory_calendar_last_extracted_ts` with a 2-day bounded-lookback re-scan for late recaps against the sync's ~24 h retention. **MEM-12 extended** with a `cal` scheme resolver (`calResolver`/`CalendarEventExists`); the builder validates via a cal-only scoped registry. **Internal-dialogs generalization (`memory.sources.chats`, default false):** the Phase-4 situation-chat ingest widens to **target/track** Discuss chats — the allowed `context_type` set (`chatContextTypes`) is `{"situation"}` off (byte-identical to Phase 4, **MEM-09 unchanged**) and `{"situation","target","track"}` on, gating `ListOwnerChatTurns` and `chatResolver.contextTypes` in lockstep. **The "remember this" command** (`parseRememberCommand`, case-insensitive `remember:`/`remember this:`) is the opt-in staging trigger for target/track chats (an ordinary drafting turn there is consumed-not-staged); situation chats still stage every owner turn. **MEM-09 extended** — owner rank now also code-mints from a validated target/track `role='user'` turn (still authored, no new write author, MEM-11 preserved). Onboarding chats are out (never persisted).
- **Render-inversion begun (Phase 5 slice 3, dark compare-mode)** — the assistant is starting to render its digests from the memory substrate instead of raw messages. **Channel-digest render (`digest_render.go`/`renderChannelDigest`, prompt `memory.render_channel_digest`, cheap/haiku tier):** a Slack channel's digest rendered from the memory episodes overlapping a time window (episode Story/Outcome + provenance first, raw coverage-gap messages only for what the episodes miss), returning the legacy `digest_topics` JSON shape. **MEM-13 (render fidelity):** every `key_messages`/decision `message_ts` the model emits is kept only when episode-cited (in the input episodes' `## Provenance` set) or a resolving raw gap-message ts; an invented ref is dropped-and-counted (`render_refs_rejected`), never written — the hallucinated `key_messages` class dies by construction (memory 100% valid vs the audit's ~0.6% legacy). **Episode-window substrate:** a derived `memory_provenance(node_id, scheme, channel_id, ts_raw, ts_unix)` index (populated wholesale-per-node inside `UpsertMemoryNode`, one parse site `parseProvenanceRefs`, queried by `ListEpisodesForChannelWindow`) — rebuildable from files, so it lives **inside MEM-02** (the reindex-equivalence guard was extended to dump it) and is cleared by `DropMemoryIndex`. **Dark compare-mode (`digest_compare.go`/`CompareDigests`, behind `memory.renders.digest_compare`, default false, tail sub-step of `phaseMemory` after extraction):** for each recently legacy-digested channel it renders the window from episodes, writes the render + coverage + rejected-ref count to `memory_digest_shadow` (memory-owned side table, **never** `digests`/`digest_topics`), and computes a field-by-field diff (topic count, `key_messages` ref-validity, coverage, length ratio). `watchtower memory digest-compare [--since --out]` runs it on demand and writes a branch report. **The legacy digest pipeline is unchanged and stays authoritative** — the compare is a pure reader (MEM-05/14, proven by `TestDigestCompare_LegacyTablesByteIdentical`); the actual switch off legacy is a later slice, gated on the owner's hand-review.
- **Entity mirrors + read surfaces + preference beliefs (Phase 5 slice 4)** — **5C:** target/track entity mirrors (`mirror_ingest.go`/`runOperationalMirrors`, Run step 3c, mechanical, no AI call) alias targets and tracks into the vault as long-lived entities (`target:<id>`/`track:<id>`, `## Current` replaced wholesale each refresh, `## Open loops` — its first writer — populated while non-terminal and cleared on terminal, `## Links` conversion cross-links to the originating `situation:<id>` episode), gated `memory.sources.operational`; re-scan + content-equality with **no watermark** (small mutable tables, the `interactionRescanWindowDays` precedent) — **MEM-14 "mirror, don't absorb"**: memory never becomes the write path for `targets`/`tracks`/`day_plans`/`day_plan_items` (guard dumps them byte-identical across a full gates-on run). Two read surfaces copy the Phase-4 `gatherMemoryRevisions` shape verbatim: the **day plan** (`internal/dayplan`) folds memory open loops into `day_plan.generate` (v2→v3) behind `memory.surfaces.day_plan`, complementing (never duplicating) its direct `targets` read; **meeting prep** (`internal/meeting`'s `PrepareForEvent`) folds attendee entity pages + beliefs into `meeting.prep` (v3→v4) behind `memory.surfaces.meeting_prep`. Both are sentinel-gated prompt slots (gate off → a fixed placeholder string, byte-identical output, the `briefing.daily` v6 precedent) and pure readers — no vault write, no vault git-log move. `targetSubjects`/`trackSubjects` (`chat_ingest.go`) now also prepend a bare target/track Discuss chat's own mirror alias to its subject refs, so a chat with no linked track finally stages once its mirror exists (a no-op when mirrors are off). **5D semantic:** the ordinary belief pass (`ReviseBeliefs`) gains a gated **OWNER ACTIONS** user-message block (`memory.semantic.preferences`) rendering this run's staged `act:` interaction refs plus per-subject `GetEngagement` aggregates, so the model can propose preference beliefs about the owner ("the owner does not care about X-alerts") through the SAME propose-new/confirm/weaken/shake/retire ops and rank machinery — no new rank (reuses slice-1's `owner-action`, MEM-15 unchanged: still non-protecting, still keyed off `rankOwner` for fresh-owner support), no new prompt id (`memory.revise_beliefs` stays v1 — the block rides the user message like the OWNER SAID precedent, so gate-off is byte-identical).

CLI `cmd/memory.go`: `status`, `reindex`, `open <ref>`, `recall <query>`, `consolidate`, `index`, `seed [--dry-run]`, `digest-compare [--since --out]`, `reset-to <commit> [--dry-run]` (operator recovery: rewind the vault to an ancestor commit, reindex, fast-forward the extraction watermarks), `migrate-slack-ids [--dry-run]` (one-off bare→namespaced Slack-id backfill over vault aliases and `## Provenance` refs).
- **Staggered-step "done today" memo + confirm evidence dedupe (2026-09-13, migration 00069, audit finding H2/owner decision 9):** `dueForRewrite`/`dueForReflect` are day-granular but STATELESS, so on a node's/workspace's slot day they answered "due" on every daemon cycle — the same first `rewrite_max_entities` pages (`ListMemoryNodes` is `ORDER BY id`) were re-rewritten by the strong model every ~70 minutes, the weekly `memory.reflect` pass re-ran end to end all slot day, and the strong map render had no gate on its AI call at all (only its file write was change-gated). `memory_step_state(step, node_id)` now memoes all three: rewrite/reflect stamp `last_run_at` **on attempt, not success** (an outage must not retry every cycle; reflect's vault commit can't serve as its own memo since a dispute-only or calm run writes none), map stamps a sha256 `fingerprint` of its rendered prompt input **on success only** (a failure leaves the input unchanged — a legitimate retry) and re-renders if `map.md` itself goes missing even on a fingerprint match. No new config key; the memo is **MEM-02-exempt** like `memory_engagement`/`memory_entity_hints` — see the amended exclusion sentence below. **Cost note:** the memo also ends a starvation bug (every due entity past the per-cycle cap in the `ORDER BY id` scan was never rewritten at all), so steady state becomes "every eligible entity once per 7 days" — on a large vault the *daily* strong-tier call count can rise; the saving is the repeats, not the total. Separately, `applyExistingOp` (`internal/memory/beliefs.go`) now drops a `confirm` op outright as a no-op (`applied=false`, `mathRejected=false`) when every evidence ref it cites is already a stored `## Evidence` line (`filterNewEvidence`, keyed on the whole rendered line — rank/direction/channel/ts, never a prefix or substring scan) — closing a loop where a daemon-cycle re-citation bought `Stability++`/`+0.1` confidence with no new `## Evidence` line, made a belief practically un-retirable, and produced a real `memory(beliefs)` commit that `reflectChurn` read as "flapping." Because `opConfirm` also sets `Status = statusActive`, this no-op has a second-order effect worth naming: a **shaken** belief re-confirmed from only-already-recorded evidence now stays shaken rather than reactivating (the op never reaches `applyOp` at all). For every op (not just `confirm`), a re-cited ref is also no longer weighed twice in `combined` — `retire`'s `flipSupported` used to double-count a duplicated evidence line, making a flip strictly easier than the stability hysteresis intends; deduping makes flips **harder**, never easier, so MEM-06 stays bit-identical. **Widened to `weaken` in wave 5 (2026-09-14, owner decision 9's flagged follow-up):** `applyExistingOp`'s no-op gate now covers `opConfirm || opWeaken` — a `weaken` citing only already-recorded evidence was applying an unconditional `-0.1` confidence step (touching only `Confidence`, no `Status`/`Stability`, so no retire/flip path is affected) from zero new information, the same manufactured-churn shape `confirm` had. `shake` (a real active→shaken status transition from zero new evidence, an owner-visible behavior change) and `retire` (already evidence-gated, never had the unconditional shape) are deliberately left as their own open item — see the audit README's wave 5 left-open list. **`shake` widened on 2026-09-23 (owner decision):** the gate now covers `opConfirm || opWeaken || opShake` — a `shake` citing only already-recorded evidence is now a no-op too (no status flip, no `## History` line, no commit), the same fix shape as `weaken`. Only `retire` stays out, unchanged.
