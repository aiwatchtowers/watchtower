# Jira status history + time in status (2026-10-02, board #185)

Spec: `docs/superpowers/specs/2026-10-02-jira-changelog-design.md`. The company keeps no Jira worklogs, so "time spent" questions are answered from the status/assignee history. No UI by owner decision: the data plus two read-only chat tools; the model does the arithmetic.

- **Tables (migration 00095).** `jira_issue_changelog` (one row per changed `status`/`assignee` field of one change history; for status `*_value` = status id and `*_string` = name, for assignee the account id and display name; replaced per issue as a whole), `jira_changelog_sync` (per-issue cursor: the issue `updated_at` the stored history belongs to — an issue is due when it has no row or its `updated_at` moved), `jira_linked_issues` (slim snapshot of link targets that are **not** in `jira_issues`; `fetch_error` for a key the site would not return). All account-scoped with `ON DELETE CASCADE`; timestamps in `db.FormatJiraTime` UTC. Linked issues stay **out of `jira_issues` on purpose** — its ~47 readers (dashboards, workload, inbox Jira detector, memory, ideas, knowledge index, briefing) must not start seeing other teams' issues.
- **Sync (`internal/jira/changelog.go`).** `Syncer.syncHistory` runs at the end of `Syncer.Sync`, after issues/sprints/releases: prune linked rows now in `jira_issues` or no longer linked (the unlinked ones lose their history too), refresh up to 200 linked issues per pass (never-fetched first, then oldest `synced_at`) with `POST /rest/api/3/issue/bulkfetch`, then fetch the history of up to `jira.changelog_issues_per_sync` (default 500, `0` = off; the syncer's own default is 0) due issues, newest `updated_at` first, via `POST /rest/api/3/changelog/bulkfetch` (`fieldIds: status, assignee`, 100 issues per request, follows `nextPageToken`, 50-page guard that stores nothing). Only `ErrAuthRevoked`/cancellation leave the step; anything else is logged and keeps the cursors. It never touches the project watermark.
- **API cost.** Steady state per account per 15-min pass: ~1 changelog request per 100 changed issues + ≤2 linked-issue requests. Backfill: 5 changelog requests per pass (+ pages for long histories), so ~10 passes for 5 000 issues. Scope `read:jira-work` (already granted).
- **Tools (`internal/tools/jira_history.go`, in `ReadTools()` → main chat, project MCP, dev MCP).** `get_jira_status_history` (≤50 keys: events with author/time, derived intervals, `history` = `synced`/`stale`/`missing`); `get_jira_time_in_status` (board/project/keys, `include_linked` default true, assignee/status filters, done category left out by default, `since`/`until` default last 30 days; totals per (assignee, status), per assignee, raw clipped intervals). Every answer carries `note`: wall-clock time in status, **not hours worked**. Reconstruction: timeline starts at `created_at`, the state before the first change of a field is that change's `from` (no change → current value). An issue without synced history is excluded and listed; done issues last updated before `since` are skipped.
- **Links are replaced per issue.** `UpsertJiraIssueBatch` now deletes an issue's `jira_issue_links` rows (by `source_key`) before writing its current links, so a link removed in Jira goes away on the issue's next sync; before, the table only grew. A link shared by two synced issues is stored once, owned by the side written last, so link expansion follows both directions.
- **Limits (v1).** Wall-clock only (no business hours); one hop of links (no parent/epic/sub-task); bare-key ambiguity across two sites as in `get_jira_issue` (`account_id` narrows); history of an issue that left the selected boards is kept until the account is deleted; a moved linked issue stays invisible until the issue linking to it changes for some other reason and re-syncs (moving the target does not touch it; an issue returned under an unrequested key is dropped, not stored); links that were already stale before this change stay until their source issue changes again (no one-time cleanup); a status seen only in history has no category (`statuses_without_category`); `watchtower jira sync` (manual) skips the history step, like comment sync.
