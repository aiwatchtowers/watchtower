# Knowledge search (2026-09-26)

- `internal/kb/` is a derived, mechanical FTS5 index (migration `00072`: `kb_documents`/`kb_chunks`/`kb_fts` porter+unicode61, `kb_sources` cursors) over Slack threads/channel-days, Gmail/IMAP threads, Jira issues+comments, calendar events, meeting transcripts, meeting recaps, digest topics, stream-digest topics, ideas/decisions and attached workbench documents (`project_doc`, visible only in their own workbench's sessions — PROJ-08, see `workbench.md`) — never memory (`memory_fts`/`memory_recall` stay separate). Each source renders title+meta+ordered sections packed into ≤2000-rune chunks (`ChunkChars`), gated by a content hash (unchanged render = no write).
- Daemon phase `phaseKnowledgeIndex` (after `phaseTranscriptAudioCleanup`, gated `knowledge.enabled`, mechanical/no AI — KB-02) runs `kb.Run` with a 60s per-cycle budget checked only between a source's change-ranges (a range already in flight completes regardless, so overshoot is bounded to one range's render time — never livelocks); per-source cursors (Slack `messages.rowid` in 20k ranges plus a 48h tail rescan for in-place edits/deletes, others by `updated_at`/`synced_at`/`created_at`) resume incrementally (marker cursors compare with `>=`, so a same-second write is never missed; the hash gate keeps re-listing free), and a reconcile deletes ids the source no longer reports — every cycle for the small sources, once per UTC day for Slack, so deletions leave search within one cycle (Slack: within a day). Every Slack reply row also marks its thread root's channel-day, so a promoted root leaves its day document. A title-only document is indexed as its title; only a nil `Build` means gone. A daemon shutdown mid-cycle (`isBenignShutdownErr`) is not recorded as a pipeline error.
- Search (`kb.Search`): per query, AND-match the top 50 chunks by `bm25(kb_fts, 4.0, 1.0, 2.0)` (title/body/meta weights), OR-fallback when AND is sparse, fuse across all queries via weighted RRF (k=50, AND 1.0 / OR 0.5), group to documents, rank by fused score × recency (`max(1/(1+0.5·age_years), 0.75)`).
- Surfaces: MCP/registry read tools `search_knowledge`/`get_knowledge_document` (`internal/tools/knowledge.go`, `AccessRead`; a hit carries its best `chunk` + `chunk_anchor`, and `get_knowledge_document` opens at `from_chunk`, `max_chars` capped at 50000); CLI `watchtower kb status|reindex|search` (`kb reindex` refuses while the sync daemon runs, unless `--force`); chat prompts point topical questions at `search_knowledge` first (Go `internal/ai/prompt.go` + the five Swift chat prompt copies — the usual dual-path) and link a hit via its `link` permalink or, for a Slack message, `anchor.channel_id` minus its `N:` prefix + `anchor.thread_ts`/`chunk_anchor` (Go prompt ↔ Swift `ChatViewModel.knowledgeLinkRule`). Search results say "slack NN% indexed" only during a real backfill (index behind sync by more than one 20k range); `kb status` shows the exact figure.
- Feature `knowledge-search` (`CostNone`, config `knowledge.enabled`, default **true**); off = no indexing, existing index stays readable (FEAT-01/02); no fast-forward hook — re-enabling just resumes from the stored cursors (FEAT-03 concerns AI-cost backfills, not this).
- v1 limits (accepted): no vectors; a Slack in-place edit/delete older than the 48h tail is caught only by `kb reindex`; every non-Slack source is one change-range (its first backfill can overshoot the cycle budget by the whole source); memory is not indexed. A batch is rendered before its write transaction opens (`buildBatch`, then `storeBatch` in the tx), so indexing never holds SQLite's write lock through the renders. Contracts KB-01..03: `docs/inventory/knowledge-search.md`.
