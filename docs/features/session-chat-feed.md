# Session chat feed — the dialog of a workbench session (2026-10-16, phases 1-3)

Spec: `docs/superpowers/specs/2026-10-16-session-chat-feed-design.md`. Contracts: FEED-01..05 in [docs/inventory/session-feed.md](../inventory/session-feed.md).

A workbench session's transcript holds hundreds of tool calls; the owner wants the conversation only. The feed is built on demand by a deterministic Go reader from the Claude Code transcript JSONL. No AI call, no transcript text stored anywhere, nothing written to the transcript files.

The Desktop runs the CLI with `--json` and decodes it; there is no Swift twin of the filter rules (the Go reader is the only parser).

## Entry kinds (agent-neutral)

`owner`, `agent`, `ask_answer`, `watchtower` (`via` = `review` or `handoff`), `brief`, `subagent`, `separator`, `event` (`event_type` = `task` or `teammate`; `title` and `text`). Every entry has a stable `id`, an `at` time, `text` and the tab's `conversation` (agent session id).

Record rules (`parse.go`):
- `user` records with string or `text` content are `owner`. Dropped: `isMeta`, `isCompactSummary`, any record holding a `tool_result` block, `<local-command…>` wrappers, `[Request interrupted…` lines, and sidechain records outside a subagent file. `<system-reminder>` blocks are stripped; images become `[image]` (unless the text already has an `[Image #N]` marker); a slash command becomes `/name args`.
- A `user` record whose text starts with `<task-notification>` or `<teammate-message …>` is an `event`, not an owner line (a task notification: title = `<summary>`, text = one `tag: value` line per child; a teammate message: title = the `summary="…"` attribute, text = the body; fallback title = first non-empty text line, else `Notice`, capped at 200 runes). Owner text before a wrapper keeps the record an `owner` line. The phone drops `event` entries: its slice keeps only `SessionFeedEntry.phoneKinds`.
- `Ask #N answered …` is `ask_answer`; the CLI joins it to `owner_asks` (title and answer text), **only for an ask of the session's own workbench** (FEED-04). An ask that cannot be read keeps the bare typed line.
- `Review round #…` and `From a Watchtower code question:` lines are `watchtower` entries (`via` review / handoff). Hook feedback is not a chat line and is dropped with the meta records.
- The start brief is not a `user` record: it is an `attachment` with `hookEvent` `SessionStart` whose `stdout` starts `Watchtower workbench #`; other SessionStart outputs are dropped. One collapsed `brief` entry.
- `assistant` records: only `text` blocks, one entry per message id, the last streamed version wins. `tool_use` and `thinking` never reach the feed (FEED-02).
- An `Agent` tool call becomes one `subagent` marker (type, description, status). Unknown record types are counted in `unknown_records`, never shown; an overlong line (over 8 MiB) or invalid JSON is skipped and counted in `skipped`; a final line without `\n` is left for the next read.

## Cursor and upsert contract

The cursor is `<agent session id>:<byte offset after the last complete line>`. `--after C` returns the entries that follow it; an entry whose message grew after the cursor is re-emitted with the same `id` and the new text, so a caller upserts by id (the Desktop store does). A poll reads only the tail after the cursor: the cursor's conversation is parsed from its offset, later conversations from 0, earlier ones not at all. `subagents` lists every subagent marker of the tab and comes from the sidecar `subagents/*.meta.json` files (tool use id, type, description, finished), not from a transcript parse.

## Subagents

`--subagent T` prints the feed of the subagent started by tool call `T`, read whole (empty cursor): its task as the first entry, its text replies, then the final report. A foreground subagent's report is the parent's `tool_result` for the `Agent` call; a background one reports through its `SubagentHandback` call (text in `input.message`). A background subagent without a hand-back has no report (the parent's result is only a launch notice). Nested subagents open the same way: the Desktop opens the feed in place in the pane (`SessionChatPath`), and a nested marker inside it opens one level deeper.

## The ledger (migration 00127)

`terminal_sessions.claude_session_id` holds only the latest id (`/clear` and resume swap it). `terminal_session_agent_sessions (terminal_session_id, agent_session_id, first_seen_at)` keeps every id the tab had, so the feed stitches the tab's transcripts in time order with a `separator` entry where a new conversation starts. Ids and times only, no text (FEED-01); rows cascade with the tab.

The rows are written by **SQL triggers on `terminal_sessions`** (`AFTER INSERT` and `AFTER UPDATE OF claude_session_id`), not by Go code: the creating INSERT is in Swift (`TerminalSessionQueries.create`), and a trigger is the one place that sees every write path. Consequences:
- A future migration that **recreates `terminal_sessions`** (the SQLite table-recreation dance) must recreate both triggers (`terminal_session_agent_sessions_ai`, `_au`), or the ledger silently stops filling.
- `internal/db/schema.sql` mirrors the table but not the triggers (only a comment points at 00127).
- The migration backfills one row per existing tab with an id (`created_at` as `first_seen_at`).

Locating transcripts: `LocateAll` lists the workbench's candidate directories (`agentlog.CandidateDirs`, worktrees included) under `<claude dir>/projects` once per call and resolves every ledger id from that one listing. A missing transcript is skipped, not an error.

## Entry points in the app

The pane is the session's **Workchat** (#711), its second mode beside the terminal (`WorkspacePane.sessionChat`/`WorkspaceView.chat` keep their raw names, so saved layouts stay valid; only titles changed):

- **Session strip toggle** (`WorkbenchSessionStrip`, since 2026-10-20, board #788; polish 2026-10-21, #846 made it one button): one button naming the mode it switches to (Terminal ↔ Workchat) swaps that pane in place — same session, same slot (`WorkspaceLayout.toggleMode`), in a single pane and in a split alike. Over a report or Branch review pane it names the session's remembered mode; it is disabled when that mode already shows in the other pane. ⌃` is unchanged. The strip's `● session ▾` menu replaces its own slot. The Board, Files and Analytics panes' pickers in a split list **Workchat**.
- **⌃`** and View → **Show Terminal** / **Show Workchat** (`WorkchatCommands`, one item titled by the mode it switches to, on while a workbench page shows a session): `WorkbenchesViewModel.toggleWorkchat(projectID:)`.
- **Session rows:** a `terminal` / `bubble.left.and.bubble.right` glyph for the mode the session opens in; the context menu's **Open in Terminal** / **Open in Workchat** record the mode and open the session like a panel click.
- **Remembered mode:** `WorkspaceLayout.workchatSessions` (decoded with `decodeIfPresent`, so a layout saved before Workchat reads as all Terminal), stored with the workbench's layout in UserDefaults, never in SQLite. Every placement of a session (`placing`: panel click, ⌘1…⌘9, the ▾ menu, Work on It, the palette) puts `pane(forSession:)` on screen. A fresh start (a new session, Start fresh) records Terminal, because a fresh agent may stop at a trust or login prompt the Workchat cannot show. A deleted session leaves the set (`forgetSession`, and `loadSessions` prunes `referencedSessionIDs`).

The pane opens scrolled to the newest message, reads the feed once when shown or when the session's state changes and every 3 s while the agent works or has background subagents (`SessionFeedStore.follow`; `SessionFeedPoller` serializes polls: a refresh asked during a run folds into exactly one more run). Any of these reads — the one on open, the one on a state change, each 3 s tick — is skipped while the main window is hidden, minimised or covered (`isTabOnScreen`), so a pane nobody sees spawns no CLI; when the app's windows come back on screen (`AppState.uiVisibility`, #731) after a skipped read, the feed is read at once (`SessionFeedStore.screenChanged`, `ForegroundRefreshGate`, board #589). The store and its CLI lookup are built once per pane, not on each render. It shows `watchtower` entries as the owner's bubble marked "via Watchtower". A subagent card opens the subagent in place (#711): the pane keeps a `SessionChatPath`, the bar shows **‹ Back** (also Esc and ⌘[) and `Workchat › <type> › …` with each part popping to its level, the subagent's feed keeps the **Task**/**Report** headings, and the read-only line "Subagents are read-only. Write to the agent in the main Workchat." stands where the composer would be. While a subagent is open the main feed's own poll stops (its `follow` runs only at the root, and **‹ Back** reads it once); the subagent is read on open and again every 3 s while its marker says `running` and the session is active (`SessionFeedStore.followSubagent`, skipped off screen), each read followed by one incremental main read (`readsMainFeed`) so the marker's status is current — the pane reads it from the store's markers (`SessionFeedSubagent.currentStatus`), not from the copy opened. Every CLI read of the store, main or subagent, waits for the one before it, so the pane runs at most one CLI process. The path resets with the pane.

## Workchat composer (#711)

The composer, the permission card and Stop make the pane a way to drive the session. `WorkchatModel` is held per session by `WorkbenchesViewModel.workchat(sessionID:)`, so the draft and the lines on their way survive pane switches; nothing is stored. The composer shows only while the session is live and not finished; a finished one shows "Session finished. The history stays readable."

- **Lines:** `send()` goes through `SessionLineDelivery.deliverLine` with key `.workchat(id)` behind `SessionControl.lineCheck` — PROJ-16's conditions (needs approval, a busy agent or one turning to a line just submitted, the owner's text in the prompt), with no device grant at the Mac. A line keeps its line breaks (owner ask #421, PROJ-12 amended): `\r\n` becomes `\n`, only the ends are trimmed, and it is pasted as one multi-line bracketed paste.
- **States** (`WorkchatOutgoing.State`): `sending` (the first try), `queued` (held or behind another line; **Cancel** drops it with `dropHeld` — a line whose retry is already under way is out of the queue and stays), `typed` and `copied` (waiting for the owner's Return, with **Show in Terminal**), `sent`, `notSent` (the session ended; the text goes back to an empty field).
- **Echo:** a bubble leaves once the feed shows its owner entry — same text with whitespace collapsed, dated at or after `sentAt`. A `sent` line's echo must be dated from 2 s before `deliveredAt` (`WorkchatModel.echoLead`: `deliveredAt` is set after `submitPrompt` returns) to 90 s after it (`WorkchatOutgoing.echoWindow`), so the same text typed in the terminal while the line sat queued is not its echo; past the window it stays as a plain bubble (`/clear` writes no owner entry). `typed`/`copied` lines wait however long. `claimedEntries` keeps one echo for one line.
- **Stop:** the round button while the agent or its subagents work (and Esc in the empty field) calls `SessionControl.interrupt` — one Esc, refused while a permission request is pending (Claude Code draws the prompt before its hook reports it). A refusal sets `stopError` above the field: "A permission prompt is open — answer it on the card or in the terminal", "The session is not running", or the failed check.
- **Permission card:** read with `SessionControl.pendingPermission` on each hook write for the session (`WorkchatModel.PermissionReadKey`: the state kind and the hook stamp), no timer. **Allow** / **Deny** go through `SessionControl.answerPermission`, PROJ-21's guarded compare-and-set, with `decided_by = "Mac"`; the hook then prints "Denied by the owner at the Mac." for a deny. The Deny-only blocks (`PermissionAllowBlock`: shortened summary, settings path) apply: the card shows its note, **Deny** and **Show in Terminal**. A read older than an answer or a newer read is dropped (`permissionReads`). A failed read shows its error on the card, or above the composer when no card is on screen. Codex writes no rows, so it has no card.
- **Show in Terminal** (`WorkbenchesViewModel.showTerminalFromWorkchat`): the Workchat's slot swaps to the session's terminal in place and Terminal is recorded; a terminal already on screen stays.
- **Ask cards:** each open ask of the session (`vm.asks.openAsks`) shows at the end of the feed with **Open Ask**, which opens the ask drawer.
- **Asks in the current mode** (polish 2026-10-21): opening an ask shows its session in the session's remembered mode (regression tests added). After an ask answer is delivered: submitted, held or queued keeps the remembered mode; typed or copied (the owner must press Return or paste) goes to the terminal with the keyboard there.

### Polish (2026-10-21, #846)

- **`queued_command` owner lines:** Claude Code records a line it took mid-turn as an `attachment` of type `queued_command` (`commandMode` `prompt`, `origin` absent or `human`, not `isMeta`). The reader makes it an `owner` entry, or an `ask_answer` entry for "Ask #N answered…". Other origins (task-notification, peer, coordinator) are ignored.
- **`activity`** (FEED-03 additive key): `{tool, summary, started_at, more}` or null. Read from the last 256 KiB of the last conversation's transcript (or the subagent file with `--subagent`) on every call, independent of the cursor: the newest open `tool_use` (no `tool_result` yet). Several Reads show as "N files"; the summary comes from a per-tool table, at most 120 runes, first line. Codex: `custom_tool_call` (summary = the first `cmd:"…"` in the input, else the name) and `function_call` (`command`/`cmd`), paired with their outputs by `call_id`. A missing file gives null silently; any other read error gives a stderr note and null.
- **Live line** (Desktop): a one-line caption row of fixed height (a blank line when empty) between the feed and the composer while the composer shows: tool symbol, summary, " · N more" and an `m:ss` timer from `started_at`. "Thinking…" when the session works with no open tool or after newer agent text; "Agents working · N" in the background state. The row is kept but hidden when the session is not working or while the permission card shows, and cleared when it stops working. A subagent pane keeps the same row and shows its own line only while that subagent runs (its status read from the current marker). The glyph pulses and the line animates with `Motion.toggle`, both off under Reduce Motion. Never an entry, never stored, never sent to the phone (FEED-05 test).
- **Sending while busy:** Claude sessions go through `SessionControl.workchatLineCheck`: `lineCheck`, except that a working agent (Working, Agents working) does not hold the line; it keeps the hold for a session not live or with no hook state this run, needs-approval, the owner's text in the prompt, settling after the previous line and session gone. The kind is read at each send and try (a pane restored at launch is made before the sessions load); only `claude` drops the busy hold. A line sent while the agent works shows "Queued · the agent reads it at its next step" until its echo, and that echo has no 90 s cap. A held line reads "Queued · sends in a moment ·" (Claude) or "Queued · sends when the agent stops ·" (Codex, a shell or a kind not known yet) with **Cancel**. The phone's hub uses the same `workchatLineCheck` for its Claude sessions since 2026-10-25 (PROJ-16 amended, ask #614; its echo carries `while_busy`); `lineCheck` stays the strict check for other kinds.
- **Paste and attachments:** ⌘V of an image (PNG/JPEG/GIF/WebP, TIFF converted to PNG, the main chat's size limit) or a PDF saves it to `<workspace>/workchat-attachments/<session id>/<yyyyMMdd-HHmmss>-<n>.<ext>` (UTC stamp; the workspace is the folder of `watchtower.db`). Finder files and drops attach their own paths, with no copy. Chips above the field carry ✕. On send: the text, then each path on its own line, in double quotes when it has a space, `"` or `\` (those two escaped with `\`); a path with a line break is refused at attach. A paste that cannot be saved, or a refused path, shows `WorkchatModel.attachmentError` under the field (the composer's `attachmentError`) until the next attach or send — the paste inserts nothing instead. Attachments alone can be sent. Echo matching ignores `[Image #N]`/`[image]` markers and the paths. Files older than 7 days are swept at launch, once the session host's reattach is done (`WorkbenchesViewModel.sweepAttachmentsAfterReattach`), except the folders of the sessions live then — the runs that survived the restart included.

## v1 limits

- Polish (2026-10-21): Codex keeps the busy hold (queue-on-Return during a Codex turn is not verified). Codex `activity` shapes come from real transcripts but are tested with synthetic fixtures only. A line sent while busy that the agent never reads stays a plain sent bubble. The launch sweep protects only sessions running once the reattach is done: a session not running loses its pasted files older than 7 days, even if it is resumed later. The phone gets no `activity`.
- Codex sessions (2026-10-17): `sessionfeed.ParseCodex`/`LocateCodex` read the rollout (`$CODEX_HOME/sessions/*/*/*/rollout-*-<id>.jsonl`, the stored `transcript_path` first) in both owner dialects (paginated `item_completed` `UserMessage`/`AgentMessage`, legacy `user_message`/`agent_message`); user text is classified like Claude's (brief, ask answer, Watchtower line). Legacy lines carry no id, so their entry id is `L<line byte offset>`. No subagent markers for Codex; a zstd-compressed rollout yields no entries (`unknown_records["<zstd>"]`).
- No search, export or sharing. The iPhone shows the tail of a feed only (phase 3 below), no paging into older entries.
- Zero time means no time: the separator, a report entry and a meta-only subagent marker may carry `0001-01-01T00:00:00Z`; the Desktop treats it as unknown and shows no timestamp.
- `--after` and `--subagent` are mutually exclusive (the command refuses both). `skipped` and `unknown_records` count only what that call read.
- A marker whose `meta.json` is not written yet is missing from `subagents` until it appears (it is still in `entries` when its call is after the cursor); a meta-only marker has no time or parent report until its transcript part is parsed.
- A background subagent without a `SubagentHandback` has no report.
- `unknown_records` is noisy on live data (several expected Claude Code record types are not yet on the ignore list); it is a drift signal, not an error.
- An owner message with a pasted image can read `[Image #1] …` followed by `[image]`.
- The in-flight CLI read is not cancelled when the pane goes away; the result is discarded.
- The format of the transcripts is undocumented: a drift degrades to skipped/unknown counts, never a failure.

## Phase 3 — the chat on the iPhone (2026-10-18, board #486)

Spec: `docs/superpowers/specs/2026-10-18-session-chat-iphone-design.md`. Contract: FEED-05; the mobile POC's I-4 is amended for this one exception (the chat crosses to the owner's iCloud, on request only). Transport: [mobile-companion.md](mobile-companion.md).

**Flow.** Opening **Chat** on a session's detail screen enqueues the relay action `session_chat_request` `{session_id?, subagent_id?, tool_use_id?}` (entity = the `terminal_session-<id>` record; `SessionChatRequestHandler` needs no grant, since it only reads). The phone repeats it every 60 s while the screen is open (`SessionChatRequester`, stop keyed by screen so a push/pop does not stop the top screen's loop). An unknown session answers `.notFound` with message `unknown_session`. A subagent request carries both ids (`subagent_id` names the record, `tool_use_id` is what the CLI's `--subagent` takes; one without the other is `invalid_params`), and a `session_id` that differs from the entity is `invalid_params`. The handler replies `.applied()` at once and tells `SessionChatRunner` to watch the session or subagent. The watch counts from when the phone asked (`created_at`): a request older than the watch applies without opening a watch, a younger one ends `created_at` + 5 min (at most now + 5 min) (`.sessionChatRequest` is a session request kind for the relay's 24 h expiry). The phone does not queue a repeat while an earlier `session_chat_request` for the same chat still waits in its outbox.

**Lifetime.** A watch lasts 5 minutes from the last request. The runner runs `watchtower workbench session-feed --session N --json` (or `--subagent <tool_use_id>`) off the main actor, every 3 s while the agent is live and once per watch for a finished session, bounded at 30 s. The result is clipped to the caps and kept **in memory only**: never in the clear on disk (not in `watchtower.db`, FEED-01; not in the hub sidecar) — only the sealed slice record waits in the hub's transport queue. When the watch expires the entries leave the slice window and the publisher deletes the record from the zone. Stopping the runner, and any time no phone is linked, drops every payload for good. `SessionChatSlice` (kind `session_chat`, record `session_chat-<session id>` or `session_chat-<session id>-<agent id>`) is an urgent kind, published after the ask kinds (asks stay first): the runner's `onChange` (a run stored a payload that differs from the last — payloads carry no clock) nudges the publisher's fast lane (`nudge(kinds: [.sessionChat])`, 1 s coalescing, 2 s spacing) and a saved or deleted record asks for the immediate send. A live chat is about 5 s behind.

**Caps** (`SessionChatPayload`, I-8): FEED-02 kinds only (a tool call, thinking or a kind a newer CLI adds is dropped before the cut and not counted), newest 300 entries (`entries_more` counts the cut ones), entry text 4000 characters (`text_clipped`), titles and subagent descriptions 200, and a payload over 600 000 bytes drops the oldest entries until it fits (counted into `entries_more`; each entry is measured once and the payload is encoded once). The payload carries no clock, so an unchanged feed is byte-identical and is not uploaded again. A subagent marker carries `tool_use_id` besides `agent_id`; the phone shows no link for a marker missing either.

**Phone.** Kit mirror `SessionChat` (`Models/SessionChat.swift`, fixtures `session_chat.json`, `session_chat_subagent.json`). Session detail has a **Chat** row; `SessionChatView` shows owner bubbles right, agent text left, ask answers and Watchtower lines marked "via Watchtower", the brief collapsed, separators, and subagent markers that push the subagent's own chat. Waiting states: "Asking your Mac…", then after 60 s without a record "Your Mac has not sent this chat yet. Is it awake?". **The Tell bar (`TellSessionBar`) shows only on the main chat**, and only for a device allowed to type (PROJ-16): a line typed from a subagent screen would reach the main agent, not the subagent. A sent line shows as a pending bubble while it waits in the outbox, then as a local bubble after the Mac applied it, until an `owner` entry with the same text dated at or after the send arrives or 90 s pass.
